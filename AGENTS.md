# Правила восстановления OpenTorchlight

## Главный принцип

OpenTorchlight восстанавливает поведение Torchlight по оригинальным данным и
коду. Совпадение картинки или ощущений при ручной проверке само по себе не
считается доказательством. Перед подбором коэффициентов, преобразований или
состояний сначала нужно исследовать оригинал.

## Приоритет источников

Используй источники в таком порядке:

1. Данные установленной игры: `pak.zip`, `.adm`, layout, material, mesh,
   animation и другие ресурсные форматы.
2. Символы, строки, RTTI и машинный код оригинального Linux ELF. Всегда
   фиксируй SHA-256 исследованного бинарника.
3. Официальный TorchED SDK, `Core.dll` и исходное поведение конкретной версии
   сторонней библиотеки, например OGRE 1.6.5.
4. Изолированное исполнение оригинальной функции и дифференциальное сравнение
   результатов с переносимой реализацией.
5. Ограниченная трассировка запущенной игры, если статического анализа и
   изолированного вызова недостаточно.
6. Ручной визуальный подбор допустим только как временный прототип. Помечай его
   как приближение и не описывай как восстановленное поведение.

Запускать всю игру необязательно. Если ответ можно получить из файлов,
дизассемблирования или небольшого стенда, используй их. Это быстрее,
воспроизводимее и не затрагивает сохранения и настройки пользователя.

## Обязательный процесс

Перед реализацией очередной подсистемы:

1. Найди относящиеся к ней ресурсы, классы, символы и функции оригинала.
2. Запиши доказательства в `research/`: хеш бинарника, имена и адреса функций,
   пути ресурсов, версию библиотеки и границы сделанного вывода.
3. Сначала построй минимальный воспроизводимый дамп или дифференциальный тест,
   затем переноси алгоритм в основной код.
4. Сравнивай числовой результат, матрицы, состояния или последовательности
   событий. Обычный smoke-тест загрузки ресурсов не доказывает совпадение
   поведения.
5. Добавь проверку в `tools/check.sh` и обнови README только после того, как
   граница восстановления стала воспроизводимой.

Для большой тесно связанной функции не создавай огромную имитацию окружения
только ради вызова. Выдели чистые подфункции, сравни их отдельно, а оставшиеся
взаимодействия проверь короткой трассировкой оригинального процесса.

## Статус утверждений

В документации и существенных комментариях называй происхождение результата:

- `original-code` — подтверждено машинным кодом или прямым вызовом оригинала;
- `resource-derived` — однозначно получено из игровых ресурсов;
- `library-derived` — повторяет зафиксированную версию оригинальной библиотеки;
- `inferred` — вывод из нескольких косвенных свидетельств;
- `prototype` — временное приближение для рабочего вертикального среза.

Не оставляй необъяснённые «магические» константы, влияющие на поведение или
вид. Рядом должен быть путь ресурса, функция и адрес оригинала, формула из
исследования либо явная пометка `prototype` с задачей на проверку.

Пример уже найденной ошибки: подобранный азимут камеры 35 градусов и локальное
отражение Z выглядели правдоподобно, но оказались неверны. Их заменили полными
матрицами `RIGHT/UP/FORWARD` из layout и формулами оригинального контроллера,
после чего результат подтвердили дифференциальными тестами.

Оригинальные бинарники и проприетарные ресурсы остаются внешними входными
данными только для чтения. Не копируй их в репозиторий.

Для исследования ELF используй сохранённый headless-проект и экспорты по
[research/decompiler-workflow.md](research/decompiler-workflow.md). Адресные
экспорты из `research/decompiled/` и ограниченный набор центральных классов из
`research/decompiled-core/` можно хранить вместе с проектом: они дают
полнотекстовый поиск и позволяют внешнему анализатору связывать функции. Не
создавай и не коммить полный дамп всех функций программы.

## Перенос от кода (code-first)

Единица работы — оригинальная функция целиком со всеми ветвями, полями,
вызовами и ошибками, а не отдельная механика. Процесс зафиксирован в
[research/code-first.md](research/code-first.md):

- `research/coverage.tsv` — обязательный реестр; `tests/registry_sync_test.py`
  не даёт коду ссылаться на оригинальные входы без reviewed-границы;
- стадии переноса в `research/function-transfer.json`: разобрана /
  перенесена / подключена / сравнена — отдельно, одна отметка запрещена;
- `research/original-callsites.tsv` (места вызовов) вместо множества
  зависимостей; условия ветвей и виртуальные цели — пофункционно;
- `tools/function_package.py --address 0x...` — полный пакет на функцию;
- общий справочник полей объекта для связанных методов; scope по
  `research/ui-contour.json` без прыжков на геймплей.
