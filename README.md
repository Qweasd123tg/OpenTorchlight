# Torchlight: восстановление исходного кода

Сначала восстанавливается поведение ПК-версии первой Torchlight по исходным
функциям, ресурсам и закреплённым библиотекам. После подтверждённой ПК-версии
тот же переносимый код будет собран для OnePlus 7 с Android 16 и получит
сенсорное управление. Требования и исходные находки:
[PORTING.md](PORTING.md).

## Действующий процесс и границы

Главное меню, credits, Settings и Options используют
[исходную CEGUI 0.6.2](research/cegui-source-integration.md) из закреплённого
тега: WindowManager, события, реальные controls, Falagard и шрифты. GLES
получает библиотечные quad-команды; собственного второго UI-дерева для этих
страниц нет. [Settings/Options](research/cegui-settings-options.md) сохраняют
Apply/Cancel, исходные значения настроек и анимационную цепочку Options.
Создание/загрузка персонажа и HUD ещё требуют переноса. Linux-сборка требует
FreeType, PCRE и Expat runtime; CEGUI и fallback Expat headers включены с
лицензиями. Android этим срезом не проверен.

Узкие CPU-проверки: `cegui_error_boundary`, `original_cegui_mainmenu_contract`,
`original_cegui_settings_contract`. `paused_settings_render` также прошёл в
общем цикле приложения с GL, изолированными saves/settings и фактическими
кадрами. Полная graphics recreation оригинала и FMOD groups остаются открыты;
покадровое сравнение с оригинальной игрой и performance не утверждаются.

Основной процесс — [code-first](research/code-first.md), правила —
[AGENTS.md](AGENTS.md), текущий scope — [UI-контур](research/ui-contour.json).
Функция — единица учёта и полного закрытия; связанное семейство или цепочка кода —
единица выполнения. Контракт каждого базового блока устанавливаем по ASM,
ресурсам и закреплённым библиотекам: ветви, поля, порядок, ошибки, зависимости.
Эффекты включаем в рабочую цепочку приложения и проверяем их потребителей.

Четыре legacy-стадии [function-transfer](research/function-transfer.json)
относятся к явно проверенной границе. Полноту функции отражает `completion`
с ревью всего контракта и точным остатком. Структурная проверка контролирует учёт;
ревью по ASM и библиотеке — перевод; callers, поля и реальные consumers —
подключение. Сборка и узкие проверки закрепляют известный контракт.
Оригинальный стенд или трасса отвечают на конкретный нерешённый вопрос.
UI-клики, скриншоты, кадры и сквозные сценарии выполняются отдельной явно
запрошенной задачей. Измерения скорости — отдельная задача производительности.

[Реестр возможностей](research/capabilities.json) — вторичная инвентаризация
совместимости и smoke-проверок. Числа feature-checklist, включая 30/38,
не являются готовностью code-first. Исторические gameplay-результаты сохраняются
для повторного использования и регрессий, но не расширяют UI scope. Среди них:
[подключение skill projectile](research/skill-production-dispatch.md):
COUNT/anchor/homing и полный lifecycle остаются открытыми. Кампания и выпуск
не завершены.

[Скриптовая автоматизация](research/scripted-automation.md) работает без моделей,
ключей и сетевых API: CTest/Ninja выбирают проверки, binutils экспортирует прямые
места вызова, Python собирает пакеты и отчёт проверок возможностей с контролем
актуальности. Этот отчёт не аттестует полноту исходных функций.

[Инструменты code-first](research/codefirst-tooling.md) собирают UI-frontier
и пакет семейства одним чтением индексов; exact normalized shapes помогают
выбрать представителей, но не доказывают эквивалентность поведения.

Ниже описан предшествующий перенос через собственный runtime; путь Main/credits
заменён библиотечным выше. Общие механизмы пока используются другими страницами.
Текущий пакет — [входное меню и painter](research/mainmenu-controller-painter.md).
В рабочий frontend подключены начальные свойства `CMainMenu::createMenus`,
видимость Continue и обе панели credits. Отрисовщик обходит окна в общем
порядке и исполняет Falagard каждого окна. Кеш кадра обновляется при изменении
состояния или размера. Загрузчик сохраняет текст тела XML Property при пустом
или отсутствующем Value, включая CreditsB, по контракту shipped CEGUI.
Подключены [диспетчер CMainMenu и подписки CDropdownMenu](research/dropdown-mainmenu.md):
исходные enum-команды, порядок вызовов, флаги статического открытия/закрытия,
MouseButtonDown. При пустом списке Load Character ведёт к созданию персонажа.
Выбор цели [по полному дереву окон](research/mainmenu-pointer-routing.md)
учитывает начальный Z-order, MousePassThroughEnabled и подписку предка.
Неподписанное перекрывающее окно блокирует нижних siblings; credits используют
собственный фон из layout. [Общий оконный runtime](research/dropdown-container-lifecycle.md)
владеет root/back/content, capture/modal, activation, widget pressed/hover и
отложенным destroy. Ordered down/up/move от desktop проходят через capture;
Checkbox и Slider Thumb меняют настройки, RadioTab переключает исходную группу; Falagard читает состояние
тех же окон. Detach сохраняет окна и capture. Modal поддерживается manager,
но Options/Settings не получают выдуманную модальность: AlwaysOnTop — Z-order.
CMainMenu flags=1 остаётся без модели. В Options подключены исходные
[OPEN/CLOSE/IDLE, tag position, mesh и звуки 22/66](research/dropdown-animation-lifecycle.md);
закрывающееся дерево остаётся до завершения CLOSE. Settings override открывается
без анимации. Звуковой PCM backend и RNG — явно обозначенные адаптеры.
[Оставшаяся CEGUI-цепочка frontend закрыта по коду](research/cegui-frontend-closure.md):
tooltip/fade, renderer/cache/factory teardown, repeat/double-click и три Settings
Combobox имеют реальные consumers. Доступные разрешения поступают от Wayland;
выбор записывается в настройки. GameClient safe pointers, внешнее CGameUI,
общие CGenericModel/FMOD и произвольные CEGUI классы остаются за этим срезом.
Реестр сохраняет `partial` полных исходных игровых функций.
В desktop подключён [Town-фон с исходной камерой](research/menu-scene.md).
[Список персонажей и настройки](research/menu-production-state.md) получают
runtime visibility, выбранное имя, highlights, prompt удаления и актуальные
audio levels. Renderer сохраняет [цветовые теги Serif](research/ui-inline-text.md)
и RGBA каждого угла. Подготовка игровых каталогов отложена до входа в игру;
команды Falagard кешируются. FPS и время старта отдельно не измерены.
Остаток: preview персонажей/питомца, pet/difficulty, resolution list/FSAA,
темы сохранённого персонажа, эффекты сцены, `.SVB`/моды и полный CEGUI runtime.
Completion остаётся `partial`; контрактные проверки и сборка отделены от запуска UI.

Предыдущий UI-проход: [mapToFunctions](research/ui-function-bindings.md) — общая
привязка 97 команд из layout, подключённая к frontend/HUD. 469 деревьев /
2312 узлов сравнены с исходным телом при явных библиотечных адаптерах;
полный CEGUI runtime и создание инвентаря остаются открытыми.

Для ручной проверки добавлен [интерактивный preview инвентаря](research/inventory-ui-preview.md):
`--inventory-ui-preview 1`. Он использует оригинальные layout/изображения и
MouseButtonDown для вкладок/Close; 81 дерево подписок и 198 случаев выбора
вкладки сравнены с машинным кодом. **Анимированная рамка, персонаж в окне и
мышиные действия с предметами ещё отсутствуют.** XML-положение не объявляется
восстановленной позой. Без флага остаётся прежний инвентарь.

```sh
./build/torchlight_desktop /path/to/Torchlight/game --inventory-ui-preview 1 \
  --save-dir ./build/inventory-preview-saves --settings-dir ./build/inventory-preview-settings
```

Создай персонажа, войди в город и нажми I. Проверь вкладки, изменение размера,
Close и переоткрытие (снова должна быть выбрана первая вкладка). Сохранения
этого запуска изолированы указанными каталогами.

```sh
python3 tools/work_frontier.py --scope ui --out /tmp/frontier.md --json /tmp/frontier.json
python3 tools/check.py --core --test ui_layout_property
python3 tools/check.py --assets /path/to/game --test original_ui_layout_property
python3 tools/check.py --core --assets /path/to/game --test ui_dropdown_contract --test original_ui_dropdown_contract
```

`--test NAME` повторяется для нескольких проверок. `--plan` показывает выбор.
`--core` отключает графический адаптер; каталог игры позиционным аргументом
выбирает core/assets/reference. Сценарные группы доступны отдельно через
`--render`, `--desktop`, `--all`. Частичная проверка описывает выбранную границу.

## Исторический проход: large-13 — Infuse, зелья Тарна и квестовые контроллеры

Донор — **large-12**, настоящие pak/ELF/библиотеки уже предоставлены. Их не нужно
присылать повторно. Это исходный проект с новым исполняемым подмножеством,
**не полная игра и не готовый установщик**.

В общий loop подключены обучение и применение **Infuse** (10 инвестируемых
рангов): исходная стоимость, ограничения уровня, оригинальная анимация, эффект
на HIT, конечное усиление физического урона, пауза и истечение. Каталог читает
407 определений навыков, но их наличие **не означает исполнение остальных**.
Неподдержанные навыки не заменяются фиктивным ударом и не расходуют ресурсы.
Тема эффекта хранится, но её частицы/звук ещё не отрисовываются полностью.

У настоящего Тарна можно купить поддержанные бесконечные HP/mana-зелья за
золото, с исходными ценовыми графами и ограничениями уровня. Перенос в сумку
предшествует списанию; найденные и купленные одинаковые бутылки объединяются.
Нет продажи, выкупа, конечного ассортимента, идентификации, зачарования и банка.
Новая native-проверка цен сравнивает **20 600** результатов с оригинальными
инструкциями; это не сравнительная проверка всего магазина.

Квестовый каталог читает 111 определений; для 35 допустима ограниченная ветвь
флагов/контроллеров без неперенесённых побочных действий. Сохраняются состояния,
порядок событий и однократное завершение. Это **не 35 готовых квестов**: разговоры,
награды, цели, заселение и питомец блокируют неподдержанное определение целиком.
Нет полного сценария предложений NPC или связного маршрута до финала.

**OTC v5** хранит ранги, затраченные очки, задержки, активные усиления и квестовые
состояния; читает v1–v4. Подлинный v4 создан неизменённой large-12 и проверяется
новым процессом. Сохраняйте отдельные копии старых `.otc`: прежние сборки v5
не читают. Это собственный формат, не перенос оригинальных `.SVB`.

Новые PORT-панели: **K** — навыки, стрелки и Enter — выбор/обучение, **F** —
выбранное поддержанное умение, **J** — журнал; клик по Тарну — подход и магазин,
стрелки/Enter — выбор/покупка. Эти привязки и панели — переносимый интерфейс,
не восстановленные оригинальные хоткеи/CEGUI-окна.

Проверки: **110/110** уникальных тестов; core **58/58**, assets **36/36**,
reference **13/13**, render **5/5** (два пересечения меток). ASan/UBSan **20/20**.
Точные результаты текущего прогона: [verification](verification/large-13/verification.json).
Сквозной тест прошёл 47 проверок в трёх процессах: купить → обучить → применить
на HIT → сохранить → загрузить → дождаться истечения. В нём **явно подготовлены
уровень 10 и золото**, а не пройдена кампания. Ранги, NPC, вещи и эффекты не
внедряются: соответствующие действия выполняет общий игровой цикл.

Главный остаток: другие умения/эффекты, настоящие снаряды, магический бой,
полные NPC/питомец/квесты/боссы и кампания; точное размещение, UI/FX/звук,
оконная и выпускная сборки. Desktop не проверялся в этом проходе.

## Исторический проход large-11 — HP/mana, пассивные эффекты и сохранения

Следующий раздел описывает только прежний проход. Упоминание отсутствовавших
тогда pak/ELF не относится к текущему large-13.


Донор — **OpenTorchlight-gpt-pro-fresh.zip** с интеграторскими исправлениями.
Это продолжение fresh, не повторное применение старого large-10. Полный
присланный дизассемблер использован для статического исследования; в проект
добавлены только небольшие адресные выдержки. Оригинальные pak и ELF в этом
проходе отсутствовали и не включаются в репозиторий.

В общем `application.cpp` подключено восстановление HP/mana по
`media/globals.dat.adm` и поддержанным постоянным эффектам класса/экипировки.
Добавлена потерянная формула максимального HP: отдельное округление процентного
и фиксированного бонусов. Смена экипировки не лечит бесплатно, повышение уровня
сохраняет бонусы, смерть и остановка симуляции не запускают регенерацию.
Неприсутствующие значения GLOBALS не заменяются выдуманными скоростями.

Checkpoint **v3** хранит базовый HP отдельно от максимума с бонусами, читает

## Предыдущий этап: интеграция large-8 и восстановление XP producer

Патч large-7 → large-8 применён интегратором: дерево побайтово совпало с
выданным ZIP, все записи `CHECKSUMS.sha256` валидны. На машине интегратора с
настоящим read-only pak (`8650ad75…`) и закреплённым ELF (`91b41ae9…`) прогнаны
все группы: **core 41/41, assets 30/30, reference 11/11, render 5/5**;
`desktop` — NOT RUN без тестового композитора.

Обычный XP producer восстановлен по машинному коду. `CCharacter::setLevel`
@0x83ecdd..0x83ecfd и `CCharacter::makeChampion` @0x85191b..0x85192e вычисляют
`trunc((g / 100) * g)`, где `g` — значение `EXPERIENCE_MONSTER` (champion —
`EXPERIENCE_CHAMPIONMONSTER`) на уровне юнита; поле данных `XP` служит только
ненулевым гейтом. Ghidra-вывод `(fVar23 / 100) * fVar23` верен, а не повреждён:
второй множитель — то же значение графа, не `UNIT.XP`. Порт переведён с
`inferred` на `original_monster_experience`; проверки
`monster_experience_export_comparison` и
`original_monster_experience_comparison` сравнили **20 031** скалярный случай с
неизменёнными инструкциями закреплённого ELF и подтвердили делитель `100.0f`.

**Граница:** это проверка скалярной формулы, а не всего `setLevel`, spawner или
церемонии выдачи награды. `CPlayer::levelUp @0x8f9ad0`, spawner give-XP
гейты/атрибуция, ранг `CLevel+0x1a8` и volatile RNG золота остаются открытыми;
связь gold-rank с portable spawn-level и использование мирового RNG —
по-прежнему `prototype`. Полная исходная прокачка, fame, skills, regen, ranged
и кампания не объявляются готовыми.

дифференциальным тестом или трассировкой он не считается восстановленным кодом.
Обязательный порядок работы и статусы доказательств закреплены в
[AGENTS.md](AGENTS.md).

## Предыдущий интегрированный этап: предметы и состояние игрока

В этом пакете соединены обычная смерть монстра, `TREASURE`/`BARREL_TREASURE`,
существующие классы спавна, runtime-предмет, подбор в инвентарь, выбор экипировки
и сохранение состояния игрока при смене этажа. Экземпляр хранит уже рассчитанные
`WeaponItem`/`ArmorItem`: замена слота не пересоздаёт предмет и не перебрасывает
его характеристики; снятое снаряжение остаётся в сумке.

Минимальное управление в desktop: **I** — инвентарь, **стрелки вверх/вниз** —
выбор, **Enter** — надеть, **U** — снять, **I/Escape** — закрыть панель.
Панель показывает предметы, занятые слоты, сохранённые характеристики и причины
отказа. Пока она открыта, симуляция приостановлена (`prototype`). Активный удар
нужно завершить перед сменой снаряжения. Подбор больше не надевает предмет
автоматически. Стартовое оружие также является экземпляром инвентаря.

`PlayerSession` живёт вне цикла загрузки этажа; здоровье, экипировка и предметы
сохраняются, а ссылки на цель и исполнение удара сбрасываются. Выбор нового
оружия переподключает его модель и существующий загрузчик атакующих клипов;
не найденные модели/клипы не подменяются. Изменение внешнего вида брони,
все аффиксы/требования, деньги, использование расходников и запись сохранений
на диск этим этапом не реализованы. Ранг уровня и полный RNG-контекст добычи
остаются прежними ограничениями.

**Проверено локально:** 12/12 переносимых проверок и полный прогон 48/48 с
закреплённым ELF и оригинальным `pak.zip`. `original_item_cycle` прошёл реальную
цепочку ресурсов; `torchlight_desktop` полностью собран, GLES smoke и рендер исходной
сцены прошли. Оконный executable также загрузил первый этаж Main и отрисовал три кадра.
Ручной сценарий с убийством, подбором и клавишами `I`/`Enter`/`U` ещё не выполнялся.

Подробная граница доказательств: [research/item-cycle.md](research/item-cycle.md).
Результат прохода: [ITEM_CYCLE_RESULT_RU.md](ITEM_CYCLE_RESULT_RU.md).

  формулой OGRE 1.6. Стартовый посох использует `Polearm1/2/3` и следует за
  костью правой руки с исходным масштабом. Длительность обычной атаки и скорость
  её non-loop клипа теперь происходят из одного выбранного attack description;
  урон срабатывает на его исходных ключах `HIT`.
  Доказательства и оставшиеся границы: [анимации](research/animation-runtime.md).

  `diffuse vertexcolour` из material-скриптов. Из OGRE mesh извлекаются
  591 528 упакованных цветов вершин в 360 геометриях. Направленный свет
  использует нормали моделей, а под скелетными персонажами рисуются мягкие
  контактные тени. Поддержаны исходные alpha rejection, additive/modulate
  blending, `depth_write`, `lighting`, clamp и filtering первого прохода;
  level `MATERIAL AMBIENT` применяется к доказанной ветке `Room Piece` как
  per-instance override одновременно для ambient и diffuse;
  подробности и границы многопроходного рендера описаны в
  [исследовании материалов](research/material-runtime.md).
- Вложенные `Layout Link` раскрываются рекурсивно с новыми runtime-ID и
  наследованием мирового преобразования. Поэтому сгенерированный этаж теперь
  получает вложенные декорации, графы и настоящие `Entrance`/`Exit`-узлы;
  контрольный первый этаж шахт раскрывает 85 ссылок и два `Warper`.
- Адресация переходов разрешает город, относительные этажи,
  `LEVEL ABSOLUTE` и `LASTDUNGEON`, а также преобразует глубину в нужную
  страту и локальный этаж внутри неё. При обычном переходе между этажами
  одного данжа игрок появляется у первого подходящего обратного `Warper` с
  учётом исходного имени, этажных полей и мирового преобразования.
  При отсутствии обратного Warper добавлена ограниченная резервная ветка
  `Entrance`/`Exit`/`Player Start`. Порядок, условия и соответствие switch
  типам узлов имеют статус `original-code`: адресные инструкции и таблица
  `.rodata` проверены на закреплённом ELF. Подробности и встроенная проверка:
  [резервная точка входа](research/level-entry-fallback.md).
- ЛКМ по лестнице выбирает исходный `Unit Trigger`. Персонаж доходит
  до него, запускает связанный `Warper`, после чего desktop-runtime в том
  же Wayland-окне пересоздаёт геометрию, навигацию, логику, сущности и бой
  для целевого этажа.

Это начальный участок восстановления. Полные источники света и тени окружения,
сглаживание пути, динамические физические коллизии, звук, углы обзора, полные
анимационные состояния NPC и врагов, сложные состояния вражеского AI, полная
формула боя, Android APK и сенсорный интерфейс пока не реализованы.
Библиотека собрана и проверена на Linux x86-64; сборка ARM64 ещё не проверена.

Полный ELF индексируется один раз в постоянном headless-проекте Ghidra, после
чего нужные функции экспортируются адресно. Команды, хеши и правила проверки
описаны в [процессе декомпиляции](research/decompiler-workflow.md).

## Пакет на функцию для анализа

Внешние проходы с целыми архивами проекта закрыты: работа идёт переносом от
кода, по одной оригинальной функции за раз ([процесс](research/code-first.md)).
Чтобы собрать всё нужное для переноса конкретной функции — строку реестра,
стадии, рёбра графа, места вызовов, попадания в декомпиляции и ссылки порта —
выполни:

```sh
python3 tools/function_package.py --address 0xb4eb70
```

Места вызовов с адресами инструкций (`research/original-callsites.tsv`)
экспортируются из headless-проекта Ghidra через
`tools/ghidra/export_call_sites.sh`; без этого TSV порядок, ветви и повторы
вызовов невосстановимы, и пакет честно предупреждает об этом. Хеши и правила
проверки описаны в [процессе декомпиляции](research/decompiler-workflow.md).

## Сборка и сравнение с оригиналом

Проверка метода восстановления:
[три ограниченных пилота](research/recovery-method-pilots.md) — 2 126
сравнений skill-арифметики с ELF, 15 оригинальных сценариев диспетчеризации
событий и сопоставление двух функций lodepng с закреплённым upstream.
Они входят в группу `reference` (lodepng — при явно указанном внешнем
checkout). Следующий [production-транш](research/skill-production-dispatch.md)
подключил SEEKING к меню/F: START warmup → HIT/TRIGGER → снаряд → расчёт
по запросу → HP. В исходном cb8360 отдельно проверены 6 сценариев порядка
MISSILEHIT/weapon/effects. Это **частичная реализация**, не полный SEEKING:
COUNT=3 пока даёт один launch, прицеливание/якорь/самонаведение, полные gates
и визуальные эффекты остаются открытыми. В меню это помечено PARTIAL PROJECTILE.

Для текущего контракта загрузчика меню:

```sh
./tools/check.sh --core --test ui_layout_property
```

Для общей переносимой регрессии без оригинальных файлов:

```sh
bash tools/check.sh --portable
```

Этот режим использует `build-verification` (или явный `--build-dir`) с
отключёнными render/desktop. Его граница — переносимые контракты ядра.

Для общей проверки core/assets/reference передайте каталог `game` аргументом:

```sh
./tools/check.sh /путь/к/Torchlight/game
```

Нужны CMake, компилятор C++17, Python 3, libpng и GNU binutils (`nm`,
`objdump`). Ninja используется в примере; сторонних Python-пакетов не
требуется.

```sh
cmake -S . -B build-verification -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DTORCHLIGHT_ENABLE_RENDER=OFF -DTORCHLIGHT_ENABLE_DESKTOP=OFF \
  -DTORCHLIGHT_ORIGINAL=/home/qweasd123tg/Games/Torchlight/game/Torchlight.bin.x86_64
cmake --build build-verification --target ui_layout_property_test
ctest --test-dir build-verification -R '^ui_layout_property$' --output-on-failure
```

После сборки запуск восстановленного этапа загрузки данных:

```sh
./build/torchlight_bootstrap /home/qweasd123tg/Games/Torchlight/game
```

Текстурированная геометрия города:

```sh
./build/torchlight_desktop /home/qweasd123tg/Games/Torchlight/game
```

Сгенерированный первый этаж шахт с указанным seed:

```sh
./build/torchlight_desktop /home/qweasd123tg/Games/Torchlight/game \
  --main-stratum 0 --seed 42
```

После смерти R восстанавливает персонажа у якоря текущего этажа с потерей gold/10.
Пауза на экране смерти — prototype UI policy; исходные альтернативные режимы не реализованы.
Escape сначала закрывает открытый инвентарь; вне панели он закрывает окно.
Штатная кнопка закрытия окна работает независимо от панели.

Тест запускает в отдельном процессе только проверенные функции оригинала.
Оригинальная игра, видимое окно и сохранения в тесте не запускаются; GLES
проверяется в невидимом буфере. Для единственного внешнего вызова
`SDL_GetKeyboardState` тест предоставляет управляемый массив состояния клавиш.
Код переходов состояния оригинала исполняется без изменений.

Тест поддерживает строго одну исследованную сборку и Linux x86-64 с размером
страницы 4096 байт. Другой SHA-256 отклоняется. Оригинальный бинарник нужен
локально и не включается в библиотеку. При сборке без `TORCHLIGHT_ORIGINAL`
сравнение не подключается; отсутствие такого теста не подтверждает совместимость.
