# Torchlight: восстановление исходного кода

Сначала восстанавливается совместимая ПК-версия первой Torchlight. После
рабочего вертикального среза тот же переносимый код будет собран для OnePlus 7
с Android 16 и получит сенсорное управление. Требования и исходные находки:
[PORTING.md](PORTING.md).

## Текущий проход: оригинальный UI — шрифты, HUD и кнопки меню

Вместо прототипного 5x7-шрифта и диагностических прямоугольников UI берёт
ресурсы оригинала:

* **Шрифты**: `<Font>` CEGUI 0.6.2 (`media/UI/*.font`) + TTF через FreeType.
  Масштаб повторяет pinned `libCEGUIBase.so.1`: per-axis `AutoScaled` из
  `Font::notifyScreenResolution @0xd18e0`, `Size*64` и `FT_Set_Char_Size` из
  `FreeTypeFont::updateFont @0xe07b0`. Проверка `original_ui_font_resource`:
  **7 шрифтов, 665 ASCII-глифов** на настоящем pak.
* **HUD**: `bottomhud.layout` рисуется целиком — панели, рамки, полосы
  HP/mana/XP (доли из состояния игрока), подписи зоны и хоткеев. Поведение
  полос снято чтением ASM `updateIngameUI @0xab8100`; точная формула якоря —
  `inferred`.
* **Меню**: подписи кнопок и их картинки (`ButtonStandardRed` и состояния)
  читаются из оригинального `GuiLook.looknfeel`.

**Границы:** это `resource-derived`/`library-derived` повторение, не побитовый
кадр: полный Falagard (состояния, 9-slice, тени, клиппинг) не реализован,
растр глифов зависит от версии FreeType, а у оригинала OGRE + CEGUI OpenGL.
`desktop` по-прежнему NOT RUN. Детали: [ui-visuals](research/ui-visuals.md).

## Предыдущий этап: интеграция large-8 и восстановление XP producer

Патч large-7 → large-8 применён интегратором: дерево побайтово совпало с
выданным ZIP, все записи `CHECKSUMS.sha256` валидны. На машине интегратора с
настоящим read-only pak (`8650ad75…`) и закреплённым ELF (`91b41ae9…`) прогнаны
все группы: **core 41/41, assets 30/30, reference 11/11, render 5/5**;
`desktop` — NOT RUN без тестового композитора.

Обычный XP producer восстановлен по машинному коду. `CCharacter::setLevel`
@0x83ecdd..0x83ecfd и `CCharacter::makeChampion` @0x85191b..0x85192e вычисляют
`trunc((g / 100) * g)`, где `g` — значение `EXPERIENCE_MONSTER` (champion —
`EXPERIENCE_CHAMPIONMONSTER`) на уровне юнита; поле данных `XP` служит только
ненулевым гейтом. Ghidra-вывод `(fVar23 / 100) * fVar23` верен, а не повреждён:
второй множитель — то же значение графа, не `UNIT.XP`. Порт переведён с
`inferred` на `original_monster_experience`; проверки
`monster_experience_export_comparison` и
`original_monster_experience_comparison` сравнили **20 031** скалярный случай с
неизменёнными инструкциями закреплённого ELF и подтвердили делитель `100.0f`.

**Граница:** это проверка скалярной формулы, а не всего `setLevel`, spawner или
церемонии выдачи награды. `CPlayer::levelUp @0x8f9ad0`, spawner give-XP
гейты/атрибуция, ранг `CLevel+0x1a8` и volatile RNG золота остаются открытыми;
связь gold-rank с portable spawn-level и использование мирового RNG —
по-прежнему `prototype`. Полная исходная прокачка, fame, skills, regen, ranged
и кампания не объявляются готовыми.

Подробности: [восстановление XP producer](XP_PRODUCER_RECOVERY_RU.md),
[результат large-8](PROGRESSION_REWARDS_RESULT_RU.md),
[доказательства и ограничения](research/progression-and-world-rewards.md),

## Предыдущий этап: развитие персонажа и мировые награды (large-8, авторская среда)

В общий `src/application.cpp` подключена цепочка: смертельный HIT игрока →
XP → несколько уровней при достаточной награде → HP/mana и очки → золото из
дропа в кошелёк → сохранение. В инвентаре **I** клавиши **1–4** распределяют
свободные очки STR/DEX/MAGIC/DEF. Skill points сохраняются, но активных умений
и магического боя этот проход не добавляет. Уровень и XP видны в HUD.

Формат `.otc` теперь v2 с чтением v1. Старые слоты не обнуляются; значения
исторических наград, отсутствовавшие в v1, не выдумываются и не перебрасываются.
Бонусы XP ограничены уже поддержанными constant passive effects.

**Граница (на момент прохода):** численная формула золота сравнена с
сохранёнными машинными инструкциями; XP producer был `inferred` (восстановлен
в проходе выше), связь gold-rank с portable spawn-level и использование мирового
RNG — `prototype`. Полная исходная прокачка, fame, skills, regen, ranged и вся
кампания не объявляются готовыми. В авторской среде не было настоящего pak/ELF;
тогдашние изменения проверялись на авторских данных и экспортированных численных
участках. Исторические прогоны настоящего pak ниже не являются проверкой
того прохода.

Подробности: [результат large-8](PROGRESSION_REWARDS_RESULT_RU.md),
[доказательства и ограничения](research/progression-and-world-rewards.md),
[формат сохранений](research/checkpoint-format.md).

```bash
python3 tools/check.py --core --jobs 4
# DIR содержит внешний read-only pak.zip:
python3 tools/check.py --core --assets DIR --render --jobs 4
# Дополнительно сравнить численный участок с закреплённым ELF:
python3 tools/check.py --reference DIR/Torchlight.bin.x86_64 --jobs 4
```

## Предыдущий принятый этап: автоматическая проверка на настоящем pak (large-6)

Оконный адаптер и автоматические сценарии используют один `run_application`.
Отдельные процессы проходят настоящее меню, три класса с их стартовым оружием,
Town, ходьбу/инвентарь/resize/save/Continue и Town → Main:1 → Town через реальные
Unit Trigger. Кадры рисует настоящий Mesa/EGL, а не графические заглушки.
Сравниваются состояния, camera/bone/world matrices, материалы/текстуры,
последовательность RNG и пиксели. Собственные снимки явно **regression only**,
не доказательство visual parity оригинала. Ручной просмотр не является
условием прохождения этих сценариев.

Добавлены независимые группы core/assets/reference/render/desktop; наличие pak
больше не требует ELF. Запрошенная отсутствующая группа или пропущенный тест
даёт **NOT RUN и ненулевой exit**, а не зелёный полный результат. Каталог
зависимостей различает поддержанный парсер, unresolved dependency, неизвестный
формат/семантику и независимо доказанную integrity ошибку.

Сценарий обнаружил и локализовал потерянный `PARENT_DUNGEON=Town`: обратный
переход с Main:1 теперь использует parent, а не снова загружает Main:1.
Статус переноса **resource-derived/inferred**; исходная loader-привязка
CDungeon+0x80 пока не подтверждена отдельным ASM.

Актуальные выполненные проверки и ограничения:
[AUTOMATED_VERIFICATION_RESULT_RU.md](AUTOMATED_VERIFICATION_RESULT_RU.md).
Архитектура/команды: [automatic-verification](research/automatic-verification.md).
Маршрут: [parent-dungeon-boundary](research/parent-dungeon-boundary.md).

```bash
# DIR содержит настоящий pak.zip; ELF для этой команды не нужен.
bash tools/check.sh --core --assets DIR --render --jobs 2 \
  --report build/verification.json
python3 tools/coverage_map.py --check --verification-report build/verification.json
```

Полный Wayland desktop здесь не собран/запущен. Автоматический compositor/input
harness ещё не реализован: `--desktop` честно возвращает NOT RUN, а общий
сценарный host не выдается за тест ОС-ввода. Закреплённый ELF отсутствует;
новые оригинальные process traces не получены. Программный рендерер не
подтверждает производительность реальной видеокарты. Ресурсы, бинарники игры и
файлы шрифтов в патч/исходный ZIP не включаются.

## Предыдущий этап: frontend и дисковая кампания (large-5)

Обычный запуск теперь открывает меню: New Game с выбором загруженного класса и
именем → Town, Continue/Load со списком слотов, пауза и Save / Save & Menu /
Save & Quit. Прежние `--frames` / `--main-stratum` остаются отдельным preview.
UI читает поддержанные исходные XML layout/bindings/imageset/PNG/DDS из внешнего
pak; кнопки, текст и отсутствующие CEGUI skins явно обозначены **prototype**.
Нормальная сложность — единственная поддержанная; выбор питомца не реализован.

Добавлен **собственный формат OpenTorchlight `.otc`**, не совместимый с `.SVB`
оригинала. Он сохраняет класс/имя/seed, позицию и recovery anchor, HP/mana/gold,
отдельные экземпляры и слоты предметов, поддержанное состояние сущностей,
логики и AI посещённых этажей. Загрузка восстанавливает данные, а не повторяет
спавн и loot. Активные действия/HIT/пути отменяются; независимые AI-таймеры и
RNG сохраняются. Исходные quest/timeline/volatile-floor правила не объявлены
восстановленными.

Запись использует version/CRC/проверки структуры, ограничение размера,
временный файл → fsync → rename → fsync каталога, блокировку и номер ревизии.
Ошибка сохранения из паузы не выводит из игры. Файлы оригинальной игры не
изменяются. Путь: `$XDG_DATA_HOME/opentorchlight/saves`, иначе
`$HOME/.local/share/opentorchlight/saves`; можно задать `--save-dir PATH`.

**Историческая проверка large-5:** GCC 14.2.0, **28/28 portable**, **28/28 ASan/UBSan**.
Трёхпроцессный сценарий проверяет New/Load, выбранный класс, ходьбу с обходом
препятствия, предметы, Town-shaped → Main-shaped → возврат, смерть/recovery и
повторную загрузку. Это авторские ресурсы, не настоящий Town. Отдельно реально
отрисованы и прочитаны пиксели **4 кадров UI в Mesa/EGL**, не в Wayland-окне.
У Python/Mesa sanitizer-host проверка утечек отключена; у нативных тестов включена.
**Полный desktop, настоящий pak/ELF и Android здесь не собраны/не запущены.**
Исторические 59/59 ниже относятся к входному `large-4`, не к этому патчу.

[Отчёт large-5](FRONTEND_CAMPAIGN_RESULT_RU.md),
[доказательства и границы](research/frontend-save-evidence.md),
[формат checkpoint](research/checkpoint-format.md),
[следующая проверка](NEXT_CHECKS.md).
Машинная карта: `research/coverage.tsv`; обновление и frontier:
`python3 tools/coverage_map.py --next 20`.

```bash
bash tools/check.sh --portable
# На машине с установленной исходной игрой и desktop SDK:
bash tools/check.sh "/path/to/Torchlight/game"
./build/torchlight_desktop "/path/to/Torchlight/game" --save-dir "$HOME/ot-test-saves"
```

В меню работают мышь, Up/Down/Tab, Enter, Escape; имя вводится физическими
US A–Z/цифрами, Backspace. Кириллический ввод/IME и оригинальный font renderer
ещё не реализованы. В игре: клик — ходьба/выбор/подход, I — инвентарь,
Escape — пауза, R после смерти — прежнее восстановление. NPC доступны для
выбора/подхода и сообщения о неподдержанном сервисе, **не для торговли/квестов**.
Unit Trigger сохраняет маршрут через логический граф; прямой клик по любому
Warper не обходит этот граф. Ranged и мировой `CItemGold` всё ещё открыты.

## Предыдущая интегрированная база: продолжение после смерти (large-4)

Реализован возврат к входному якорю **того же этажа**: HP/известная mana до
максимума, штраф gold/10, сохранение мира и экземпляров предметов, отмена старых
HIT и путей. В desktop: **R после смерти**, HP/MANA/GOLD и незацикленная death pose.
Точные defaults/EffectsList/вертикальная граница подключены; AI multiplier применяется
только к явно оценённому флагу. Добыча конкретной смерти теперь предшествует её
логическому уведомлению; смена экипировки проверяет все параметры до commit.

**Проверено после локального слияния:** полный desktop собран GCC 16, 59/59
тестов прошли с SHA-проверенным ELF и настоящим `pak.zip`. Новые gold/mana/death
расчёты дали 6497 совпадений с исходными числовыми spans; сохранены 12 392
совпадения скорости и 42 739 AI cooldown. GLES и оба рендера прошли, оконный
executable загрузил Main:1 и отрисовал три кадра.
Ручной сценарий смерть → R → продолжение боя ещё не выполнен. Ranged/projectile,
XP/skills и мировой CItemGold остаются открытыми; disk saves на этом историческом этапе ещё не было.
AI flags lifecycle не подменяется глобальным ускорением монстров.

Главный актуальный отчёт: [GAMEPLAY_CONTINUATION_RESULT_RU.md](GAMEPLAY_CONTINUATION_RESULT_RU.md).
Доказательства: [research/gameplay-continuation.md](research/gameplay-continuation.md).

## Предыдущий интегрированный этап: единое обычное боевое действие

Игрок и монстры используют `OrdinaryAttackAction`: описание оружия/innate →
выбранный клип → скорость и поза → каждый допустимый HIT → физический урон.
Вражеский временный `100 / ATTACKSPEED` удалён; signed AI cooldown остаётся
отдельным параллельным ограничителем. Поддержаны фиксированные passive-эффекты
скорости/сопротивления и ограниченная физическая арифметика. Нет выдуманного
HIT для отсутствующей анимации или подмены ranged мгновенным melee.

**Проверено после локального слияния:** полный desktop собран, 52/52 теста
прошли с SHA-проверенным ELF и настоящим `pak.zip`. Новый тест скорости дал
12 392 побитовых совпадения с инструкциями и константами ELF; `original_combat`
и `original_enemy_ai` прошли на игровых ресурсах. GLES smoke и оба рендера
прошли, оконный executable загрузил Main:1 и отрисовал три кадра.

Семь исходных констант и путь `media/EffectsList.dat` извлечены read-only в
`research/original-combat-inputs.json`. В этом проходе подключены точные входы и ограниченный entry-respawn; projectile,
полный effect lifecycle и ручной сквозной бой на новой версии ещё открыты.
См. [COMBAT_ACTION_RESULT_RU.md](COMBAT_ACTION_RESULT_RU.md) и
[research/ordinary-attack-action.md](research/ordinary-attack-action.md).

## Метод восстановления

Поведение восстанавливается из ресурсов, символов и машинного кода оригинала,
официального TorchED SDK и точных версий использованных библиотек. Визуальный
подбор разрешён только как явно помеченный временный прототип: до подтверждения
дифференциальным тестом или трассировкой он не считается восстановленным кодом.
Обязательный порядок работы и статусы доказательств закреплены в
[AGENTS.md](AGENTS.md).

## Предыдущий интегрированный этап: предметы и состояние игрока

В этом пакете соединены обычная смерть монстра, `TREASURE`/`BARREL_TREASURE`,
существующие классы спавна, runtime-предмет, подбор в инвентарь, выбор экипировки
и сохранение состояния игрока при смене этажа. Экземпляр хранит уже рассчитанные
`WeaponItem`/`ArmorItem`: замена слота не пересоздаёт предмет и не перебрасывает
его характеристики; снятое снаряжение остаётся в сумке.

Минимальное управление в desktop: **I** — инвентарь, **стрелки вверх/вниз** —
выбор, **Enter** — надеть, **U** — снять, **I/Escape** — закрыть панель.
Панель показывает предметы, занятые слоты, сохранённые характеристики и причины
отказа. Пока она открыта, симуляция приостановлена (`prototype`). Активный удар
нужно завершить перед сменой снаряжения. Подбор больше не надевает предмет
автоматически. Стартовое оружие также является экземпляром инвентаря.

`PlayerSession` живёт вне цикла загрузки этажа; здоровье, экипировка и предметы
сохраняются, а ссылки на цель и исполнение удара сбрасываются. Выбор нового
оружия переподключает его модель и существующий загрузчик атакующих клипов;
не найденные модели/клипы не подменяются. Изменение внешнего вида брони,
все аффиксы/требования, деньги, использование расходников и запись сохранений
на диск этим этапом не реализованы. Ранг уровня и полный RNG-контекст добычи
остаются прежними ограничениями.

**Проверено локально:** 12/12 переносимых проверок и полный прогон 48/48 с
закреплённым ELF и оригинальным `pak.zip`. `original_item_cycle` прошёл реальную
цепочку ресурсов; `torchlight_desktop` полностью собран, GLES smoke и рендер исходной
сцены прошли. Оконный executable также загрузил первый этаж Main и отрисовал три кадра.
Ручной сценарий с убийством, подбором и клавишами `I`/`Enter`/`U` ещё не выполнялся.

Подробная граница доказательств: [research/item-cycle.md](research/item-cycle.md).
Результат прохода: [ITEM_CYCLE_RESULT_RU.md](ITEM_CYCLE_RESULT_RU.md).

  24 876 записей и оба используемых метода сжатия.

  мировыми смещениями; проверены все 12 случайных ruleset кампании.

  классами спавна, разрешаются в конкретные мастер-ресурсы с учётом отношения

  позицией и связью с логическим графом. Конкретные `UNIT` получают оригинальный
  меш и появляются в GLES-сцене; одинаковые существа используют общий ресурс.
  Смерть последнего монстра продолжает исходную цепочку `All Monsters Dead`.
- У созданных монстров здоровье и урон масштабируются исходными графиками
  текущего уровня; также сохраняются их скорости, темп атаки, радиус зрения и
  дистанция удара. ЛКМ рядом с живым монстром выбирает его целью, прокладывает
  путь на дистанцию атаки и запускает удары стартовым оружием выбранного класса.
  Урон игрока проходит исходную цепочку
  `MINDAMAGE/MAXDAMAGE`, `RARITY_DMG_MOD`, `SPEED_DMG_MOD` и
  `BASE_WEAPON_DAMAGE`; дальность складывается из оружейного `RANGE`,
  `REACH_BONUS` и контактной поправки оригинала. После смерти модель скрывается,
  а логика уровня получает исходные события спавнера.
- Размещённые прямо в layout персонажи тоже входят в `RuntimeEntityWorld` и
  связаны со своими уже загруженными моделями. Исходные `UNITTYPE`, `ENABLED`,
  `TARGETABLE` и `INVINCIBLE` отделяют боевых монстров от NPC, торговцев,
  отключённых сцен и тел; поэтому городские персонажи не становятся целями
  только из-за редакторского дескриптора `Monster`.
- Боевые монстры замечают игрока в своём `SIGHT_RADIUS`, преследуют его до
  `FOLLOW_RADIUS` по общей A*-сетке и перемещаются с исходной
  `RUNNINGSPEED`. В ближнем бою каждый враг имеет отдельный AI cooldown из
  `AI_ATTACKCOOLDOWN` своего UNIT и выбранного оружия. Он идёт параллельно
  исполнению выбранного клипа, а не после него. Временный `100 / ATTACKSPEED`
  удалён на combat-action этапе; урон врага исполняется по каждому HIT этого клипа.
  Загрузка, signed timer и порядок взведения проверены 42 739
  побитовыми сравнениями с SHA-проверенным оригинальным ELF:
  [AI cooldown](research/monster-ai-cooldown.md). У Алхимика первого
  уровня 200 HP из графа `HEALTH_PLAYER_ALCHEMIST`; после смерти ввод движения
  блокируется, а R восстанавливает текущую сессию у входного якоря без генерации этажа.
- Исходные OGRE-скелеты уже исполняются на CPU. Строгий парсер обработал все
  182 исходных `.animation`: 1 514 привязок клипов, 2 650 событий и 252
  смещения костей. Алхимик, размещённые персонажи и появляющиеся монстры теперь
  получают `Idle`, `Run`, атаку, `Hit` и смерть из манифеста своей модели,
  без поиска похожих `.SKELETON` по каталогу. В городе этот общий путь оживляет
  26 уникальных скелетных моделей без отдельных правил для каждого NPC или
  вида существа. Боевые существа независимо переключаются между клипами,
  поворачиваются по ходу преследования и смотрят на игрока при ударе. Получение
  урона включает манифестный `Hit`, а убитая модель проигрывает манифестный
  `Die` или `Death` перед исчезновением. Исправлена и OGRE-интерполяция до
  первого ключа, а bind-поза отдельного клипа теперь пересчитывается точной
  формулой OGRE 1.6. Стартовый посох использует `Polearm1/2/3` и следует за
  костью правой руки с исходным масштабом. Длительность обычной атаки и скорость
  её non-loop клипа теперь происходят из одного выбранного attack description;
  урон срабатывает на его исходных ключах `HIT`.
  Доказательства и оставшиеся границы: [анимации](research/animation-runtime.md).
- Рендерер читает исходные `ambient`, `diffuse`, `emissive` и
  `diffuse vertexcolour` из material-скриптов. Из OGRE mesh извлекаются
  591 528 упакованных цветов вершин в 360 геометриях. Направленный свет
  использует нормали моделей, а под скелетными персонажами рисуются мягкие
  контактные тени. Поддержаны исходные alpha rejection, additive/modulate
  blending, `depth_write`, `lighting`, clamp и filtering первого прохода;
  level `MATERIAL AMBIENT` применяется к доказанной ветке `Room Piece` как
  per-instance override одновременно для ambient и diffuse;
  подробности и границы многопроходного рендера описаны в
  [исследовании материалов](research/material-runtime.md).
- Вложенные `Layout Link` раскрываются рекурсивно с новыми runtime-ID и
  наследованием мирового преобразования. Поэтому сгенерированный этаж теперь
  получает вложенные декорации, графы и настоящие `Entrance`/`Exit`-узлы;
  контрольный первый этаж шахт раскрывает 85 ссылок и два `Warper`.
- Адресация переходов разрешает город, относительные этажи,
  `LEVEL ABSOLUTE` и `LASTDUNGEON`, а также преобразует глубину в нужную
  страту и локальный этаж внутри неё. При обычном переходе между этажами
  одного данжа игрок появляется у первого подходящего обратного `Warper` с
  учётом исходного имени, этажных полей и мирового преобразования.
  При отсутствии обратного Warper добавлена ограниченная резервная ветка
  `Entrance`/`Exit`/`Player Start`. Порядок, условия и соответствие switch
  типам узлов имеют статус `original-code`: адресные инструкции и таблица
  `.rodata` проверены на закреплённом ELF. Подробности и встроенная проверка:
  [резервная точка входа](research/level-entry-fallback.md).
- ЛКМ по лестнице выбирает исходный `Unit Trigger`. Персонаж доходит
  до него, запускает связанный `Warper`, после чего desktop-runtime в том
  же Wayland-окне пересоздаёт геометрию, навигацию, логику, сущности и бой
  для целевого этажа.

Это начальный участок восстановления. Полные источники света и тени окружения,
сглаживание пути, динамические физические коллизии, звук, углы обзора, полные
анимационные состояния NPC и врагов, сложные состояния вражеского AI, полная
формула боя, Android APK и сенсорный интерфейс пока не реализованы.
Библиотека собрана и проверена на Linux x86-64; сборка ARM64 ещё не проверена.

Полный ELF индексируется один раз в постоянном headless-проекте Ghidra, после
чего нужные функции экспортируются адресно. Команды, хеши и правила проверки
описаны в [процессе декомпиляции](research/decompiler-workflow.md).

с незакоммиченными изменениями и целевыми экспортами Ghidra, выполни:

```sh
./tools/package_gpt_context.sh
```

Скрипт создаёт `OpenTorchlight-gpt-pro.zip` в корне проекта. Он берёт все
отслеживаемые и новые неигнорируемые файлы, поэтому включает актуальную рабочую
версию, индекс символов и псевдокод центральных классов оригинала, но
пропускает `.git`, `build`, оригинальные бинарники и игровые ресурсы.
Рекомендуемое первое задание анализатору находится в
[GPT_PRO_REVIEW.md](GPT_PRO_REVIEW.md).

Текущий пакет содержит псевдокод 2 630 функций из 70 классов, полный индекс
32 805 символов, 42 326 разрешённых рёбер графа вызовов и 50 353 строки ELF с

системами, даже если нужная функция ещё не была выбрана для отдельного
исследования.

## Сборка и сравнение с оригиналом

Для текущей установки весь цикл запускается одной командой:

```sh
./tools/check.sh
```

Для независимых тестов без оригинальных файлов:

```sh
bash tools/check.sh --portable
```

Этот режим использует отдельный каталог `build-portable` и не запускает
сравнение с оригиналом или аудит ресурсов. Он не подтверждает совместимость
с игрой.

Если игра лежит в другом месте, передайте каталог `game` аргументом:

```sh
./tools/check.sh /путь/к/Torchlight/game
```

Нужны CMake, компилятор C++17, Python 3, libpng и GNU binutils (`nm`,
`objdump`). Ninja используется в примере; сторонних Python-пакетов не
требуется.

```sh
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DTORCHLIGHT_ORIGINAL=/home/qweasd123tg/Games/Torchlight/game/Torchlight.bin.x86_64
cmake --build build
ctest --test-dir build --output-on-failure -V
```

После сборки запуск восстановленного этапа загрузки данных:

```sh
./build/torchlight_bootstrap /home/qweasd123tg/Games/Torchlight/game
```

Текстурированная геометрия города:

```sh
./build/torchlight_desktop /home/qweasd123tg/Games/Torchlight/game
```

Сгенерированный первый этаж шахт с указанным seed:

```sh
./build/torchlight_desktop /home/qweasd123tg/Games/Torchlight/game \
  --main-stratum 0 --seed 42
```

После смерти R восстанавливает персонажа у якоря текущего этажа с потерей gold/10.
Пауза на экране смерти — prototype UI policy; исходные альтернативные режимы не реализованы.
Escape сначала закрывает открытый инвентарь; вне панели он закрывает окно.
Штатная кнопка закрытия окна работает независимо от панели.

Тест запускает в отдельном процессе только проверенные функции оригинала.
Оригинальная игра, видимое окно и сохранения в тесте не запускаются; GLES
проверяется в невидимом буфере. Для единственного внешнего вызова
`SDL_GetKeyboardState` тест предоставляет управляемый массив состояния клавиш.
Код переходов состояния оригинала исполняется без изменений.

Тест поддерживает строго одну исследованную сборку и Linux x86-64 с размером
страницы 4096 байт. Другой SHA-256 отклоняется. Оригинальный бинарник нужен
локально и не включается в библиотеку. При сборке без `TORCHLIGHT_ORIGINAL`
сравнение не подключается; отсутствие такого теста не подтверждает совместимость.
