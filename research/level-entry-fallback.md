# Резервная точка обычного перехода внутри данжа

## Основа и границы доказательств

Кодовая основа: `OpenTorchlight-gpt-pro(5).zip`. Старые реализации не переносились.
Закреплённый оригинальный ELF: `Torchlight.bin.x86_64`, SHA-256
`91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.
Хеш независимо пересчитан перед проверкой таблицы; ELF и игровые ресурсы в репозиторий не добавляются.

В свежем пакете есть адресный ASM выбора обратного Warper. Для следующей
стадии использованы только ограниченные диапазоны из ранее приложенного
`OpenTorchlight-gpt-pro(2).zip`, `original-analysis/full-intel-disassembly.asm`.
Они сохранены в `research/disassembly/58d398-level-entry-mode.asm`,
`585770-level-entry-forwarding.asm`, `95f150-level-entry-argument.asm` и
`960050-level-entry-nodes.asm`. Полный дамп в проект не добавлялся.

`original-code`: инструкции ниже подтверждают режим входа, порядок перезаписи
позиции и передачу аргумента. Соответствие трёх ветвей switch
строкам `Player Start`, `Entrance`, `Exit` также имеет статус `original-code`: read-only тест
прочитал ячейки 1/4/5 табицы `.rodata` по адресу `0xfd6ad0` из закреплённого ELF.
Они указывают соответственно на `0x960ad8`, `0x9609c0` и `0x960910`, что совпадает с адресными ветвями.

## Воспроизведение до изменения

Синтетическая сцена содержит Editor Player Start (-100, 0, 0), Entrance
(10, 0, 20) и Exit (30, 0, 40), но не содержит Warper. При Main:2 -> Main:1
с delta=-1 исходный код выбирает (-100, 0, 0). Узкая восстановленная ветка
выбирает Exit (30, 0, 40). Это измерение порта, не запуск игры.

Также исходный desktop вызывает `generated_player_start` или
`layout_player_start` до поиска Warper. Для сцены только с Exit этот
предварительный вызов может бросить исключение раньше, чем начнётся
разрешение точки перехода. Новый выбор выполняется в загрузчике до этого
прототипного fallback.

## Цепочка оригинала

1. `CGameClient::warpLevels @0x5819b0` сохраняет delta/absolute раздельно
   в +0x10a0/+0x10a4 (`game_client.c:6646–6652`).
2. `CGameClient::performWarp @0x58d110`, инструкции 0x58d39f–0x58d3ba:
   в обычной ветке режим равен 1, когда оба поля нулевые или delta > 0;
   иначе режим 0. Проверка обоих полей — 64-битное сравнение, а знака delta —
   32-битное. Режим нельзя получать только из сравнения конечных глубин.
   В частности, delta=0 и ненулевой absolute даёт режим 0.
3. Режим передаётся в r9d через вызов `loadLevel @0x585770` в 0x58d571,
   сохраняется в [rsp+0x44] (0x585791), передаётся в ecx при вызове
   `loadRoomLayout @0x95f150` (0x5860b3–0x5860bf) и сохраняется в
   [rsp+0x4c] (0x95f169).
4. `loadRoomLayout` последовательно проходит Property Node. Ветвь
   0x960910–0x96095c записывает текущую позицию/направление только в режиме 0.
   Ветвь 0x9609c0–0x960a19 записывает их в режиме 1 (также 3, который этим
   патчем не реализуется), либо когда ещё ничего не выбрано.
   Обе ветви выставляют общий флаг [rsp+0x67]. Цикл продолжает обход:
   предпочтительный маркер не означает ранний return.
5. Ветвь 0x960ae3–0x960b25 обновляет запасную позицию и направление.
   Финал 0x960cb1–0x960d1b копирует их только при незаданной основной точке.
   Инициализация даёт позицию (0,0,0), направление +Z.
6. `loadLevel` использует level+0x140 при `addCharacter` (0x5862ff–0x58633a)
   и level+0x164 при `setToward` (0x586350–0x58635e).
7. Затем `performWarp` пытается переопределить позицию найденным обратным
   Warper. При неудаче она остаётся прежней (0x58dffc–0x58dffe).

Для поддержанных режимов это даёт: режим 1 — последний Entrance, режим 0 —
последний Exit, а при отсутствии Exit — первый Entrance. Если ни один из
подходящих узлов не выбран, используется последний Player Start; если нет
и его — исходная нулевая позиция с направлением +Z. Editor Player Start не
заменяет Player Start. Поиск ведётся по TYPE Property Node, не по NAME.

## Переносимый контракт

`find_same_dungeon_level_arrival` сначала сохраняет уже реализованный приоритет
обратного Warper. Иначе выполняет описанный последовательный выбор по всему
составленному/раскрытому LayoutManifest. Возвращает причину выбора,
необязательный ID маркера, мировую позицию и горизонтальный угол.
Ни скорость, ни масштаб маркера не переносятся на персонажа.

Режим определяется исходными полями запроса, а адрес назначения для поиска
Warper нормализуется загрузчиком до выбора. Waypoint, межданжевые переходы,
LASTDUNGEON и специальный delta=-99 исключены из новой ветки: у оригинала
там есть дополнительные изменения полей/режимов. Начальная загрузка без
запроса сохраняет существующий прототипный выбор старта.

Мировые преобразования используют существующий resolver порта. Совпадение
порядка объектов портового раскрытия с обходом всех реальных CEditorScene,
физический dropToGround и runtime-изменения поз не проверены без ресурсов.
Патч не восстанавливает порталы, waypoint, сохранения или весь загрузчик.

## Проверки

`level_entry_test` работает без игры: оба направления, исходные delta/absolute,
несколько одинаковых узлов, отсутствие предпочтительного узла, Editor Player
Start, default origin, сохранение приоритета Warper, неподдержанные пути,
родительские преобразования и порядок узлов. Тест зарегистрирован в CTest.
`tools/check.sh --portable` запускает независимые проверки без изменения
конфигурации обычной проверки оригинала.

Синтетические фикстуры не обозначаются как resource-derived. Таблица проверена
на настоящем ELF; ресурсные тесты, сборка desktop и GLES smoke прошли в составе
штатного `tools/check.sh`. Полная игра и ручной переход в окне не запускались.

## Подтверждение таблицы оригинала

Из закреплённого ELF прочитаны адреса table[1]=0x960ad8,
table[4]=0x9609c0 и table[5]=0x960910. Это закрывает гипотезу о соответствии ветвей
типам Property Node без повторного экспорта всей `loadRoomLayout`.


Для машины с закреплённым оригиналом добавлен read-only тест
`tests/verify_original_entry_dispatch.py --original /path/to/Torchlight.bin.x86_64`.
Он проверяет SHA-256 и читает именно table[1/4/5] через ELF PT_LOAD, не запуская
игру. CTest регистрирует его только при заданном TORCHLIGHT_ORIGINAL.
Тест успешно прошёл на оригинале 2026-09-15 и входит в обычную проверку проекта.
Код разбора ELF также отдельно проверен синтетическим сегментом и намеренно
испорченной записью.


## Результаты этой проверки

До изменения прошли 4/4 независимых CTest. После изменения прошли 5/5,
включая 2 730 синтетических последовательностей и 5 480 утверждений нового
`level_entry_test`. Повторный запуск воспроизведения даёт (30,0,40) вместо
(-100,0,0). Сборка с GCC AddressSanitizer/UndefinedBehaviorSanitizer также
прошла 5/5 без диагностик на выполненных тестах (исполняемые файлы собраны
с -no-pie, leak detection включён).

Компаньон патча содержит `compare_instruction_slices.py`: 100 сочетаний
raw delta/absolute и 2 730 последовательностей совпали с исполнением
ограниченных неизменённых блоков инструкций. Обёртки ABI и внешний обход
синтетические; захват последнего Player Start моделируется. Это не проверка
всего loadRoomLayout, OGRE или игры. Таблица switch проверена отдельным
read-only тестом на закреплённом ELF.

Дополнительная сборка Clang 17 в среде автора патча остановилась на существующем
предупреждении `src/adm_document.cpp:39`, превращённом в ошибку через -Werror. Этот файл
не изменялся ради патча; успешный sanitizer-прогон выполнен GCC 14.2. В текущей
среде desktop собран, а GLES smoke и рендер исходной сцены прошли.
