# Генератор таблиц: неполнота сдвигает индексы

6 октября 2026, сохранённый срез 0abcd3c. Это дополнение к седьмому отчёту про восстановление таблиц. Production-код не изменялся. Исследован существующий tools/decomp/name_tables.py, не новый snapshot_to_cpp.py из прохода7: новый прототип неизвестные ячейки уже отвергает.

## 1. Пропавший элемент становится пропавшей позицией

Настоящий Tables.definition получил синтетический результат recover: FIRST, неизвестно, THIRD, список missing=[1]. Выдал C++ с неуказанным размером массива, где вместо неизвестного элемента стоит только комментарий. Компиляция GCC14.2 GNU C++98 успешна, sizeof показывает2 элемента, sample[1]==THIRD. Требуемая позиция THIRD была2, стала1.

Файлы probe_missing_slot.py, generated.cpp, result.json. Оригинальный ELF не использовался, реальный повреждённый игровой массив не установлен. Предупреждение в комментарии есть, но не мешает скомпилировать неверную индексацию.

Решение: для готового определения требовать полноту; неизвестную ячейку нельзя заменять пустой строкой или нулём. Неполную информацию выдавать отдельно как данные для исследования. Простая явная размерность массива тоже не исправляет сдвиг внутренних индексов.

## 2. Пустое известно, но превращается в неизвестное

Tables.read_text для16 нулевых байтов возвращает None вместо известной пустой строки. Это связано с printable_string, ориентированным на распознавание литералов для objdiff. Если такой результат попадает в definition, позиция исчезает как в первом опыте. Существование именно такой таблицы в оригинале здесь не утверждается.

## 3. Известный тип строки теряется перед декодированием

STRING_CTORS уже различает std::string и std::wstring. Но read_text использует эвристику printable_string, которая сначала пробует UTF-32. Для узкой строки AB с нулевым дополнением, байты4142000000000000, возвращается символ U+4241 (䉁), а не AB. Этот результат получен настоящим Tables.read_text с синтетическим image.read.

Файл string-read.json. Это не доказательство наличия такого расположения конкретной строки в ELF.

Решение: передавать известный тип из STRING_CTORS в декодер. Узкие строки читать как байты до однобайтового NUL с корректным C++-экранированием; широкие в исходной целевой разрядности wchar_t до соответствующего NUL. Не навязывать узкой строке UTF-8 и не определять ширину по содержимому. Отсутствие терминатора в доступном диапазоне отдельно от пустой строки. Ограничение4096 байт нельзя трактовать как доказательство конца строки.

## Минимальные регрессии

- Известный пустой элемент между двумя непустыми: длина и индексы сохранены
- Неизвестный элемент в начале, середине, конце: готовый исходник не выдаётся
- Короткая узкая строка с нулевым выравниванием не декодируется как wide
- Wide содержит не-ASCII; narrow содержит произвольные допустимые байты: сохранение исходных единиц данных
- Длинная строка и отсутствие NUL в ограниченном диапазоне: явная неполнота, не тихое принятие

Для реальных таблиц следующее действие — найти все определения, ранее сгенерированные с WARNING slots not found, и проверить их по исходным размерам/инициализаторам. Автоматического исправления уже принятых данных этот эксперимент не выполняет.
