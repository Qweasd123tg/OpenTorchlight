# Проверка седьмого прохода Pro

6 октября 2026. Проверен предоставленный OpenTorchlight_pass7.zip и сохранённый срез исходников 0abcd3c. Актуальная ветка ПК и оригинальный ELF здесь не проверялись.

## Независимая проверка

- Для всех 81 именованных callback-кандидатов JSON проверены полные имена с параметром CEGUI::EventArgs const& и адреса против research/original-symbols.txt. Проверены специализации vtable MemberFunctionSlot<Owner> и address point +16, receiver=this, нулевая поправка. Всего в JSON 89 записей; оставшиеся восемь виртуальных случаев не объявлялись разрешёнными именованными callback.
- В исходниках CEGUI 0.6.2 подтверждены пустой деструктор SubscriberSlot, отдельный cleanup(), копирование подписчика в BoundSlot, cleanup при disconnect/Event destruction. Удаление временного SubscriberSlot само по себе не завершает подписку.
- В inventory_menu.c:8892–8913 действительно присутствуют четыре записи адаптера, вызов через указатель, освобождение временной Connection и деструктор SubscriberSlot. Это даёт полезную целую последовательность для следующего пилота, но неизвестный виртуальный вызов нельзя автоматически подписать именем subscribeEvent без проверки таблицы/ABI.
- В effect.c:4178–4200 подтверждены текущие поля как defaults SAVE и USEOWNERLEVEL. Третий EXCLUSIVE следует проверять вместе с окружением тем же способом, а не считать все defaults false.
- По оригинальному списку символов независимо подтверждены 10 глобальных BSS-таблиц и 19140 байт суммарного хранения объектов/чисел (не строковых буферов). Пять по 1160, три по 580 и две по 5800. При предположениях размеров wstring=8 и int32=4 это согласуется с 145 и 145x5 элементами.
- name_tables.py выбирает только локальные глобальные записи, поэтому эти B-символы не входят в его текущий поиск.

Результат статической проверки: static-check.json. Python-прототипы автора не исполнялись, 28 unit-тестов, 162 callback-проверки, 216 default-случаев и синтетический roundtrip взяты из его сохранённых результатов. Исходники прототипов и ограничения прочитаны. Никаких новых игровых функций не принято.

## Что действительно новое

SDK-first уже применялся нами к прототипам вызовов. Здесь более узкий следующий уровень: обратное восстановление конструкции SubscriberSlot из объекта-адаптера и восстановление операций чтения ключа с default. Нельзя складывать89/81/558 в число готовых функций: это места внутри 17/80 функций, пересечения возможны.

Данные gEFFECT_TYPE_* полезны сразу нескольким участкам анализа, но фактических 145 названий в этом пакете нет. Значения null не нужно заменять догадками из ресурсов. Прототип snapshot_to_cpp — генератор уже готового логического снимка, не средство получения снимка оригинала.

## Дополнения к внедрению

1. Пилот адаптера должен проверять весь жизненный цикл: создание, регистрацию, копию Connection, уничтожение временных объектов, disconnect и уничтожение Event. Одинаковый результат одного вызова callback недостаточен для владения и отсутствия двойного удаления. Тип возврата callback не закодирован обычным mangled-именем, поэтому совпавшие параметры символа не являются самостоятельным доказательством return type; библиотечный интерфейс и ASM должны согласоваться.
2. Для resource-рецепта нужен reaching definition именно используемого объекта строки и default. В присланном коде выбирается последний текстовый конструктор, а default ищется в предыдущих 300 символах. Статус CANDIDATE_ONLY корректен; автоматическое применение через ветвления, исключения или повторное использование stack slot пока недопустимо.
3. Для таблиц сначала проверить, можно ли восстановить константы статически из initializer/callee оригинала. Динамический логический снимок — альтернативный источник наблюдений, для него в текущей восстановленной среде отсутствует оригинал. Не требуется запускать игру с UI ради этой проверки.
4. Одного состояния после инициализации недостаточно: порядок, регистрации деструкторов, возможные дальнейшие изменения и влияющие входы входят в проверку. Старый libstdc++ ABI на GCC14 не заменяет оригинальный GCC4.4.7.
5. Реализацию ограничить текущими C++98/TU-инструментами. Не возобновлять замороженный исторический UI-runtime или p-code-runtime. Любая конструкция до проверки остаётся за пределами decomp/src.

## Приоритет

Для ближайшего пилота — три чтения bool-полей CEffect, с сохранением текущего default и проверкой окружающего метода. Следом — один целый цикл подписки CInventoryMenu на настоящем CEGUI, включая владение. Таблицы эффектов требуют оригинала/его инициализации; готового извлечения оригинальных значений в этом отчёте пока нет. Общий коэффициент ускорения не измерен.
