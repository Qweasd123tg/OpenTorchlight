# Готовые внешние инструменты: отбор для OpenTorchlight

Проверено 6 октября 2026. Цель — сократить ручное восстановление крупного C++/ELF x86-64, исходный GCC4.4.7. Ни один из перечисленных инструментов в этом проходе не запускался на игре. Проверены первичные источники и выборочно код; выигрыш в днях не измерен.

## 1. Альтернативный декомпилятор: первый кандидат на небольшой сравнительный опыт

**angr/SAILR.** Готовы восстановление CFG, calling conventions, reaching definitions, переменных, типов, структуры и генерация кода. SAILR уже фигурировал в проходе 5: это не новая находка, а доступная реализация для опыта. Источники: [анализы angr](https://docs.angr.io/en/latest/analyses/decompiler.html), [SAILR API](https://docs.angr.io/en/latest/api/angr.analyses.decompiler.structuring.sailr.html).

**rev.ng.** Открытый декомпилятор на LLVM/QEMU; есть генерация C и модель ABI/типов. Клонирован commit a939c780474334be585127a81f3030d2bac6fec0. Прочитаны модель register/stack arguments и наличие отдельного CliftEmitC. Это возможность получить другой черновик, не восстановление исходной C++ архитектуры одним нажатием. [Репозиторий](https://github.com/revng/revng), [модель](https://docs.rev.ng/references/model/).

Мой предлагаемый опыт: одинаковые 10 ещё не принятых функций с разным составом (обычная логика, контейнеры, математические типы, EH, косвенные вызовы). Одни исходные адреса/типы, ограниченный бюджет, сравнение с Ghidra. Мерить оставшиеся ручные решения и возможность штатной приёмки, а не красоту или число строк. Не мигрировать весь проект до результата.

## 2. DDisasm + GTIRB: готовая основа извлечения нативного эталона

DDisasm получает из ELF пересобираемое представление; GTIRB-pprinter выдаёт ASM. Клонирован commit fe18e25e459c0ccdfbb3aeb28786aa438c441558. В src/datalog/binary/elf/exceptions.dl проверена генерация CFI, LSDA и personality; use_def_analysis.dl учитывает пути из LSDA callsites к landing pads. Поэтому не требуется с нуля писать весь аналогичный слой для капсул.

Это не готовый C++ и не доказательство правильной изоляции любого метода: остаются зависимости, инициализация и проверка оригинальных байтов. Предлагаемый пилот — один метод с EH и один без, без запуска UI. Результат — корректно выделенный проверочный фрагмент, не доля восстановленной игры. [DDisasm](https://github.com/GrammaTech/ddisasm), [код EH](https://github.com/GrammaTech/ddisasm/blob/fe18e25e459c0ccdfbb3aeb28786aa438c441558/src/datalog/binary/elf/exceptions.dl), [GTIRB printer](https://github.com/GrammaTech/gtirb-pprinter).

## 3. BSim / BinDiff: готовый поиск повторного использования

BSim уже является частью Ghidra и ищет структурно похожие функции в коллекциях бинарников. Для нас — проверить библиотечные сборки и родственные методы, которых не нашёл текущий строгий токеновый группировщик. Сходство выдаёт кандидата, не семантическое доказательство и не исходник. Уже исключённые библиотечные функции нельзя повторно записывать в выигрыш. [BSim](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/GhidraClass/BSim/README.md).

BinDiff — готовое сравнение функций/графов и перенос части результатов анализа. Но официально интеграция Ghidra относится к Tier4: потребуются ручные шаги. Поэтому начать с уже доступного BSim дешевле, чем обещать бесшовный BinDiff. [Репозиторий](https://github.com/google/bindiff), [поддержка дизассемблеров](https://github.com/google/bindiff/blob/main/docs/disassemblers.md).

Diaphora также умеет сравнивать TU и переносить структуры, но основной экспорт связан с IDA. При отсутствии готовой IDA-среды дополнительный переезд не выглядит первым шагом для двухдневной цели. [Diaphora](https://github.com/joxeankoret/diaphora).

## 4. QBDI: полезная трассировка, но ограничение для EH

Есть готовые API запуска выбранной функции, наблюдения исполнения и интеграция через preload/Frida. Однако официальный ExecBroker не поддерживает исключения, включая setjmp/longjmp; диапазоны должны охватывать функции, а не произвольный внутренний кусок. Трассировка аллокатора также затрагивает нерекурсивность общей стандартной библиотеки.

Для Torchlight — возможный инструмент изучения ограниченных успешных путей. Не предлагается как универсальный эталон для C++-исключений или как замена проверке cleanup. [API и ограничения](https://qbdi.readthedocs.io/en/stable/api_description.html), [устройство](https://qbdi.readthedocs.io/en/stable/intro.html).

## 5. Rebrew: близкая задача, но не готовая замена нашего процесса

Клонирован commit189f0df2eed554df142a22b7d8e813d658aad3fe. Есть compile/compare, генетический подбор C и ограниченные symbolic proofs, документированы ELF/x86-64 профили. Но в прочитанном src/rebrew/prove.py backend создаётся с arch='x86', состоянием ESP и 32-битными аргументами; сравнение ориентировано на EAX/EDX и заданные адреса. Наличие ELF/x64 сборочного профиля не делает именно этот verifier готовым для SysV AMD64/OGRE aggregate returns.

Готового профиля GCC4.4.7 в просмотренных источниках не найдено. Система потребует настройки и дублирует значительную часть уже существующего compile-compare процесса. Может дать отдельные идеи подбора, но сейчас не рекомендована к полной миграции. [Репозиторий](https://github.com/maci0/rebrew), [проверенный backend](https://github.com/maci0/rebrew/blob/189f0df2eed554df142a22b7d8e813d658aad3fe/src/rebrew/prove.py).

## 6. Что исключено из первого опыта

**reccmp:** README указывает 32-битный x86 со старым MSVC; это другой ABI/формат, не наш ELF x86-64 GCC. [Источник](https://github.com/isledecomp/reccmp).

**dewolf:** исследовательский декомпилятор поверх Binary Ninja MLIL; авторы прямо предупреждают об исследовательской зрелости и возможных ошибках. Не первый выбор без уже готовой Binary Ninja-среды. [Источник](https://github.com/fkie-cad/dewolf).

## Практический вывод

Самый дешёвый новый опыт — сравнение альтернативного декомпилятора на одинаковой небольшой выборке; следующий — BSim с уже собранными библиотечными кандидатами; более инженерно затратный — DDisasm для эталонов. Это рекомендации по порядку проверки, не измеренные результаты.

Неделя→два дня требует примерно 3.5x, если исходная оценка недели верна. Готовые компоненты дают шанс убрать целые категории ручной работы, но наличие инструмента не устанавливает такой коэффициент.

В текущей облачной среде не найдены установленные angr, revng, ddisasm, QBDI, Docker; оригинальный ELF также отсутствует в восстановленном комплекте. Ничего не устанавливалось и не запускалось на игре. Источники скачаны только для чтения, команды из чужих репозиториев не исполнялись. Пользователь не должен пересылать новый архив на каждый пункт: эта карта предназначена для одного ограниченного опыта в существующем рабочем окружении.
