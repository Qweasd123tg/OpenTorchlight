# Исследование полноты наблюдений, 6 октября 2026

## Новое сверх проверки Capture по отдельности

end_to_end.cpp использует настоящий AutoTest.h и настоящий compareCase/runChild с fork. Синтетические тела заменяют оригинал/кандидат; Torchlight ELF не запускается.

1. Допустимая арена равна1МиБ; буфер наблюдения256КиБ. При g_arenaUsed=300001 оригинал пишет1 в байт300000, кандидат2. Оба выполняют report с addHeapInUse и дампом арены по форме существующего генератора. compareCase ошибочно засчитывает same=1,different=0.
2. Разные внешние указатели на два известных исходных объекта также дают same=1,different=0.

Это воспроизведение пропущенного различия на уровне рабочего механизма fork/сравнения, но не доказательство ошибки конкретной уже принятой игровой функции.

## Проверенный вариант защитного наблюдателя

GuardedCapture.h — отдельный C++98-прототип, НЕ замена production AutoTest.h. Его свойства:
- переполнение явно помечает наблюдение недостоверным; вычисление границы не переполняется от length+n
- известные внешние объекты имеют ID, закреплённый входным состоянием, а указатель кодируется ID+offset
- сохраняется различие NULL, начала арены, разных объектов и offsets
- неизвестный внешний указатель даёт INCONCLUSIVE, в том числе когда обе стороны вернули неизвестный указатель
- пересекающиеся входные регионы и повторные ID отклоняются
- поля токена сериализуются раздельно, без случайных padding-байтов

24 assertions прошли на системном GCC14.2 в режиме C++98 с -Wall -Wextra -pedantic -Werror. Pinned GCC4.4.7 сейчас не восстановлен; ABI/runtime-интеграция с игрой не проверялась.

Прототип намеренно не пытается автоматически сопоставлять новые heap-объекты. Порядковые ID, присвоенные отдельно при обходе результата, могут скрыть перестановку объектов. Для новых объектов нужен журнал allocations или типизированный граф с правилами соответствия. Также этот код не распознаёт use-after-free и не заменяет проверку жизненного цикла.

## Важное условие внедрения

Недостаточно добавить error в Capture: статус должен пройти через протокол runChild → compareCase → Stats → генератор → check.py. Нельзя сравнить два одинаковых error-токена и назвать их SAME. Нельзя просто отправить observation-error в существующий bothFailed и забыть о нём, если проверка функции затем примет её по оставшимся лёгким случаям.

Предлагаемый gate: completed>=MIN_COMPLETED, different=0, observation_errors=0 и корректный полный протокол. Старые accepted-test fingerprints инвалидировать, поскольку изменился наблюдатель. Уже существующие пороги MIN_COMPLETED в check.py/mutate.py проверены: они есть; это НЕ новая найденная ошибка с отсутствующим порогом.

Требуются отдельные отрицательные случаи на неизвестную/переполненную запись и на обрыв протокола. Произвольные ранние _exit, неполные заголовки/данные не должны считаться полноценным пустым наблюдением.

## Запуск

Из этой папки:
g++ -std=c++98 -Wall -Wextra -pedantic -Werror -O2 guard_test.cpp -o guard_test
./guard_test

Для end_to_end.cpp добавить -I <корень проекта>/decomp/hybrid. Системный warning mallinfo deprecated можно подавить; это не новая проблема реализации.
