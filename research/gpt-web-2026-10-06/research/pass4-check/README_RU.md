# Сверка четвёртого мнения Pro, 6 октября 2026, 12:00 МСК

Проверена сохранённая ревизия 0abcd3c. Свежие изменения агента на ПК не получены. Игровой ELF и исходный GCC4.4.7 не использованы: исполняемые пробы собраны системным GCC14.2 в C++98. Production-файлы не изменены.

## Подтверждено независимо

verify.py вызывает настоящий ghidra_cpp.convert целиком и компилирует/исполняет результаты:
- direct CBase::step: контроль возвращает11, преобразованный код22 из override
- return x!=false: входы-3,0,2 дают1,0,1 до преобразования и-3,0,2 после
- строка bad UTF-8 continuation byte меняется на bad UTF-8 continuation unsigned char
- дополнительный контрпример: строка keep /* payload */ exact становится keep  exact. Начальное удаление комментариев тоже не различает строковые токены
- определение CProbe::get() const теряет const; это проверено по выводу convert

verify_metadata.py вызывает настоящие функции инструментов на синтетических данных:
- Gen.method_decl с cv=const выдаёт int get();
- virtual_signature считает const и non-const одинаковой идентичностью
- trial_include при наличии read(int) не добавляет известный read(double)
- candidates возвращает только small.cpp, исключая существующий partial.cpp и large.cpp с60001байтом ожидаемого кода

Это не подсчёт повреждённых игровых функций. Исторические348/666,1.4МиБ и123перегруженныхимени из мнения здесь не пересчитаны. Подавление namespace-функции чужим коротким именем отдельно не воспроизводилось.

## Новое расширение прототипа виртуальных слотов

member_slots.cpp не содержит реализаций Left::left, Right::f или Derived::f и не создаёт экземпляров. Тем не менее собирается и показывает представление точных member-pointers:
- Right::f(int): slot0, adjustment0
- тот же member-pointer в представлении Derived: slot0, adjustment8
- Right::f(long) в Derived: slot1, adjustment8
- Derived::f(int): slot1, adjustment0

Следствие для схемы данных: одного номера слота недостаточно. Минимально нужна связка owner/view + точная сигнатура + slot + this-adjustment + группа vtable. Перестановки перегрузок и выбор другого базового подобъекта нельзя свести к одному COver::f.

Это проверка простой невиртуальной множественной наследуемости на x86-64 системного компилятора, не универсальный ABI-валидатор. Деструкторы, virtual bases, covariance и GCC4.4.7 ещё не проверены. Нельзя трактовать любую member-pointer пару как виртуальную: различение virtual/direct и соответствие целевому ABI обязательны.

## Порядок внедрения

1. Добавить регрессионные пробы полного convert, затем защитить литералы/символы/комментарии лексическим разбором. Недостаточно исправить одну замену byte: начальное удаление /*...*/ уже портит значения
2. Убрать типозависимые глобальные упрощения без доказанного контекста. x!=false эквивалентно x по истинности условия, но не по числовому результату
3. Сохранять provenance вызова: прямой подтверждённый target нельзя превращать в виртуальную диспетчеризацию; настоящий virtual нельзя насильно квалифицировать
4. Одно представление signature identity для headers, convert, virtual_signature, overload-detection и кэшей. Учитывать scope, типы параметров, cv, static/member и исходный mangled symbol
5. Отдельный preflight заголовков по member-pointers после проверки ABI. Не ждать написания всех тел, чтобы заметить неверную перегрузку или группу
6. Планировать по свежему непринятому остатку функций. TU остаётся единицей компиляции и владения; большой TU нужно разбивать на задания, не на конфликтующие параллельные записи одного файла. Не просто снять лимит60000 и отправить весь файл модели
7. Сокращать compile failures по конкретной диагностике и закреплённому окружению. Сокращатель из мнения здесь не запускался. Его целевой predicate должен отличать исходную проблему от новой случайной синтаксической ошибки

Опциональная оптимизация objdiff из предыдущего пакета остаётся независимой: она ускоряет старые правила и не лечит перечисленные семантические потери.

## Воспроизведение

verify.py и verify_metadata.py запускать из корня сохранённого проекта. Их out указывает на каталог исследования и требует изменения при переносе. member_slots.cpp собирается обычным g++ -std=c++98; результата для другого ABI ожидать нельзя.

Артефакты: results.json, metadata-results.json, скомпилированные исходники до/после и member_slots.log. Бинарные исполняемые файлы в пакет не входят.
