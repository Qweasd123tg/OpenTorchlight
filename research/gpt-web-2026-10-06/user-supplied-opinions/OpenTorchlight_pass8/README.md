# OpenTorchlight: ненейросетевая автоматизация, проход 8

Основной отчёт: `REPORT_RU.md`. Проект не изменяется. Это отдельные исследовательские инструменты и тестовые кандидаты, не патч игры.

## Повторный запуск

Нужны Linux x86-64, Python 3.10+, современный GCC-совместимый `g++`, GNU binutils и распакованный исходный архив. В выполненном запуске использованы Python 3.13.5, GCC 14.2.0 и binutils 2.44. Доступ к сети, оригинальный ELF, запуск игры и установленные сторонние Python-пакеты не нужны.

```sh
python3 run_all.py /absolute/path/to/OpenTorchlight-main --out /tmp/torchlight-pass8-results
```

Выходная папка должна быть вне исходного проекта. Скрипт собирает тестовые программы во временной папке, запускает пять специально отобранных изолированных нативных функций и записывает JSON. Это не защитная песочница для произвольного враждебного ассемблера. Изменённые листинги необходимо отдельно проверять до исполнения.

Текущие команды ориентированы на современный компилятор. Они не являются готовой конфигурацией GCC 4.4.7. Для математических проб используется `OGRE_MEMORY_ALLOCATOR=1`, потому что тесту нужны только математические заголовки, а полный альтернативный аллокатор отсутствует в выделенном подмножестве библиотеки. Также применён `_GLIBCXX_USE_CXX11_ABI=0`; это не делает современную libstdc++ и компилятор исходной версией.

## Состав

- `tools/census.py`: адресная выборка исторических кандидатов, без вывода о завершённости.
- `tools/native_capsule.py`: пересборка пяти отобранных листингов в тестовые нативные эталоны.
- `tools/memory_transfers.py`: статический анализ происхождения байтов и генерация `memcpy`/`memset` для ограниченного класса функций.
- `tools/math_shapes.py`: строго упорядоченное распознавание суммы трёх квадратов.
- `tools/static_guards.py`: сопоставление guard-переменных и локальных статических объектов по полным именам.
- `examples`: исходники компиляторных, математических, жизненных циклов и дифференциальных проб.
- `tests`: 32 модульных теста прототипов.
- `results`: результаты выполненного запуска, ассемблерные листинги тестовых сборок, автоматически полученный C++ и контроль целостности.

`results/native/generated_capture.cpp` получен программой из архивного ассемблера. Его не следует устанавливать в `decomp/src`: соответствующий метод уже есть в `decomp/src/keymanager.cpp`. Это контроль воспроизводимости автоматического восстановления, а не новая принятая функция.

## Ограничения

Оригинальный ELF не проверялся. Пересобранный архивный текст инструкций не равен независимо подтверждённому оригинальному машинному коду. Нативные тестовые эталоны не используются как часть итоговой игры. Пять выбранных функций не вызывают внешние зависимости; обобщение на функции с релокациями, исключениями, TLS и внешними вызовами не реализовано.

Сравнение C++ с OGRE выполнено на заголовках закреплённой библиотеки и синтетических входах, не на машинных инструкциях оригинальной игры. Тесты жизненного цикла также синтетические. Восстановление динамических типов и массовый импорт ABI-размещения в Ghidra описаны как следующие этапы, но не реализованы.
