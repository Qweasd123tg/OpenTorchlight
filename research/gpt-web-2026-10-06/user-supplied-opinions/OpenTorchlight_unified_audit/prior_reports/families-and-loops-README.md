# OpenTorchlight: проход 6, новые этапы без LLM

Дата анализа: 6 октября 2026 года. Исходный архив: `OpenTorchlight-main(4)(1).zip`.

Главный документ: `REPORT_RU.md`. Краткие численные результаты: `results/summary.json`.

Это набор исследовательских прототипов, не изменение игры и не готовый декомпилятор. Все игровые совпадения имеют статус кандидатов. Проверки Z3 относятся к явно заданным моделям, не к автоматически переведённому оригинальному машинному коду.

## Состав

- `scripts/family_deltas.py`: группировка исторических тел Ghidra с сохранением конкретных различий литералов, типов и вызовов.
- `scripts/member_alignment.py`: кандидаты соответствий прямых обращений `this + offset` между классами; неоднозначные соответствия остаются конфликтами.
- `scripts/loop_obligations.py`: 10 условий для индуктивных отношений и состояния контейнера через системную библиотеку libz3; поиск лексических кандидатов в архиве.
- `scripts/test_stage_prototypes.py`: 15 синтетических тестов, включая все 10 условий Z3 внутри одного параметризованного теста.
- `scripts/verify_corpus.py`: обратное восстановление токенов 2 608 тел из шаблонов и привязок, проверка конкретной пары Merchant/Stash. Это проверка сохранности представления, не поведения.
- `examples/loop_scan.cpp`: отдельный синтетический C++98-тест восстановления цикла с сохранением нестандартного поведения доступа к массиву.
- `results/`: результаты запусков, SMT-LIB2 условия, сводка и контроль целостности исходного архива.

## Воспроизведение

Нужны Python 3.10+, исходный распакованный проект, системная `libz3` для SMT-проверок и C++-компилятор для синтетического теста. Python-пакет `z3-solver` не требуется: используется C API установленной библиотеки. При отсутствии библиотеки `loop_obligations.py` сообщает об ошибке; модульный тест SMT пропускается, а не считается пройденным. Здесь установлена libz3 4.13.3.0, и тест не пропускался.

Из каталога этого отчёта:

```sh
ROOT="/путь/к/OpenTorchlight-main"
python3 scripts/family_deltas.py "$ROOT" results/family-deltas.json
python3 scripts/member_alignment.py "$ROOT" results/member-alignment.json
python3 scripts/loop_obligations.py "$ROOT" results/loops
python3 scripts/verify_corpus.py "$ROOT" results/corpus-verification.json
python3 scripts/test_stage_prototypes.py
```

Синтетический тест, исполняемый файл вне проекта игры:

```sh
BIN="$(mktemp /tmp/opentorchlight-loop-scan.XXXXXX)"
g++ -std=gnu++98 -O2 -fno-strict-aliasing -Wall -Wextra \
    examples/loop_scan.cpp -o "$BIN"
"$BIN" > results/loop-scan-tests.json
rm -f "$BIN"
```

Для повторного запуска SMT-условий отдельно от Python можно передать файлы `results/loops/*.smt2` совместимому решателю SMT-LIB2. В сохранённых файлах запрошен статус проверки; конкретные значения контрпримеров дополнительно записаны в `loop-results.json`.

## Важные границы

Игровой оригинальный ELF, GCC 4.4.7 и графический процесс Torchlight не запускались. Нет новых принятых игровых функций, изменения правил приёмки или измеренного общего ускорения. Ни один кандидат не помещён в `decomp/src`. Исходные 2 285 файлов побайтно совпадают с ZIP; контроль в `results/integrity.json`.

Имеющиеся `manual-shape-clusters` читаются как историческая информация о похожих функциях. Замороженный процесс ручного учёта/старый runtime не изменяются и не возобновляются. Предлагаемый выход новых этапов — обычный C++98 в существующем активном процессе `decomp`, после его штатной приёмки.
