# Единый пакет аудита OpenTorchlight

Основной документ — **REPORT_RU.md**: сквозной разбор действующего конвейера, приоритеты и полный каталог 56 замечаний/дополнений. **AGENT_HANDOFF_RU.md** — самостоятельное задание для агента, который будет внедрять изменения. Исходный проект в пакет не включён и не изменялся.

Повторная локальная проверка исходного архивного среза:

```bash
python3 run_audit.py /путь/к/OpenTorchlight-main --out /tmp/otl-audit --verify
```

Без `--verify` выполняются инвентаризация и сравнение reviewed fingerprints. При изменении исходников инструмент не накладывает старые патчи и не выдаёт устаревшие результаты за новую проверку. Полные регрессии рассчитаны на проверенный архивный срез; адаптация к уже изменённой версии делается отдельно по коду.

Для полного набора используются локальные Python, GNU g++/cc, binutils, git, patch и libz3. Среда — Linux x86-64. Установка зависимостей, сетевые запросы и вызов модели отсутствуют. Синтетические исполняемые файлы создаются локально при проверке. Некоторые тесты исполняют пять маленьких изолированных листингов, восстановленных из архива; сама игра и её original ELF не запускаются.

**results/portable-run/summary.json** содержит результат единого запуска 13 групп в этой среде. **results/active-unittests.log** содержит полный исходный unittest: 24 прошли, два требуют отсутствующий GCC 4.4.7. **results/final_source_integrity.json** подтверждает неизменность 2285 исходных файлов.

**patches/** содержит четыре опциональных патча. Они применились совместно во временной копии, после чего прошли 24 доступных Python-теста. Это не полное исправление всех замечаний и не проверка игры. Патчи не применяются автоматически. Их точная область описана в REPORT_RU.md.

**reproductions/** содержит исходники всех использованных экспериментальных инструментов из предыдущих исследований. **prior_reports/** сохраняет историческое происхождение, но не является главным документом и может описывать промежуточный взгляд. **results/findings.json** — машинный каталог замечаний; он не заменяет существующий project acceptance ledger и не является новым ручным реестром игровых функций.

Ноль новых игровых функций принят в рамках аудита: оригинальный ELF и точный GCC отсутствуют. Найденные кандидаты, синтетические проверки и готовые патчи не переименованы в восстановленную игру.
