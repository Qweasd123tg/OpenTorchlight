# Когда прекращаем ремонт конвейера и возвращаемся к игре

Цель: получить один принятый крупный метод, затем повторяемую небольшую серию. Не требуется сначала реализовать все девять исследовательских проходов. Этот документ задаёт критерии проверки, а не утверждает, что текущая ветка ПК им уже соответствует.

## Обязательный минимум для выбранного метода

### 1. Достоверные входы

Фиксированы оригинальный ELF, исходный компилятор/флаги и версия кода инструментов. Для выбранного метода есть пригодный полный вход: успешный черновик плюс ASM/символы; файл с timeout/failed не считается fresh. Ошибки типов отделены от тайм-аутов. Если updateIngameUI пока не экспортируется, не блокировать все остальные крупные методы: взять другой с проверенным входом.

Проверка: неудачный/отсутствующий экспорт возвращает неполноту; повтор обновляет именно ожидаемые цели; успешное тело не получает новый отпечаток без соответствующего обновления.

### 2. Сборка до обращения к модели

Перегенерированы include-gen и устранены дубли/несовместимые объявления для выбранного TU. Точные перегрузки и cv-квалификаторы сохранены. Компиляционный кэш учитывает смену разрешения include, а не только старый список зависимостей. Владельцем текущей доработки include-gen остаётся агент на ПК.

Проверка: базовая единица компиляции проходит без вмешательства модели; холодная и повторная сборки согласуются. Добавление одноимённого заголовка в более приоритетный каталог не возвращает старый объект.

### 3. Преобразователь не меняет известный смысл

Пройдены конкретные регрессии: квалифицированный прямой вызов остаётся прямым; числовое return(x!=false) не превращается в return x; строки/символы/комментарии не повреждаются заменами. Если конкретное правило пока не исправлено, его можно отключить для пилота, сохранив исходный черновик.

Проверка: полная цепочка convert на контрпримерах, не только один helper. Для таблиц, если выбранный метод их использует, неизвестные ячейки не превращаются в пропущенные позиции.

### 4. Приёмка не может тихо одобрить непроверенное

Ноль выполненных тестов возвращает ошибку; full selftest очищает унаследованный фильтр. Положительные stats аварийного процесса не принимаются. После header promotion проверяется финальный объект, а не совпадение слова DIFF. Кандидаты до приёмки находятся в staging.

Исправлены либо консервативно заблокированы доказанные коллизии нормализации литералов/EH для применимого пути MATCH. Ошибки наблюдения, переполнение Capture и неизвестные указатели не считаются равенством. Старый результат мутационного теста нельзя привязать к новому коду; взаимозависимые мутанты не выдают ложную независимую силу тестов.

Проверка: известные неверные варианты из приложенных контрпримеров отклоняются или получают UNKNOWN; правильный контроль проходит. Число пройденных тестов само по себе не заменяет это требование. Для пилота можно использовать более консервативную проверку вместо немедленной перестройки всей системы доказательств.

### 5. Исполнители не мешают друг другу

На первом пилоте достаточно одного владельца TU и последовательной выдачи задач. Перед расширением параллельности — независимые входы/журналы экспорта, атомарный claim, корректное восстановление после неудачного старта. Общие project/cache Ghidra и публикация одного TU требуют отдельной проверки; mkdtemp для io не решает их полностью.

Проверка: две разные задачи читают свои targets, не затирают результаты; отказ запуска не делает задачу потерянной. Если работает один исполнитель без конкурирующего экспорта, расширение распределённого планировщика не является блокером пилота.

## Первый рабочий прогон

1. Выбрать один крупный метод с доступным входом и понятным способом проверки, сохранить baseline и время этапов
2. Восстановить его существующим рабочим процессом; использовать только необходимые этому методу улучшения
3. Пройти штатную приёмку всего метода и обязательный общий прогон проекта на конечном состоянии
4. Повторить на небольшой фиксированной выборке крупных методов. Отдельно измерить ожидание/декомпиляцию, компиляцию, повторные ошибки, ручной анализ и проверку
5. Расширять параллельность, когда серия не ломает общие заголовки и артефакты

Если повторяется одна инфраструктурная причина, исправить её общее правило. Если затруднение уникально для поведения метода, продолжать восстановление игры, не открывать ради него новый универсальный исследовательский проект.

## Что можно отложить

PCH, e-graphs/альтернативные формы, широкий вывод динамических типов, всеобщий автоматический AST-перенос, полный генератор CEGUI-операций, снимки всех таблиц и универсальные нативные капсулы. Поднимать конкретное направление только если измерение или выбранный метод показывает пользу.

Узкие приёмы памяти, ABI, OGRE и переноса родственников проверять по одному на ещё не принятом участке. Итог — принятый исходник и уменьшение ручной работы. Количество рецептов, кандидатов и синтетических тестов не является закрытой частью игры.

## Чего этот пакет не доказывает

Состояние текущих исправлений на ПК неизвестно. Нет подтверждения, что весь перечисленный минимум уже выполнен. Нет измеренного общего ускорения. Ориентир 1.5–3x ранее был условной гипотезой и не должен использоваться как обещанный срок или критерий готовности.
