# large-10: menu text, pause and glyph upload

Historical integration record for the frozen port. Former method: [code-first](archive/frozen-directions/code-first.md).
Recorded menu boundary and successor checks of that port: [controller/painter](mainmenu-controller-painter.md).

## Evidence recorded before implementation

Input: complete `OpenTorchlight-gpt-pro-large-9.zip`. No original pak.zip,
Torchlight ELF or pinned libCEGUIBase is present in this environment. Earlier
integrator results are historical, not results of this pass.

The input `src/frontend.cpp::frame` collects only callback-free images and
known action buttons. All callback-free StaticText / StaticTextOutline widgets
are discarded. Resource pages still get synthetic titles. `src/ui_layout.cpp`
already preserves original Text/Font/rect; this is a lost presentation path,
not a missing resource parser. `research/original-strings.txt` contains
CharacterName, Player1Name, CopyrightInfo, CharacterModsWarning and TabTextA.

`research/ui-actions.json` records the original read-only resource bindings:
optionsmenu.layout / Settings -> guiSettingsMenu; ExitGame -> guiExitGame;
ReturnToGame -> guiCloseMenu. Exit semantics are NOT established by this table.
The new portable pause must retain .otc actions as explicitly supplemental and
must not silently interpret guiExitGame as save-and-main-menu.

The input font upload has a reproducible ordering defect:
`prepare_font` calls notify_screen_size (clears glyphs), immediately uploads
atlas_rgba (zero-filled), and does not upload when `text_run` later rasterizes
new glyphs. This makes valid resource-font text invisible. CPU atlas revision
tracking and upload AFTER glyph creation are port correctness fixes, not
original CEGUI bit parity. Input text iteration is byte-wise, not UTF-8.

Baseline no-FreeType build fails with -Werror=unused-parameter on the constructor
archive parameter. This optional configuration must compile without weakening
warnings.

## Implementation boundary

Preserve source text/font/rectangle, explicit widget image-state properties,
visibility/disabled state, and known callback dispatch. Static text formatting
and clipping are a bounded property-based renderer, not full Falagard.
Settings and the original exit confirmation flow remain unsupported. Inventory,
9-slice frames, original font DPI and exact HUD formulas remain separate work.
Tests use authored layouts and generated test glyphs; framebuffer samples are
port regression evidence, not screenshots or process traces of the original.

## Implemented boundary and fresh evidence

Resource presentation now retains static Text/Font widgets, bounded inherited
clipping and formatting. CharacterName and PlayerNName/Desc bind port state;
no .SVB parser is claimed. Known optionsmenu callbacks are mapped as above;
unsupported Settings and original exit remain disabled. Explicit PORT .otc
save actions are supplemental. Hidden/disabled source actions do not become
active fallbacks. Font GPU upload follows rasterization and atlas revisions.
PushedImage is parsed but not driven by pointer events. Colors, supplemental
geometry/focus border and incomplete Label/StateImagery remain prototype.
DPI=96 stays inferred; outlines, 9-slice and full Falagard remain open.

The exact large-9 renderer, compiled with the current probe/core, fails the
new font-only sequence on its first frame: bright pixel count 0. The fixed
renderer returns [153,419,70,115,419,419,80,459] across eight persistent-resource
states; resize back to the original dimensions reproduces the prior mask.
This demonstrates the specific port upload regression. Neither pixel counts
nor authored menu colors are an original CEGUI image oracle.

Author-created TTF test data is generated by `tests/make_ui_font_fixture.py`;
no font binaries are committed. The actual system FreeType runtime was linked
using explicitly generated test-only public ABI declarations because its SDK
headers were unavailable. The declarations implement no functions and are
not an automatic production dependency. Binding/runtime versions and offsets
are recorded in the verification directory. A normal SDK build and pinned
original-library font differential remain unexecuted in this environment.

`menu_resource_probe` / `original_menu_presentation` was compiled and sanity
checked against authored fixtures only. Original pak execution remains an
integrator prerequisite, not an implied successful test. See the Russian
result document and raw logs for exact commands and scope.
