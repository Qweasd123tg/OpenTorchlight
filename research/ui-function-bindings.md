# CGameUI::mapToFunctions: привязка команд UI

Статус: `original-code`, текущий пакет зависимости inventory/createMenus.
Не закрывает создание инвентаря, его события или весь CGameUI::onClick.

## Входы и контракт

Read-only ELF `Torchlight.bin.x86_64`, SHA-256
`91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.
`CGameUI::mapToFunctions @0xa980e0`, размер `0x374`; ASM повторно прочитан
через `tools/original.py`. Декомпиляция: `research/decompiled-core/game_ui.c`.
Таблица: `KLayoutFunctionNames @0x14b7dc0` (не другие одноимённые копии),
97 строк из инициализатора `0xa850bd..0xa85a5b`, повторно извлекаемых
`tools/audit_original.py::recover_commands`. Конструктор `0xaa6944..0xaa6960`
пишет `this+0x1790+4*i = i`, включая `96/NONE` по `this+0x1910`.

- `0xa980f7..0xa9813b`: дети перед родителем, порядок массива сохраняется;
  число детей берётся при входе, child pointer читается перед каждой рекурсией.
- `0xa98153..0xa9817f`, `0xa982ed..0xa98337`: точное свойство `onClick`;
  существующее свойство читается для проверки пустоты, непустое — ещё раз.
- `0xa98181..0xa98188`: отсутствующее/пустое свойство записывает NONE.
- `0xa981d3..0xa98201`: UTF-8 CEGUI → `std::string(char const*)` (обрезка
  по первому NUL) → `STRINGS::StringUpper @0xc8e0e0`.
- `0xa98237..0xa98291`: сравнение длины и байтов всех 97 имён. Неизвестное
  непустое имя сохраняет прежний userData. При дубликатах побеждает последний.
  Пробелы не удаляются. Непустая строка с первым NUL не равна пустому свойству.
- `0xa9833c..0xa98357`: landing pad записывает NONE; string cleanup не
  заменяется на успешное сопоставление. Рекурсия находится вне property try.

Catch-all проверен по FDE `.eh_frame +0x575c8`, LSDA `0x119c4d0`:
type index 1 по `0x119c524` равен нулю (`catch (...)`); action table
`0x119c51f` = `01 00 00 7d`. Рекурсивный call `0xa98133` имеет
landing pad/action = 0/0: ошибки обхода не поглощаются property catch родителя.

StringUpper вызывает libc `toupper` с signed-char расширением
(`0xc8e140`, `0xc8e14a`). Это байтовое преобразование в текущей C locale,
не Unicode casefold. Перенос закрепляет ASCII/C-locale контракт исходных
команд; иные locale не объявляются восстановленными.

## Граница сравнения

Минимальный native-стенд исполняет целое неизменённое тело mapToFunctions
с небольшими явно синтетическими адаптерами CEGUI/std::string/property и
StringUpper. Они задают библиотечную границу; не имитируют игру или renderer.
Сравниваются результаты привязки и порядок запросов свойств, включая
повторное чтение, child-first, неизвестное имя и NUL. Машинные записи указывают
на настоящие элементы synthetic enum-массива; порт хранит типизированный ID.

Полная CEGUI ABI/lifetime-совместимость, реальные библиотечные исключения и
производственный runtime инвентаря остаются открытыми. Синтетические
адаптеры не считаются доказательством этих зависимостей или whole-function full.

## Перенос и потребители

`ui_function_bindings.hpp/.cpp`: одна таблица 97 команд и один исполнитель
обхода через узкий `UiFunctionTree`. Адаптер `LayoutFunctions` в
`src/ui_layout.cpp` выполняет привязку при загрузке; resize/resolve сохраняют
её, не повторяют поиск строк на каждом кадре. `layout_function == nullopt`
отличается от `NONE`: первое означает отсутствие привязки, второе — enum 96.
Сырое `callback` сохранено для диагностики, включая исходный регистр.
Для существующего immutable HUD непустота `callback` также определяет наличие
кликабельной цели; произвольный runtime-remap/подписки здесь не заявляются.

`src/frontend.cpp` использует привязанный ID для выбора существующего действия;
`src/ui_hud.cpp::hud_press_function` передаёт его в настоящий application loop.
Таким образом, case-insensitive сопоставление выполняется один раз общим
алгоритмом; прежнее точное сравнение `guiToggleInventory` в HUD больше не
теряет корректные смешанные регистры. Неподдерживаемые команды не получают
выдуманного поведения. Производственная политика пяти HUD-действий не менялась.

В `tests/compare_ui_bindings.py`: 469 деревьев / 2312 узлов, все 97 имён
в исходном/нижнем регистре, NUL/пробелы/неизвестные имена, разные предшествующие
привязки и вложенные деревья; сравниваются также presence/get-вызовы.
`tests/ui_function_bindings_test.cpp`: отдельные ошибки presence/первого/второго
чтения, сохранение изменений детей при ошибке родителя, ошибки обхода,
дубликаты таблицы, динамическое второе чтение и повторная привязка.
Ресурсная проверка загружает настоящие inventory tabs 14/15/16 и HUD command 72.

Регистрации CTest: `ui_function_bindings` (core),
`original_ui_function_bindings` (assets), `original_ui_binding_comparison`
(reference). Существующий `paused_settings_render` проверяет настоящий
путь HUD InventoryButton → приложение → открытие/закрытие инвентаря, плюс
frontend-переходы. Это не сравнение целого UI с оригинальной игрой.

При сквозном прогоне найден старый дрейф теста: commit `b9c7da8` добавил
`PauseButton` в сценарий, но Python ожидал прежние четыре события. Ожидание
исправлено на все пять команд (`guiPause` плюс четыре панели), с сохранением
проверки down-before-release, отсутствия повтора, двух неподдержанных команд
и отсутствия случайного сохранения. Сценарий и production-поведение ради
этой проверки не упрощались.
