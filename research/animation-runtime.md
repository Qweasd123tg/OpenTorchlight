# Анимации моделей

## Зафиксированные входы

- `original-code`: `Torchlight.bin.x86_64`, SHA-256
  `91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.
- `library-derived`: `libOgreMain-1.6.5.so`, SHA-256
  `bef109bfdc1210ede92731ead4a2b3fae76a8905f10bac14d5fdb54ae5474c31`.
- `library-derived`: исходники OGRE, tag `v1-6-0`, commit
  `39c254402e53eea446f5f81e988154aedec1af79`.
- `resource-derived`: установленный `pak.zip`; оригинальные файлы остаются
  внешними входными данными и в репозиторий не копируются.

## Манифесты моделей

В `pak.zip` находятся 182 файла `.animation` в UTF-16LE. Строгий проход по
каждому файлу дал 1 514 секций `ANIMATION`, 2 650 секций `KEY` и 252 секции
`BONEOFFSET`. Манифест связывает модель с конкретными `.skeleton` и хранит
события `HIT`, `FOOTSTEP`, `BLENDOUT`, звук, layout частиц, кость, смещение и
дрожание камеры.

Например, `media/models/Alchemist/alchemist.animation` прямо перечисляет
`alchemist.skeleton`, `Attack1.skeleton`, `Idle.skeleton`, `Run.skeleton` и
остальные клипы. У `Attack1.skeleton` записан `HIT` на `FRAME=10.88222`.
Поэтому поиск соседнего файла по префиксу имени был удалён: он обходил
исходную таблицу привязок и мог выбрать клип другой вариации модели.

`resource-derived`: загрузчик сначала использует манифест с тем же stem, что у
mesh. Если его нет, принимается только единственный манифест каталога, который
содержит `FILE` bind-скелета mesh. Равные кандидаты считаются неоднозначностью,
а не разрешаются сортировкой имени.

`resource-derived`: состояния `Idle`, `Run`, `Hit`, `Die` и `Death` выбираются
из записей выбранного манифеста. Для атаки сначала рассматривается семейство
`Attack`, затем клипы с исходным событием `HIT`; это охватывает названия вроде
`RSlash` и `Polearm`, не вводя список имён по видам монстров.

`original-code`: стартовый `Moldy Staff` имеет тип `NORMAL STAFF`, который по
таблице unit type наследует `STAFF` (ID `0x3d`).
`CEquipment::calculateCombatStats` выдаёт и `STAFF`, и `POLEARM` описание атаки
с префиксом `POLEARM`. Поэтому игрок теперь загружает из манифеста все три
`Polearm1/2/3` в исходном порядке. `CGenericModel::findRandomAnimation`
оставляет первое совпадение, затем каждое следующее с вероятностью 50 процентов
заменяет выбранное; этот алгоритм перенесён вместо постоянного `Attack1`.

## Интерполяция OGRE

`library-derived`: `AnimationTrack::getKeyFramesAtTime` из OGRE `v1-6-0`
возвращает первый ключ одновременно как левый и правый, когда текущее время
лежит до первого ключа. `NodeAnimationTrack::getInterpolatedKeyFrame` поэтому
удерживает первый transform. Между ключами перевод и масштаб интерполируются
линейно, а вращение использует `Quaternion::nlerp` с кратчайшим путём.

Восстановленный sampler раньше до первого ключа смешивал последний ключ с
первым через конец цикла. Это исправлено отдельной синтетической проверкой с
ключами на 0,25 и 0,75 секунды: поза в момент 0 теперь точно удерживает ключ
0,25. Проверка реальных `Run` и `Attack1` Алхимика по-прежнему проходит по всем
1 524 вершинам.

`library-derived`: Torchlight подключает отдельные клипы через
`Skeleton::_mergeSkeletonAnimations`. Bind-позы `Alchemist.skeleton` и
`Run.skeleton` различаются у 37 из 43 костей; максимальная разница локального
поворота составляет 1,63506 радиана. Раньше sampler накладывал ключи клипа на
bind-позу модели напрямую. Теперь каждый ключ пересчитывается точной формулой
OGRE `destKey = inverse(destBind) * sourceBind * sourceKey`, включая создаваемый
OGRE статический track для костей без ключей. Сравнение skin-матриц реального
`Run` в момент 0,4 секунды с установленной `libOgreMain-1.6.5.so` прошло по
всем 43 костям; максимальная покомпонентная ошибка равна `4,71e-6`.

## Машинный код и границы

Символы в зафиксированном ELF:

- `0x8a2de0` — `CGenericModel::findRandomAnimation(std::string const&)`;
- `0x8a4130` — `CGenericModel::getAnimationIndex(std::string const&) const`;
- `0x8a5a40`, `0x8a5cf0` — перегрузки `playAnimation`;
- `0x8a6d70`, `0x8a71d0` — перегрузки `blendAnimation`;
- `0x8aa4b0` — `CGenericModel::updateAnimation(float, bool)`;
- `0xdd3ac0` — `CAnimationPlayer::update(float)`.

`original-code`: `findRandomAnimation` сравнивает верхний регистр префикса с
именами клипов. Для каждого следующего совпадения он заменяет текущий результат
при `randomBetweenVolatile(0, 1000) < 500`. Runtime повторяет этот выбор для
вариантов атаки игрока; последовательность случайных чисел пока локальна этому
контроллеру и не синхронизирована с общей последовательностью оригинальной игры.

`original-code`: `blendAnimation` создаёт 64-байтовый `CActiveAnimation`,
включает новый `Ogre::AnimationState`, добавляет его в очередь и сначала задаёт
ему вес 0. `updateAnimation` продвигает время каждого активного состояния,
линейно уменьшает оставшееся время blend и вызывает `setWeight`. Длительность
перехода приходит аргументом вызывающей стороны; это не общая константа.

`library-derived`: переход игрока теперь смешивает translation и rotation
костей как два OGRE `AnimationState`, а skinning выполняется один раз после
смешивания. Прежняя интерполяция уже деформированных вершин и smoothstep
удалены. Используемые runtime веса линейны. `original-code`:
`CCharacter::updateAnimation` и `CCharacter::attack` передают для переходов
игрока 0,2 секунды; runtime использует это значение для idle/run/attack.

`original-code`: `CEquipment::attachToGivenLocation` присоединяет модель
оружия к equipment bone с единичным локальным смещением и поворотом, затем
задаёт масштаб `WEAPON_SCALE`. Стартовый `staff01.MESH` теперь каждый кадр
следует за `tag_righthand` из вычисленной позы Алхимика с исходным масштабом
`0.8`.

Удалено отдельное ограничение обновления сценовых и вражеских поз до 15 Гц.
OGRE вычисляет кости из текущего набора `AnimationState` при обновлении кадра,
поэтому runtime теперь передаёт sampler фактическое время каждого отображаемого
кадра. Это устраняет видимый шаг в 66,7 мс, не меняя скорость самих клипов.

`original-code`: `CGenericModel::updateAnimation` делит `FRAME` каждого ключа
на константу 30,0 перед сравнением с предыдущим и текущим временем клипа.
Следовательно, время события в секундах равно `FRAME / 30`. Адресный ASM
производителя событий сохранён в `disassembly/8aa4b0.asm`, а порядок
`model update -> bone positions -> updateAttack` из
`CCharacter::updateAnimation` — в `disassembly/848870.asm`.

Обычная атака игрока теперь начинается без немедленного урона. Для выбранного
клипа создаётся устойчивый ID исполнения; проигрыватель публикует все ключи,
пересечённые текущим обновлением, в исходном порядке и с идентичностью клипа.
Список не забирается одним потребителем. После расчёта позы и положения оружия
каждый `HIT` вызывает отдельный `perform_attack`; до ключа HP цели не меняется.
Завершение клипа закрывает то же исполнение. Синтетический тест проверяет два
`HIT` в одном обновлении, повторное чтение списка без потери, отсутствие
дублирования и масштабирование времени скоростью проигрывания.

Вражеская обычная атака, звук, частицы, bone offset и camera shake пока не
переведены на этот список событий.

`original-code`: скорость выбранного клипа атаки вычисляется как
`max(0.2, (effect(type 0x16) / 100 + 1) / attackDescription.speed)`; у
`Moldy Staff` поле `SPEED=110` даёт знаменатель `1.1`. Связь базового
`ATTACKSPEED=80` со значением effect `0x16` ещё не доказана, поэтому эта
скорость пока не подменяется предположением.

## Воспроизведение

```sh
cmake --build build --target animation_events_test animation_manifest_test skeletal_animation_test scene_geometry_render_test
ctest --test-dir build --output-on-failure \
  -R 'animation_events|original_(animation_manifests|skeletal_animation|scene_geometry_render|combat)'
```

Тест манифестов обязан разобрать все 182 оригинальных файла с точными общими
счётчиками. Рендерный тест дополнительно требует, чтобы пять состояний
контрольного `Skeletal Warrior` пришли из одного манифеста, а выбранная атака
содержала исходное событие `HIT`.
