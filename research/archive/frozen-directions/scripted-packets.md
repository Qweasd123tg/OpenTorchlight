# Скриптовые пакеты исследования

> **Архив замороженного направления.** Указания, команды, очереди и числа ниже
> относятся к прежнему снимку; они не задают текущую работу или приёмку.
> Действующий процесс: [decomp](../../../decomp/README.md).

Статус: локальная детерминированная автоматизация. Скрипт не вызывает модель,
сетевой API или оригинальный процесс и не изменяет исследовательские реестры.

Для семейства основной вход — `prepare_family_packet.py` и короткий `ENTRY.md`:
[codefirst-tooling.md](codefirst-tooling.md). Описанный здесь инструмент —
нижний уровень для явных адресов. Отдельное `completion` и открытый остаток
включаются в карточку; четыре legacy-стадии не означают whole-function closure.

## Что автоматизировано

`tools/function_package.py` один раз загружает индексы репозитория и собирает
для явно заданных начал функций:

- строку `coverage.tsv` и четыре независимые стадии
  `function-transfer.json` без их повышения;
- множество прямых рёбер графа и, когда экспорт существует, все места вызова
  с сохранением повторов и сортировкой по статическим адресам инструкций;
- имеющиеся ссылки на декомпиляцию, дизассемблирование, код и тесты;
- известные evidence/implementation/tests/comparison ссылки;
- структурированный список незакрытой работы;
- SHA-256 идентичность оригинального ELF и составной отпечаток каждого
  прочитанного входного файла.

JSON стабилен при неизменных входах: в нём намеренно нет времени генерации,
абсолютных путей рабочих копий и случайных идентификаторов. Входы скрипт
только читает. Кеш не добавлен: полный хеш прочитанных файлов одновременно
служит безопасной проверкой актуальности; кеш по mtime создавал бы риск
использования старых доказательств.

## Использование

Один прежний markdown-пакет:

```sh
python3 tools/function_package.py --address 0xb4eb70
```

Структурированный пакет для явной группы:

```sh
python3 tools/function_package.py \
  --address 0xb4eb70 \
  --address 0xb569e0 \
  --format json \
  --out /tmp/inventory-packet.json
```

Чтобы за один проход оставить и читаемый Markdown, и структурированный файл:

```sh
python3 tools/function_package.py \
  --address 0xb4eb70 \
  --out /tmp/inventory-packet.md \
  --json-out /tmp/inventory-packet.json
```

Допустимо от одной до 64 функций. Адрес обязан совпадать с началом функции из
`research/original-symbols.txt`: невалидный, неизвестный или interior-адрес
завершает команду ошибкой. Это не даёт молча подменить запрос ближайшей
функцией. `--symbol` оставлен для одиночного однозначного поиска.

Если `research/original-callsites.tsv` ещё не экспортирован, JSON содержит
`callsites.available=false`, предупреждение и unresolved-код
`callsites_index_missing`. Множество из `original-callgraph.tsv` не выдаётся за
порядок или кратность вызовов. После штатного экспорта Ghidra через
`tools/ghidra/export_call_sites.sh` те же пакеты автоматически включат места
вызовов; повторяющиеся sites не удаляются.

Можно передать готовый локальный индекс без копирования в репозиторий:

```sh
python3 tools/function_package.py \
  --address 0xb4eb70 \
  --callsites /tmp/opentorchlight-callsites.tsv \
  --json-out /tmp/inventory-packet.json
```

При наличии `/tmp/opentorchlight-callsites.tsv.meta.json` проверяются его
`kind=direct-callsites`, SHA-256 TSV и SHA-256 поддерживаемого ELF. В пакет
попадают граница экспортёра и только те unresolved indirect/virtual sites,
у которых запрошенная функция является caller. Повреждённый индекс или
sidecar с другим ELF отклоняется.

Сортировка по адресу инструкции не является порядком исполнения runtime:
условия ветвей, число фактических проходов цикла и виртуальные цели остаются
явно неразрешёнными.

## Граница автоматизации

Это объединитель уже собранных фактов, а не декомпилятор и не восстановитель
семантики. Он намеренно не:

- придумывает ABI, типы полей, виртуальные цели и условия ветвей;
- считает навигационный псевдокод доказательством;
- повышает стадии переноса;
- запускает тяжёлый анализ Ghidra или оригинальный ELF;
- объявляет функцию завершённой только потому, что список unresolved пуст.

`--out` и `--json-out` разрешены только вне дерева исходников либо в
игнорируемом каталоге сборки. Они не могут перезаписать ELF, callsites,
sidecar или любой прочитанный вход. Путь назначения не входит в отпечаток:
одни входы дают один JSON независимо от места сохранения.

Готовая внешняя часть процесса уже используется: Ghidra headless создаёт
целевые экспорты и callsites, а этот стандартный Python-скрипт детерминированно
соединяет их с локальными реестрами. Поэтому отдельный сервис или нейросетевая
оркестрация для подготовки пакета не нужны.

## Проверка

```sh
python3 tests/function_package_test.py
```

Проверяются невалидный/interior/неизвестный адрес, лимиты 1 и 64, явное
отсутствие callsites, сохранение повторных вызовов, проверка sidecar,
запрет перезаписи исходников, стабильность JSON и неизменность входных файлов.
Тест также зарегистрирован в CTest как `function_package_automation`.
