## Как начать и вернуть работу

Создайте новую рабочую папку из переданного git bundle, чтобы не затереть
имеющиеся изменения, и отдельную ветку, например `user-collision`.
Прочитайте AGENTS.md, decomp/README.md и decomp/WORKER.md.
Пути worktree в WORKER.md — пример прежнего процесса, используйте свою копию.
Не переписывайте историю переданной базы. Возвращайте коммиты своей ветки
в git bundle и короткое описание проверок/общих изменений.

Git bundle содержит историю и отслеживаемый код. Оригинальный ELF, pak.zip,
компилятор и кэш в него не включены: используйте исходные handoff/extra входы.
Пути задаются OTL_DECOMP_CACHE и TORCHLIGHT_GAME_DIR; окружение сборки должно
использовать исходный GCC 4.4.7-3.el6 и необходимые библиотеки оригинала.
Начните с `python3 tools/decomp/check.py` и подтвердите исходное состояние.

Пакеты можно подготовить через `python3 tools/decomp/scaffold.py collisionlist.cpp`
и аналогично для остальных TU. Функции принимаются через MATCH либо
сравнение с оригиналом и сильные mutation tests по действующим правилам.
Игру с окном не запускайте; проверки гибрида заканчиваются до main.

## Полезные уже проверенные детали

- CollisionModel имеет размер 0x48, указатель CollisionList расположен на 0x38.
- CollisionList имеет размер 0x108; размеры подтверждены new в оригинале.
- Ray/sphere wrappers возвращают bool: вызывающий BaseUnit читает AL.
  Черновик Ghidra ошибочно показывает void, ему нельзя доверять без ASM.
- `decomp/hybrid/tests/BaseUnitCollisionTest.cpp` использует настоящий
  CollisionList с двумя гранями и оригинальные вычисления нормалей/bounds.
  Он покрывает 768 сценариев, включая реальные попадания обоих видов.
  Это готовый пример окружения, но не замена тестам всех 44 функций.
- При подмене vtable для fixture сохраняйте два RTTI-prefix элемента:
  настоящий dynamic_cast иначе может падать.
- Одновременное падение обеих сторон теста не является успешным сравнением.
