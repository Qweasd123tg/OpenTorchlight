# Ограниченный модельный конвейер

Работа продолжает контрольный игровой коммит `38b8f52` в ветке
`bunny/character-inventory-pilot`. Это доработка существующего `llm_loop.py`,
не новый процесс контрактов и не второй оркестратор. Цель — восстановленный
исходник оригинальной Torchlight, а не максимальное число запросов к модели.

## Реализовано

- Бесплатная `opencode/space-bunny-free` по умолчанию, без скрытого платного
  fallback. Кодовая модель работает через общий OpenCode V2 service в
  изолированном deny-all профиле: без инструментов, LSP и snapshots.
- Конечный срез TU: адреса/символьные алиасы, предел числа определений и
  размера функций. Уже определённые функции исключаются до применения limit;
  ABI-thunk не становится самостоятельным заданием на написание C++.
- Целевой ASM и полный заголовок владельца, ограниченный prompt; необязательные
  примеры убираются первыми. Обязательные входы не обрезаются молча. Ghidra
  автоматически не запускается; недоступные объявления блокируются до запросов.
- Атомарный checkpoint и возобновление из `publication.Stage`; восстановленные
  статусы не являются доказательством, определения сравниваются заново.
- Вызовы модели параллельны, операции над Stage/окружением последовательны.
  Host-wide flock-пулы ограничивают preprocessing, backend, assembly и
  headless-процессы независимо от числа worktree. По умолчанию два слота каждого
  типа (на одноядерной машине один); авария процесса освобождает слот.
- Публикация только явным `--publish`, из проверенного конечного снимка.
  Прежние исходные байты сохраняются, неожиданный delta отклоняется.

Инструкции запуска — `decomp/README.md`, раздел «Модельный конвейер».

## Закрытые риски приёмки

Независимый аудит обнаружил, что прежняя проверка одного запрошенного адреса
могла пропустить дополнительное определение из ответа. Теперь модельный текст
должен содержать ровно одну функцию; MATCH проверяется у всех испущенных
ABI-вариантов этого определения. Конечная Stage проверяет новые оригинальные
определения независимо от weak/strong и owning TU; DIFF требует свежего
выполненного сравнения, в том числе для каждого отдельного варианта.

Локально определённый придуманный игровой метод не считается допустимым лишь
потому, что нет unresolved references. EXTRA разрешены узко: GCC scaffolding
и стандартные template helpers; старый прочий EXTRA сохраняется только с
прежним полным объектом и контекстом. Compiler initialization не считается
перенесённой игровой функцией и не подменяется гибридом.

Сгенерированные сравнения включены в финальную проверку; их файлы
fingerprinted до публикации. Stats-only, чужой PASS, неполный вызов и старый
checkpoint не дают приёмку. Journal/rollback публикации сохранены.

## Настоящий пробный запуск

```sh
python3 tools/decomp/llm_loop.py inventorymenu.cpp --address 0xb457a0 --address 0xb457c0 --address 0xb457e0 --jobs 3 --rounds 2 --model-retries 0 --no-autotest
```

Получено **три MATCH с первой попытки**: equipmentDropped,
equipmentEquipped, equipmentUsed. Проверены и три соответствующих non-virtual
thunk: всего шесть испущенных оригинальных адресов. Финальный TU собирается
без generated include paths. Модель не читала репозиторий и не запускала tools.

| Метрика | Результат |
|---|---:|
| Реальные модельные запросы | 3, все `ok` |
| Передано / получено | 26145 / 253 символа |
| Отдельные запросы, wall time | 9,318 / 68,651 / 124,671 с |
| Весь диагностический запуск | 143,49 с |
| User + system CPU | 19,60 + 2,26 с |
| GNU time max RSS | 291304 KiB (284 MiB) |
| Тесты инструментов с JDK | 289 PASS, без skip |

RSS — максимум из отчёта GNU time, **не сумма памяти всех одновременно
работавших процессов и общего OpenCode service**. Это один запуск с тремя
запросами, не benchmark десятков агентов. Token usage CLI в этом запуске не
вернул; количество символов не выдаётся за количество токенов.

Первая проверка публикации отказала на линковке самотестов: в конечном снимке
не было общей observer storage из `AutoTestRuntime.cpp`. Теперь runtime
готовится независимо от генерации новых сравнений, **до** fingerprint fixtures;
сохранённые сравнения при этом не удаляются. Исправление покрыто тремя тестами.
Сохранённый кандидат rebased штатным `Stage.rebase()` на исправленные инструменты.
Повторная полная проверка и публикация завершились: **104 самотеста PASS**,
все шесть новых адресов MATCH. Изменён только `decomp/src/inventorymenu.cpp`;
полная проверка и публикация заняли 1545,63 с, отдельно от модельного запуска.

## Следующий, более сложный срез

Первый запуск `CCharacter::giveGold(int)` и `strength()` дал 0 принятых из 2
за три раунда: ответы не соблюдали кодовый формат. В deny-all профиле
обнаружен `steps=1`: OpenCode V2 на последнем шаге просит текстовый итог,
конфликтующий с задачей написания функции. Лимит шагов **убран полностью**,
а не повышен до другого малого числа; профиль с таким лимитом отклоняется.
Таймаут зависшего вызова и межпроцессные resource slots сохранены.

Повторный Character-срез с таймаутом 600 с завершился за 6,8 мин: пять
модельных ответов, **все `ok`** по формату. `strength()` получил MATCH во
втором раунде. `giveGold()` после трёх раундов остался DIFF: лишние записи
баланса при сходной структуре ветвей. Вместо дальнейшей подгонки инструкций
подготовлен отдельный оригинал-vs-восстановленный тест на 648 входах: нулевые,
положительные и отрицательные суммы, границы `int`, насыщение, цепочки
владельцев длиной 0/1/3, вызовы журнала и изменение баланса в collaborator.
Используется явная coverage receipt точной пары вызовов, не просто PASS.
Тест выполнен: **648 завершённых сравнений, 0 различий, 0 неполных вызовов**;
он написан родителем, а не получен автоматически из ответов Bunny.

Achievement-срез завершился за 12,2 мин: шесть ответов `ok` по формату,
**0 принятых из 2**. `checkForAchieved()` обращается к таблице
`g_strStatDefines`; в пакете нет её объявления, модель вместо этого придумала
несуществующий `CSteamStats::getStatType()`. Шлюз это отклонил.
`getStatCompleteString()` компилируется, но последний ответ перепутал текущий
стат и требуемый в строке; его DIFF не является только различием размещения
локальных переменных. Эти ответы не добавлены в игровые исходники.
Для следующего такого среза пакету нужны объявления конкретных зависимостей
и проверенные referenced data, а не новые попытки с теми же неполными входами.

Первый Cinematics-срез: поиск по имени (430 байт оригинала) остался DIFF после
трёх кодовых ответов; для него подготовлен отдельный поведенческий тест.
`reload()` (1806 байт) **не дошёл до модели**: обязательный пакет 25570 символов
не прошёл прежний лимит 24000. Это ограничение подготовки, не неудача Bunny.
Бюджет по умолчанию увеличен до 131072; `reload()` повторно запущен с таким
пакетом и таймаутом 900 с. Второй запуск занял 14,4 мин: три ответа `ok`,
функция компилируется, но осталась DIFF, в том числе по пути освобождения
памяти; её приёмки нет. Blocked больше не включается в число accepted в
промежуточном логе.

Поиск cinematic по имени прошёл тест: **864 завершённых сравнения, 0 различий,
0 неполных вызовов**. Покрыты пустой и непустой список, найденные и отсутствующие
ключи, регистр/Unicode, индексы в пределах и вне списка, ёмкость, null-элемент;
наблюдаются возвращаемая идентичность, строки, map и список. Этот тест тоже
написан родителем. Оба новых теста повторно прошли вместе в одном снимке.

Итого после снятия лимита шагов: 17 кодовых ответов, все `ok` по формату;
104233 / 8885 символов sent/received. Из шести функций следующего среза один
MATCH (`strength`) и два успешных поведенческих сравнения (`giveGold`, поиск
cinematic). Три остальные определения не допущены в игру. Это не результат
полностью автоматического переноса 3/6: две оснастки разработаны вручную.
Общая финальная проверка трёх кандидатов отказала в публикации: добавление
поиска cinematic изменяет полный объект TU, где уже есть непроверенные DIFF
`CCinematic::load` (`0xe79710`) и конструктор `CCinematics` (`0xe7a3a0`).
Успешный тест нового метода не принимает за них поведение. Шлюз не ослаблен,
Cinematics-кандидат и его fixture сохранены в ignored попытке, игровой TU
не изменён. Для этого TU нужен отдельный класс/TU-срез с проверкой старых DIFF.
Character опубликован отдельным срезом: `strength()` MATCH, `giveGold()` принят
выполненным сравнением. Полная проверка конечного дерева завершилась:
**913 MATCH, 916 принятых функций, 59821 байт; 105 самотестов PASS**.
Все прежние принятые адреса сохранены; Merchant/Stash и их тесты не менялись.

## Измерение общих расходов

Профиль сравнения показал лишний расход на `SequenceMatcher.ratio()` всех DIFF:
процент похожести — диагностика, не приёмка. Проверенный ignored прототип
отключает только эту метрику: Character 2,92 → 0,71 с, Equipment 5,73 → 2,79 с.
Объекты и все поля результата, кроме score, одинаковы; шесть offline-тестов
проверили сохранение отказов по коду, данным, EH и неизвестным ссылкам.

Проверка опубликованного дерева использует только полный digest объекта и
неизвестные ссылки, но заново нормализует и оценивает все функции. Прототип
того же полного object-identity маршрута без ненужного анализа: 0,37 / 0,80 с
для тех же TU, обе проверяемые величины совпадают. Это пока не ускорение всего
`check.py` и не перенос старых поведенческих свидетельств на новые объекты.

В публикации Character 480 с прошли до готовности гибрида; ещё 994 с — самотесты
и конечная проверка публикации. По таблице тестов и записанным timing четыре
shard получили 543 / 267 / 352 / 353 с работы при двух host-wide slots.
Балансировка имеет потенциал, но её ускорение ещё не измерено выполнением.

Автосбор и оба ускорения подключены к существующему конвейеру, без новых
оркестраторов и без правил под отдельные игровые методы. Пакет берёт owning
header, прямые игровые зависимости и данные из одного индекса снимка и
кэшируется до модельных раундов. Отсутствующие объявления и переполнение repair
budget дают явный blocked; код/feedback не режутся. Строгая подготовка обоих
Achievement-методов и Cinematics reload на настоящем ELF проходит без gaps.

На интегрированных инструментах warm-cache контроль дал Character 1,87 → 0,49 с
и Equipment 4,34 → 2,11 с. Верификация полных опубликованных объектов — 0,29 /
0,62 с; digest и неизвестные ссылки совпали с полным анализом. Это локальные
замеры сравнения, не обещание такого же ускорения всей игры/самотеста.
**351 тест инструментов PASS**, без skip. Полный `check.py` интегрированной
версии также прошёл: **913 MATCH, 916 принятых функций, 59821 байт;
105 самотестов PASS**, ни одного потерянного принятого адреса. Приёмка не
ослаблена; игровые исходники, заголовки и ручные тесты этого среза не менялись.

Полный прогон занял 1280,92 с (21,3 мин): около 452 с до готовности гибрида и
829 с на самотесты/завершение. Предыдущий прогон по соседним timestamps артефактов
занял около 1158 с (19,3 мин). Это не контролируемая парная серия: одновременно
шли модельные задания, сборки и ожидание общих slots. **Ускорение полного
`check.py` пока не подтверждено**; ускорение отдельных сравнений нельзя выдавать
за ускорение всего процесса. Сумма записанных времен 105 тестов почти одинакова
(1486,41 / 1486,36 с), основная оставшаяся стоимость — сборка и самотесты.

Первый повтор с автосбором Achievement завершился за 8,3 мин: 0/2 принятых,
три `ok` и три `transient` ответа из шести запросов (сеть и quota 429).
Пакеты самих функций подготовились без gaps. Ответы используют настоящую
`g_strStatDefines`, литералы `1/1`, `0/1`, `/` и верный порядок current/required;
прежнего выдуманного API больше нет. Кандидаты всё ещё не приняты, и исправления
под эти два метода не добавлялись. Из-за ошибок провайдера этот прогон не является
чистым сравнением качества модели с предыдущим запуском.

Следующая серия Character подготовлена по 16 отсутствующим методам размером
120–800 байт с существующими объявлениями. Автосбор пропустил 9 пакетов,
7 остановил до модели на недостающих сигнатурах владельца/прямых callees.
Все причины сохранены в ignored result; отдельного ручного ремонта этих случаев
не было. Готовая часть серии завершилась тем же checkpoint за 22,4 мин:
**0/9 принятых**, 27 запросов — 7 `ok`, 18 `transient`, 2 `timeout`.
Ошибки провайдера содержат quota 429 и обрывы соединения; пригодные ответы
также имели ошибки компиляции/выдуманные члены, поэтому нулевой результат нельзя
объяснять только провайдером. Попытки сохранены, публикации нет. Новые запросы
остановлены: повторять серию в таком состоянии бесплатного сервиса невыгодно.

## CPU и память подготовки

После отдельного профиля подключены индекс диапазонов EH и дешёвые фильтры
ASM перед регулярными выражениями. Индекс хранит неизменяемый снимок и максимум
правой границы каждого префикса: вложенные/перекрывающиеся FDE не скрываются.
Отказы по частичному/множественному overlap, LSDA, personality и ошибкам разбора
сохранены. **362 теста инструментов PASS**, включая контроль этих границ.

Парный ресурсный контроль использует одинаковые 3623 запроса к оригинальному
EH и 289 ASM-файлов, без компилятора, модели и игры. До/после совпадает полный
digest выходных текстов и метаданных. Это подготовительные ядра, не полный
`check.py` и не число принятых игровых функций в час.

| Запуск | CPU-секунды до → после | Wall-секунды до → после | Пик PSS до → после |
|---|---:|---:|---:|
| Один worker | 44,26 → 9,05 | 44,83 → 9,35 | 117,6 → 118,5 МиБ |
| Два worker одновременно | 102,50 → 20,28 | 52,39 → 10,47 | 233,7 → 233,8 МиБ |

CPU-расход изменённых ядер снижен примерно на 80% без повышения количества
workers или host-wide slots. Память практически неизменна, небольшая цена индекса
учтена. Логически прочитано около 106 МБ каждым worker до и после; разницу
физического IO нельзя приписывать оптимизации из-за прогрева файлового кэша.
Прочие расходы (компилятор, отдельные objdump, fork-самотесты) здесь не устранены.
Полная проверка нового конечного дерева завершилась: **913 MATCH, 916 принятых
функций, 59821 байт, 105 самотестов PASS**, все прежние принятые адреса сохранены.
Wall 1009,97 с (16:50), против 1280,92 с в предыдущем прогоне. Это наблюдаемые
прогоны, не контролируемая парная серия. GNU time зарегистрировал 380,51 user +
1349,64 system CPU-секунды, включая дочерние процессы; максимум RSS отдельного
процесса 407944 КиБ, не совокупный пик дерева процессов. Уменьшение ресурсов
всего `check.py` по этим данным не сравнивается: старого парного CPU/RSS-отчёта нет.

По просьбе пользователя следующая серия Bunny выбирает отсутствующие игровые
методы размером 1–4 КБ, не мелкие callbacks. Автосбор проверил 52 кандидата:
14 прошли проверку прямых зависимостей/данных без gaps, 38 — нет. Это ещё не
проверка точной owning-сигнатуры конвейера. Полная подготовка шести выбранных
методов заблокировала `CDataGroup::SetGroupName` (2598 байт),
`CSoundBankDataInformation::parseSoundData` (3368 байт) и векторную перегрузку
`CCollisionList::sphereCollision` (2080 байт) на сигнатурах заголовков.
Частного ремонта не было. На модель отправлены `createSoundData` (1834 байта),
другая `sphereCollision` (2054 байта) и `rayCollision` (1024 байта): два TU
параллельно с одним запросом каждый. Collision завершился без кода: все шесть
запросов получили quota 429 `FreeUsageLimitError`. Это не отрицательная оценка
способности модели на крупных методах. SoundBank при возобновлении остановился
до модели: автодополнение добавило дубликат `parseSoundData(const std::wstring&)`.
Проверка owning-сигнатур не распознаёт эквивалентность стандартных typedef/default
template arguments; заголовок и повреждённая попытка сохранены для общего
исправления, без ручного вмешательства в fingerprints. Для `createSoundData`
без проблемного соседа запущена новая отдельная попытка на один запрос, чтобы
не повторять серию при закрытой квоте. Публикации новых функций нет.

Отдельный `createSoundData` тоже получил quota 429, без кода. По новой явной
просьбе пользователя те же три функции запущены через подписочный
`opencode-go/deepseek-v4.1-flash`, без цепочки моделей и без изменения дефолта.
Оба TU завершились без ответов: Go отклонил запросы HTTP 400
`This Go model requires Global regions. Select Global in your workspace's
Privacy settings to use it.` Настройки Privacy/Regions и списания с баланса не
менялись. Качество DeepSeek на этих функциях пока не измерено; нужна доступная
для текущих настроек модель либо решение пользователя о Global regions.
Параллельный полный `check.py` ресурсного среза завершился успешно; результаты
и оговорки GNU time приведены выше. Пользователь подтвердил переключение
Privacy/Regions в Console; та же серия DeepSeek повторно запущена свежими
попытками, без изменения локальных исходников/инструментов и цепочек моделей.

## Границы

Конвейер требует подготовленных типов/раскладок; он не решает автоматически
все неоднозначности ABI и сложные методы. `--no-autotest` оставляет DIFF в
артефактах. Restored `tested`-DIFF консервативно отклоняется, если не стал свежим
MATCH; для него требуется новый выполненный маршрут сравнения.
Ни MATCH, ни успешный гибрид не означают готовую самостоятельную сборку игры.
