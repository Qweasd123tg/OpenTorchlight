# OpenTorchlight — отдельный cooldown AI

Патч подготовлен поверх **OpenTorchlight-gpt-pro-6(1).zip**, без изменений GitHub.
SHA-256 исходного архива:
`99e75e0520d2161809dc0eb1f36df6f7da02b5ea2145e39ae71a12b655a854b7`.

## Результат

Монстры учитывают `AI_ATTACKCOOLDOWN` своего UNIT и выбранного оружия.
Восстановленный таймер AI отделён от пока прототипного времени действия врага.
Оба идут одновременно; ожидание AI не добавляется после завершения действия.
Код атаки игрока, переходы, материалы, логический dispatcher и Timer не менялись.

Особенно важна связь, которой не хватало прежним ревью: поле
`equipment+0x408` тоже происходит из **AI_ATTACKCOOLDOWN**, а не из SPEED.
`CEquipment::calculateCombatStats @0x880950` и `CMonster::unitInit @0x8e2ae0`
используют один адрес ключа `0xfcf8a0`. Порядок взведения виден в
`CMonster::attackAI @0x8dfd80`, точный диапазон `0x8e00e6–0x8e013d`.

Для конечных float32 алгоритм таков:

```text
При обновлении: remaining -= dt

После успешного начала атаки:
    если есть выбранное оружие:
        remaining = max(0, remaining) + weapon.AI_ATTACKCOOLDOWN
    remaining = max(0, remaining) + monster.AI_ATTACKCOOLDOWN
```

Отрицательный остаток времени не сокращает свежую задержку. Отрицательный
вклад оружия зажимается до прибавления UNIT, но финальное значение UNIT не
зажимается. NaN/Inf отклоняются загрузчиком как некорректные входы порта;
это не утверждение о поведении оригинальной игры на повреждённых данных.

## Измеренное изменение

Одинаковые остальные параметры, собственные синтетические UNIT, шаг 1/16
секунды, время **от 0 до 1,5 секунды включительно**:

| Вариант | До патча | После патча |
|---|---:|---:|
| UNIT cooldown 0, без оружия | 2 атаки | 2 атаки |
| UNIT cooldown 2, без оружия | 2 атаки | 1 атака |
| UNIT cooldown 1,5 + weapon cooldown 0,5 | 2 атаки | 1 атака |

Эти результаты получены на библиотеках до/после изменения, а не в оригинальной
игре. См. `logs/before.txt`, `logs/after.txt` и
`evidence/reproduce_ai_cooldown.cpp`.

`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`.
Сборка: GCC 14.2.0, CMake 3.31.6, Linux x86-64. Команды и полный вывод сохранены
в `logs/`; тест с оригинальным pak собирается, но без пакета не исполнялся.

Новый тест проходит реальную цепочку PakArchive/ADM/BASEFILE/создание сущности/AI.
Он проверяет UNIT-default и override, выбор оружия напрямую и через spawn-класс,
размещённых и созданных монстров, длинный action timer, параллельность таймеров,
ожидание, потерю и повторное обнаружение цели, отказ атаки, некорректные входы
и индивидуальное состояние двух монстров.

## Границы доказательств

**ELF не запускался и в архив не включён.** Два неизменённых scalar-среза
(87 + 20 байт) восстановлены из ранее предоставленного адресного текстового
дампа. SHA-256 дампа совпал с манифестом старого пакета. В срезах нет внешних
вызовов или RIP-констант; синтетическая ABI-обёртка только передаёт адрес
объекта, сохраняет RBX и возвращает управление. Это подтверждает арифметику,
но не исполнение полной атаки, updateAI, OGRE или игры.

При наличии закреплённого ELF новый тест `original_ai_cooldown_comparison`
самостоятельно проверит его SHA-256, ключ свойства и прочитает исходные bytes
из file-backed сегментов. Здесь этот режим не выполнялся.

Подробное исследование с адресами, статусами `original-code` / `inferred` /
`prototype`, происхождением предыдущего дампа и следующей задачей:
`changed-files/research/monster-ai-cooldown.md`.

**Вражеская анимационная часть остаётся prototype.** Ограничитель действия
врага по-прежнему равен `max(0.1, 100 / ATTACKSPEED)`, а его урон происходит при
старте логической атаки. Исправлен именно независимый AI cooldown, не весь
боевой цикл. Эффект 0x16 и таймер клипа игрока не изменены. Полный порядок фаз
`CGameClient::updateIngame`, выбор атак и поведение при Disable/Enable не
считаются восстановленными.

Оригинальные ELF/pak отсутствуют; заявленные исходным пакетом 39 проверок с
установленной игрой не повторялись. Графический desktop не собран и не
запускался: отсутствуют development-пакеты Wayland/EGL/GLES. Эти ограничения
не скрываются успешными независимыми тестами.

## Применение

Для **чистой версии из шестого архива** положить `OpenTorchlight-ai-cooldown.patch`
в корень проекта и выполнить:

```sh
git apply --check OpenTorchlight-ai-cooldown.patch
git apply OpenTorchlight-ai-cooldown.patch
bash tools/check.sh --portable
```

В полном `OpenTorchlight-gpt-pro-6-patched.zip` изменения уже применены.
На него повторно накладывать patch не нужно. Применение поверх других
локальных изменений не проверялось; сначала использовать `git apply --check`.

Для самостоятельного сопоставления с установленным оригиналом:

```sh
bash tools/check.sh /path/to/Torchlight/game
```

При такой конфигурации CTest подключит и новый original-режим scalar-проверки.
Не считать этот будущий запуск уже выполненным.

Содержимое этого комплекта: patch, только изменённые файлы, числовой
воспроизводящий стенд, логи и контрольные суммы. Полная версия проекта
поставляется отдельным ZIP.
