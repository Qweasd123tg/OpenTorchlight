# large-6: автоматический стенд на настоящем pak

## Результат и входы

Реализованы независимые группы проверок, общий цикл приложения для окна и
сценариев, каталог ресурсов, настоящая EGL/GLES-сцена, точные дампы и diff.
На предоставленном pak семь отдельных процессов прошли меню/классы/Town,
движение/экипировку/resize/save/Continue и Town → Main:1 → Town. Ручной просмотр
не был условием прохождения. Стенд сам обнаружил неправильный обратный
переход и позволил проверить его узкое исправление.

Это не полное завершение шести этапов задания: новый compositor/input harness
не реализован; живые original-process traces не получены. Первые четыре
этапа доведены до описанной ниже границы, пятый расширен только в ограниченной
численной части. Исторические сравнения не подменяют новый прогон ELF.

Исходный архив: `OpenTorchlight-gpt-pro-large-6.zip`, 538 файлов, SHA-256
`9147fd500e1e177c5718c2ed0d816ef1e33cb96ca87504ccc8e57a2be62e6ac8`.

Ресурс: настоящий `pak.zip`, 24 876 записей, SHA-256
`8650ad752a81e7289e94e7b1bd3c86404ff2b0c74d7abab34fb8fc4d515064d8`.
Хеш совпал с закреплённым исследовательским входом. Pak не изменялся и не
включается в выходные файлы. Оригинальный ELF отсутствует.

Компилятор GCC 14.2.0. Реальный графический контекст: EGL 1.5, Mesa
25.0.7-2, OpenGL ES 3.2, llvmpipe LLVM 19.1.7. Контекст surfaceless/pbuffer,
не Wayland-окно. Нет development SDK EGL/GLES/Wayland и Weston. Попытка
установки зависимостей закончилась DNS-ошибкой; настоящие runtime-библиотеки
Mesa доступны. Не использовались графические функции-заглушки. Инструмента
отдельных субагентов в этой среде нет; независимые сборки/процессы выполнялись
локально. В GitHub изменений нет.

## 1. Что изменено

### Группы и строгий отчёт

`TORCHLIGHT_GAME_DIR` отделён от `TORCHLIGHT_ORIGINAL`. Все прежние 27 тестов,
которым достаточно pak, перенесены в ресурсный блок. Renderer отделён от
Wayland, который нужен оконной цели. `--assets`/`--reference` без запроса
окна не пытаются собирать desktop. Полный список исходных 67 имён тестов
сохранён; новых имён восемь, всего 75 условных регистраций в CMake. Это
проверка исходных регистраций, не заявление «75 тестов здесь выполнены».

Драйвер `tools/check.py` поддерживает core/assets/reference/render/desktop,
JSON/JUnit, явно выбранные входы, их SHA, NOT RUN и ненулевой код для
недоступной обязательной группы. Перед сборкой обнаруживает пустые группы;
отсутствующий оконный harness не заставляет собирать посторонние цели ради
ложного smoke. CTest skip, пустая или повреждённая XML-запись не становятся
PASSED. Проверено реальным вызовом: отсутствующий ELF и desktop при имеющемся
pak дали два NOT RUN и exit 1, без полной сборки.

Первая ресурсная попытка дала 26/27: bootstrap требовал внешний resources.cfg.
Теперь явный `--pak` проверяет архив; старый установочный режим остаётся
строгим. При наличии resources.cfg для него зарегистрирован отдельный тест.
Не создан фиктивный конфиг вместо отсутствующего исходного файла.

### Один цикл приложения

Примерно полторы тысячи строк игрового владения и порядка исполнения
вынесены из `linux_desktop_main.cpp` в `application.cpp`. Общими остались
frontend/session/load/save, world/logic/AI, анимации, взаимодействия, камера,
renderer и HUD. Окно адаптирует системный ввод/время/размеры/EGL swap.
Сценарный host подаёт события в те же обработчики. Он не создаёт сессию
в обход меню и не телепортирует героя к ожидаемой точке.

Вводится монотонное время и seed; сценарный dt по умолчанию 1/60 — prototype,
не оригинальный scheduler. Пишется порядок RNG-вызовов с состояниями,
границами и результатами. Наблюдение не меняет RNG; отдельный тест проверяет
в том числе вложенные scopes. Указатели не используются как стабильные ID.

### Настоящий рендер и первая разница

На каждой контрольной точке записываются state, world/bone/camera transforms,
материалы/текстуры/RGB uniforms, blend/depth/alpha/cull, RGBA8, actor contribution
mask и provenance. Размер/позиция UI для кликов берётся из реального frontend
frame. Новая проверка pause/resume удерживает время и сравнивает первый
вернувшийся кадр и render-state точно; она не ждёт, пока последующие кадры
случайно восстановят состояние.

Герой должен вносить видимый вклад в городской кадр. Диагностический повтор
временно убирает героя/оружие, строит маску изменившихся пикселей, возвращает
прежнюю видимость и требует идентичный framebuffer. Это contribution mask,
включая соответствующие тени, не идеальный ID/depth pass. За открытым
инвентарём нулевая видимость допустима, на обычном Town и после resize — нет.

`compare_scenarios.py` даёт первое поле/индекс/пиксель/канал расхождения. В
двух новых процессах совпали точно 33 файла: состояния, render metadata,
ordered RNG, картинки и маски. Нет 99%-метрики, подобранного допуска или
незаметной перезаписи эталона. Негативные фикстуры ловят изменение кости,
текстуры, RNG, одного пикселя, потерю файла и provenance. **Это собственный
regression baseline порта, не эталон исходной картинки Torchlight.**

## 2. Семь настоящих процессов

Основной сценарий создаёт Destroyer не через `players.front()`, а выбором
второй кнопки класса. Имя вводится физическими клавишами. Герой появляется
в настоящем Town; выполняются мышиная ходьба, открытие инвентаря, снятие
Rusty Blade, возврат той же вещи, resize, Save, Resume и Save & Quit.
Следующий процесс через Continue проверяет 15 полей семантики, включая
реальные экземпляры и слоты, позицию, HP/mana/gold и характеристики.

Далее первый сценарий полностью повторяется в другом пустом save store,
выбираются ещё два настоящих класса в отдельных процессах. Реальные
стартовые вещи: Rusty Blade (SPEED 100), Moldy Staff (110), Loose Shortbow
(120). Кости и видимый вклад каждой модели проверены. Последние два процесса
проходят Town → Main:1 → Town через настоящие Unit Trigger и затем ещё раз
загружают сохранение. Всего 41 верхнеуровневое проверочное утверждение
оркестратора, помимо проверок внутри общего runtime и остальных тестов.

Это не новый сквозной бой всеми тремя классами: стрельба из лука остаётся
неподдержанной. Основная смена экипировки — снять/вернуть стартовый экземпляр;
боевой loot/equip на реальных ресурсах проверяется отдельными прежними
pak-only тестами, не автоматически всем новым renderer-сценарием.

Численные данные одной контрольной сцены:

| Состояние | Фактическое значение |
|---|---|
| Destroyer, исходный Town | position примерно (24.44, 0, 88.7), HP 300, mana 20 |
| Видимый вклад героя/оружия | 629 пикселей при 640×360 |
| Урон с Rusty Blade | 10–20 |
| Без оружия | 11–22, используется innate-ветка |
| Возврат той же вещи | тот же экземпляр, урон снова 10–20 |
| Классы | три различных GUID, со своими реальными моделями/оружием |
| Контроль после перехода | Main:1, затем Town:0 и отдельный Continue |

Не подбирался урон «чтобы оружие выглядело лучше»: это наблюдаемые текущие
расчёты. Их полная исходная fidelity не выводится из успеха меню/сохранения.

## 3. Ошибка, которую нашёл стенд

Сценарий впервые вернулся с Main:1 в Main:1 вместо Town. Loader отбрасывал
`PARENT_DUNGEON=Town` из `MAIN.DAT.ADM`, а нулевой depth затем ограничивался
до первого подземного этажа.

Добавлено сохранение parent и узкое разрешение отрицательного relative
перехода с первого не-Town этажа. Не затронуты explicit destination,
ненулевой absolute, waypoint и специальный -99. Исходный запрос сохраняется.
Нативный тест покрывает ограничения, а настоящий сценарий подтвердил
Town → Main:1 → Town без вызова resolver напрямую из теста.

Статус **resource-derived/inferred**, не «побитово доказано всё»:
`CGameClient::performWarp @0x58d110` в Ghidra показывает отрицательную
first-floor ветвь и dungeon+0x80. Но точная loader-привязка +0x80 к
PARENT_DUNGEON требует focused ASM. Подробно:
`research/parent-dungeon-boundary.md`. Ни геометрия Town, ни координаты
маркеров не подправлялись для прохождения сценария.

## 4. Ресурсный каталог

Каталог построен через production decoders. Получено 30 189 узлов и 44 528
отношений, включая виртуальные UNIT/material/piece. 23 972 узла имеют
поддержанную parser capability, 6 065 явно unsupported и 152 unresolved
references. Все реально выполненные декодеры на исходном pak отработали без
отказа; это не означает поддержку всех перечисленных форматов/семантик.

152 записи **не являются доказательством порчи игры**: сюда входят неразрешённые
текущим resolver старые authoring paths и иные зависимости. Unknown semantics
не называются corrupt. Отдельная авторская негативная фикстура проверяет
четыре различимых состояния: валидный PNG, искусственная CRC-порча другого
PNG, неизвестное расширение и отсутствующая текстура. Оригинальный архив
при этом не изменяется. Поддержанный material parser не равен поддержке
каждого runtime pass/effect/timeline.

## 5. Проверки и статусы

Исходные 28 portable тестов прошли до изменения. Текущий обычный Debug:

| Группа | Итог |
|---|---|
| core | 33/33 PASSED |
| assets | 28/28 PASSED на настоящем pak |
| render | 2/2 PASSED, настоящий Mesa/EGL |
| reference | NOT RUN: нет ELF; отдельный запрошенный вызов подтвердил nonzero |
| desktop | NOT RUN: нет реализованного compositor/input harness и SDK |

Это 62 уникальных теста: UI-тест имеет обе метки core/render и в групповом
драйвере выполняется дважды. При обычной конфигурации не изменялись численные
или визуальные допуски. Один ранний параллельный прогон core попал в
30-секундный предел read_only_extractors при одновременной компиляции;
последующий групповой прогон прошёл с прежним пределом.

Ограниченное сравнение скорости: **12 395 побитовых float32 совпадений**,
из них три дополнительных пары GUID/SPEED взяты из настоящих сцен. Исполнялись
два прежних неизменённых, SHA-проверяемых ASM span, не целый ELF. Нулевые
эффекты и численные constants — явно заданные fixture inputs; полной
трассы атаки/HIT/эффектов здесь нет.

Инструментированная сборка ASan/UBSan успешно выполнила **все 62 уникальных
тестовых случая с явным повтором каталога**. Это не один исходно зелёный
вызов CTest: общий прогон дал 61/62, потому что у каталога оставался вложенный
240-секундный subprocess limit. После согласования внешнего и вложенного
лимита тот же каталог на том же pak прошёл отдельно. Оба исходных XML/log
и история повтора сохранены в `sanitized-aggregate.json`.

Для ASan явно задан `TORCHLIGHT_TEST_TIMEOUT_SCALE=4`; Debug использовал 1.
Не изменены сцены, seed/dt, число уровней, проверочные утверждения, численные
или пиксельные допуски. Например, неизменённый тест 192 генерируемых уровней
прошёл под ASan за 275,53 секунды, каталог — за 379,76. Эти времена описывают
конкретный инструментированный стенд, не FPS игры или целевой GPU.

Все семь реальных application процессов прошли и под ASan/UBSan, с теми же
41 утверждением и точным повтором кадров. На выполненных успешных проверках
нет диагностик AddressSanitizer/UBSan. Leak detection включён для нативных
CTest, отключён у Python/Mesa host и его детей из-за runtime global allocations;
проверка адресов/undefined behavior остаётся включённой. Промежуточная
несогласованность RGB/RGBA diagnostic dump устранена: теперь дамп соответствует
трем компонентам фактических uniforms, без изменения самого shader-расчёта.

Карта coverage обновлена до 17 027 строк (17 023 адреса и четыре port-native
подсистемы). Ни один original адрес не повышен до closed только по успеху
ресурсных/регрессионных проверок. `--verification-report` позволяет машинно
сопоставить пять групп со статическим reviewed coverage без изменения статуса.

Патч применён к чистой распаковке входного large-6; независимая свежая сборка
этой копии прошла **33/33 core-теста**. Она не использовала готовые object files
основной сборки. Полный pak/render прогон относится к основной проверенной
копии, а не повторно к этой чистой сборке.

Финальная доставка проверена отдельно: **560 файлов** после применения
окончательного патча совпадают побайтово с подготовленным проектом,
**559 записей CHECKSUMS.sha256** валидны. Различия между собранной чистой
копией и финальной — только завершённый отчёт, описание sanitizer budget и
их manifest-хеши. Исходный pak повторно проверен по SHA-256, не изменён и не
включён в выдачу. В отдельных evidence сохранены успешные результаты и
история явного sanitizer-повтора; там нет ELF, библиотек или файлов шрифтов.

## 6. Что не выполнено

Полный Wayland executable после извлечения не собран и не запущен. Общий
application и renderer реально скомпилированы/связаны/исполнены, но это не
заменяет adapter ABI/callbacks/focus/configure/close. Автоматический тестовый
compositor и доставка ОС-ввода пока именно **не реализованы**, а не скрыто
прошли в headless EGL. `--desktop` остаётся NOT RUN даже с pak.

Оригинальные process traces для атаки, warp и UI ещё не сняты; оригинальная
OGRE-библиотека/ELF не предоставлены. Старые limited exported spans не
превращаются из-за этого в полную original reference группу. Не проверены
произвольные драйверы/GPU/Android и производительность целевого телефона.
Нет новых ranged/skills/NPC services/quests/pet/gold/timeline реализаций.
Известная thin-wall проблема NavigationGrid не исправлена этим стендом.

## Применение и команды

В полном ZIP патч уже применён. Pak остаётся внешним read-only входом:

```bash
bash tools/check.sh --core --assets "/каталог/с/pak.zip" --render --jobs 2 \
  --report build/verification.json
python3 tools/coverage_map.py --check --verification-report build/verification.json
```

`--assets` принимает **каталог**, не путь самого файла. Каталог может быть
корнем рабочей папки проекта. При передаче чистого входного large-6:

```bash
git apply --check OpenTorchlight-automatic-verification.patch
git apply OpenTorchlight-automatic-verification.patch
```

Повторно применять патч к готовому ZIP не требуется. Полный `--all` с pak/ELF
должен честно сообщать недоступный desktop, пока harness не реализован.
Команды низкого уровня, происхождение дампов и следующие границы находятся
в `research/automatic-verification.md` и `NEXT_CHECKS.md`.
