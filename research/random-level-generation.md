# Универсальная генерация этажей

## Ответ на вопрос о ручной пересборке

Каждый этаж не хранится как отдельная готовая трёхмерная сцена. Основная
кампания ссылается на 25 уникальных ruleset для 35 этажей. Эти правила задают
типы chunks, размеры сетки, допустимое число комнат, входы, выходы и наборы
готовых `.layout`-фрагментов. Поэтому нужен один генератор, который собирает
этаж из исходных фрагментов. Город проходит тот же путь загрузки ресурсов, но
его ruleset содержит один заранее размещённый chunk.

Новый загрузчик уже читает для основной кампании:

- 22 ссылки на случайные и 13 ссылок на фиксированные ruleset;
- 306 описаний `CHUNKTYPE` и 419 точек `EXIT`;
- 257 уникальных `.layout`-фрагментов;
- `MINCHUNKS`, `MAXCHUNKS`, `ENTRANCE_CHUNK`, `EXIT_CHUNK`, `MUST_PLACE`,
  `FOLDER` и `INCLUSIVE_FILES`.

## Алгоритм оригинала

В исследуемом бинарнике генерация сосредоточена в
`CLevelTemplateData::createRandomLayout(int)` по адресу `0x973370`. Рядом
находятся отдельные проверки:

- `intersectsChunks` (`0x972980`) отклоняет пересечение границ chunks;
- `exitsMatch` (`0x9725d0`) проверяет, что соприкасающиеся края совместимы;
- `matchExits` (`0x972e90`) записывает пары соединённых выходов;
- `resetOdds` (`0x971410`) восстанавливает веса вариантов;
- `getRandomChunk` и `getRandomLayout` выбирают вариант через `CRandomizer`.

Из машинного кода восстановлена следующая последовательность:

1. При ненулевом аргументе устанавливается seed.
2. Создаётся начальный `CChunkInstance` в координатах `(0, 0, 0)` из отдельной
   группы входных chunks.
3. Целевое число chunks выбирается между `MINCHUNKS` и `MAXCHUNKS`.
4. Новый тип и свободный выход выбираются по весам. Положение вычисляется так,
   чтобы его выход совпал с выходом уже размещённого chunk.
5. Кандидат принимается только после `intersectsChunks` и `exitsMatch`, затем
   `matchExits` помечает использованные выходы с обеих сторон.
6. При `REQUIRESEXIT` к подходящему свободному выходу добавляется тип,
   помеченный `EXIT_CHUNK`.
7. Счётчик появлений отключает варианты, достигшие `MAX_APPEARANCE`.
8. Для каждого принятого instance выбирается конкретный `.layout` по весам,
   и готовая комбинация добавляется в каталог случайных раскладок.

Оригинал ограничивает внутренние попытки размещения 1000 итерациями. Он также
готовит множество вариантов раскладки, из которого позже работает
`getRandomLayout`.

Структура `CChunkInstance` в этой сборке содержит индекс типа по смещению
`0x10`, позицию XYZ по `0x20/0x24/0x28` и список индексов уже соединённых
выходов по `0x30`. У типа chunk ширина и высота находятся по `0x14/0x18`, а
массив трёхкомпонентных выходов начинается по `0x48`. Эти наблюдения относятся
к проверяемой сборке с SHA-256
`91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.

Полные листинги сохранены в:

- `research/disassembly/CLevelTemplateData-createRandomLayout.txt`;
- `research/disassembly/CLevelTemplateData-chunk-validation.txt`;
- `research/disassembly/CLevelTemplateData-matchExits.txt`;
- `research/disassembly/CLevelTemplateData-random-choice.txt`.

## Перенесённый общий путь

В C++17 теперь есть явные структуры размещённого chunk, его позиции и взаимных
пар выходов. Общий генератор:

- начинает с допустимого входного типа;
- выбирает число промежуточных chunks из диапазона правил;
- соединяет локальные точки выходов в мировых координатах;
- отбрасывает пересечение занятой площади и делает ограниченный поиск с
  возвратом из тупиков;
- соблюдает `MAX_APPEARANCE`, `MUST_PLACE` и `REQUIRESEXIT`;
- после построения графа выбирает исходный `.layout` каждого chunk по его
  весу.

Тест строит 192 уровня по 16 seed для всех 12 уникальных случайных ruleset
основной кампании. Получено 952 размещённых chunk; повтор одного seed проверен
на полное совпадение типов, layout-файлов, позиций и пар выходов. Отдельное
сравнение с машинным кодом оригинала подтверждает 24 000 результатов и
состояний целочисленного и вещественного PRNG, 20 000 результатов взвешенного
выбора и 20 004 результата `intersectsChunks`.

Для `intersectsChunks` перенесены исходные отступы `-0.1`, вертикальный
диапазон `position.y ± 1000` и фактическое использование ширины chunk для
обеих горизонтальных осей. Последнее похоже на особенность или ошибку
оригинала, но сохранено ради совместимости.

Выбранные layout-фрагменты уже объединяются в общую геометрию. Контрольная
генерация первого этажа шахт с seed 42 содержит 3 chunk. Вместе с Алхимиком,
поставленным в найденный `PlayerStart`, сцена содержит 2 866 экземпляров,
171 159 треугольников и 46 текстур и выводится тем же GLES-рендерером, что и
город.

Оставшаяся граница — добиться полного совпадения порядка вызовов генератора и
всех пограничных проверок `exitsMatch` с оригиналом. Сам взвешенный выбор уже
совпадает с исходной `CRandomizer`. Текущая реализация даёт корректную
воспроизводимую связную сцену, но конкретная раскладка для одного seed пока не
заявлена побитово идентичной исходной игре.
