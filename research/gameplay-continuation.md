# Продолжение игры после смерти, витальные параметры и границы боя

База: `OpenTorchlight-gpt-pro-large-4.zip`, SHA-256
`8ccb7a4cb52031c0e56c2b426cda097990b0c97fc9c9255a151938670728b7c0`.
Исследуемая версия ELF по входным материалам:
`91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.
Сам ELF и игровые ресурсы в этом проходе отсутствовали. JSON констант получен
интегратором из закреплённого ELF; новые ASM-фрагменты извлечены из ранее
предоставленного текстового дампа. Это разные источники, не повторный запуск
оригинала. Происхождение экспортов: [gameplay-export-provenance.md](gameplay-export-provenance.md).

## 1. Подтверждённые входы обычного боя

`original-code` + входное свидетельство `original-combat-inputs.json`:

| Вход | VA | Подключение |
|---|---|---|
| Innate ATTACK_RANGE по умолчанию 0.375 | 0xfce4f8 | `load_innate_attack`, только при отсутствии поля |
| Innate STRIKE_RANGE по умолчанию 0.5 | 0xfa4810 | То же; явно повреждённое значение не заменяется default |
| Вертикальный melee cutoff 2.5 | 0xfce4c4 | `within_character_attack_reach` |
| Минимальная скорость 0.2 | 0xfa86e8 | До дополнительного AI multiplier |
| Множитель hasAIFlag(1): 1.5 | 0xfce498 | После minimum clamp; фиксируется в начале действия |
| Единица и 100 | 0xfa47fc / 0xfa483c | Арифметика скорости |
| Каталог `media/EffectsList.dat` | 0xff82c8 | Ровно compiled counterpart `.dat.adm`, нормализованный поиск |

`CCharacter::inAttackRange @0x826140` различает наличие ranged в руках и
вертикальную проверку. Для подхода учитываются обе руки; для исполненного
удара — выбранное описание. Допустимая граница `abs(dy) <= 2.5`. Отдельные
горизонтальные attack/strike reach и collision radii сохранены. Не утверждается
побитовое совпадение `std::hypot` с каждой промежуточной инструкцией исходного
sqrt; вертикальный предикат и конечные состояния проверяются отдельно.

`CCharacter::attack @0x82b550`, участок около `0x82b9e1`, применяет 1.5 **после**
нижнего ограничения. Добавлен явно оценённый вход `AttackCharacterValues::ai_flag_one`.
Он по умолчанию false. Флаг не выставляется всем монстрам и не выводится из имени
юнита. Менеджер флагов, их источники/сроки/снятие не восстановлены. Реализован
потребитель доказанного состояния, а не весь `CAIFlagManager`.

Смена входов после запуска не переписывает текущую скорость. Ненулевой AI
cooldown остаётся самостоятельным параллельным таймером. MISS расходует HIT,
повторные/чужие/старые события по-прежнему отклоняются.

Каталог больше не выбирается по похожей структуре другого `*EFFECT*.DAT.ADM`.
Отсутствующий точный файл означает неизвестную таблицу; повреждённый точный файл
даёт диагностируемый отказ. Это не повод брать файл-двойник из ZIP. Авторские
фикстуры содержат такой двойник с заведомо другими ordinal.

## 2. Почему resetLevel — не воскресить игрока

`original-code`:

```
CDieMenu::onClick @0xb05ec0
  → параметры выбранного способа смерти/восстановления
CDieMenu::update @0xb06110
  → списание штрафов, передача режима, состояние GameClient = 5
CGameClient::updateIngame
  → для обычного режима CLevel::restartLevel @0x936300
  → virtual levelResetting существующих персонажей
CPlayer::levelResetting @0x8f5810
  → CCharacter::levelResetting
  → restore HP / mana
  → mode 1: уровень.position +0x140 и facing +0x164
  → dropToGround и оставшиеся действия
```

`CPlayer::resetLevel @0x8e3f90` меняет **уровень развития персонажа** на 1,
сбрасывает XP и пересчитывает максимумы. Он не выбран для восстановления после
смерти. `CLevel::restartLevel` не выгружает и не генерирует уровень заново.

В onClick ветвь `ELayoutFunction=0x0f` формирует mode=1, gold_loss=gold/10,
XP loss=0, fame loss=0 (`0xb06060..0xb060a8`). Восстановлен только этот вариант:
возвращение к входному якорю с сохранением текущего мира. Режимы восстановления
на месте и в городе, pet, XP/fame progression, удаление временных afflictions и
точная `dropToGround`-физика не реализованы.

`PlayerSession::recover_at_entry` проверяет смерть, hardcore и конечность якоря
до мутации. Сохраняет инвентарь, рассчитанные предметы/слоты, текущее состояние
мира и независимые AI-таймеры. Сбрасывает боевые исполнения/цели/пути, восстанавливает
существующие HP/mana до их максимумов. Возврат в живой сессии повторно не списывает
золото и не телепортирует. `hardcore` — явная политика создания сессии; загрузчик
оригинального сохранения/меню выбора этого режима ещё отсутствует.

`EnemyController::level_resetting` — ограниченная адаптация stop-current-action и
очистки target/path, а не перенос всего виртуального restart для любого класса.
Монстры не оживают и не лечатся. Клипы/resolver, RNG и счётчики поколений событий
не пересоздаются; старый HIT не становится действительным при следующей атаке.

## 3. Отдельный якорь этажа

`CLevel::loadRoomLayout @0x95f150` выбирает Property Node и сохраняет его в самом
уровне; `placePlayerAtWarpToDungeonFloor @0x953000` затем может поставить игрока
к обратному Warper. Это **не одно и то же место**.

Выделен `find_same_dungeon_entry_anchor`. Обычная загрузка сохраняет его отдельно
от точки входа через Warper; при восстановлении используется именно якорь.
Существующий приоритет Warper при переходе не меняется. Тест включает оба
маркера в разных координатах.

`prototype`: начальный запуск без обычного запроса перехода и неподдержанные
межданжевые/waypoint-входы пока сохраняют старый player_start как резервный
recovery anchor. Лог `original_entry_anchor=0` прямо отличает этот путь. Поворот
берётся из маркера; поверхность — существующая navigation-модель, не доказанная
копия исходного dropToGround.

## 4. Gold и mana — ограниченные, но связанные состояния

`CCharacter::giveGold @0x811a70`: проверена own-player числовая ветвь, где нет
master/pet перенаправления. Прибавление ограничено `[0, INT32_MAX]`; нет wrap.
Существующий UNIT `GOLD` загружается с default 0. Штраф режима 1 есть целочисленное
`gold/10` для неотрицательного gold. Получение золота из мирового CItemGold пока
не подключено: номинал предмета нельзя вывести из его GUID или имени.

`CPlayer::unitInit` выбирает `MANA_GRAPH`, default `MANA_PLAYER_DESTROYER`;
`calculateMaxMana @0x8e4d60` вычисляет graph(level), затем ceil. Переносимый
загрузчик сейчас использует **существующий уровень 1**. При отсутствии графа mana
остаётся `nullopt`, а не становится произвольным 100. Повреждённый граф/overflow
отклоняются. Развитие уровня и изменение growth-поля отдельно не подключены.

`CCharacter::maxMana @0x813a10`:

```
base = max(1, trunc(float(raw_base) + growth))
maximum = base + ceil(float(base) * effect(0x13) / 100) + ceil(effect(4))
```

Округления раздельные, промежуточная арифметика float32. Не переносить `ceil`
на всю сумму. `evaluated_maximum_mana` проверяет границы до преобразования int32;
невалидные и выходящие за поддержанный числовой домен данные — явный portable
отказ, не обещание повторить undefined/overflow поведение оригинала.

Активная экипировка даёт поддержанные постоянные эффекты mana из обеих имеющихся
категорий: оружие и броня. Смена вещей не восполняет потраченную mana; уменьшение
максимума только обрезает текущую. Восстановление после смерти восполняет её.
`spend_mana` проверяет alive/known/finite/nonnegative/остаток; реальный skill consumer,
регенерация и расходники ещё не подключены.

HUD отображает HP, известную MANA или `MANA ?`, GOLD. Это текущая сессия, без disk save.

## 5. Транзакция экипировки

`prototype` defensive implementation, не извлечение отдельной original-функции:
слоты и расчёты готовятся на копии неактивной сессии и коммитятся no-throw swap.
Если вычисление параметров отвергло предмет, живые слоты, armor, damage, mana и
содержимое сумки не оказываются из разных состояний. Во время действия смена
по-прежнему запрещена. RNG при подготовке не продвигается, предмет не перебрасывается.

Desktop сначала проверяет изменение на кандидатной сессии, затем подготавливает
доступные renderer-ресурсы и только потом заменяет live session. Так отказ параметров
не создаёт кэш, указывающий на чужую модель. Это защита от проверенных ошибок
данных; не обещание восстановления после аварии GPU/исчерпания памяти.

## 6. Смерть → loot → callback

`original-code`: `CCharacter::die @0x838ed0` выполняет treasure до
`broadcastKilled`. Старый runtime уведомлял логику раньше отложенного создания
предметов. Теперь `record_death` сохраняет отдельный snapshot позиции, таблицы,
владельца и drops_loot, без раннего логического события.

В безопасной фазе `resolve_death_loot(logic)` создаёт предметы **одной смерти**,
затем сообщает её спавнеру. Затем берёт следующую. No-loot death тоже получает
уведомление. Принудительный Hide/Destroy не превращён в death loot. Повторное
kill/drain не дублирует вещи и события. Добыча по-прежнему не принадлежит спавнеру
умершего. Список дочерних drop не удаляется его последующим Destroy.

API: `kill/apply_damage` ставят death в очередь; после освобождения указателей
на `entities()` обязательно вызвать `resolve_death_loot(logic)` и только затем
исполнять запрошенные скриптом создания/уничтожения. Вызовы в desktop и старых
тестах обновлены. Сам `LogicRuntime&` в kill оставлен для совместимости сигнатуры,
но больше не означает синхронную рассылку.

`prototype` граница: это восстановление **локального порядка на одну смерть**,
не исходной глобальной re-entrancy всех персонажей. Несколько смертей уже могут
быть отмечены до drain. Повреждённый ресурс во время генерации остаётся fatal
ошибкой данной фазы: частично созданная смерть не перебрасывается повторно,
следующие записи остаются в deque. Rollback/безопасное продолжение этого случая
не обещаются. Layout-ключ `setUnitsGiveLoot` пока неизвестен; программный флаг есть.

## 7. Проверки и ограничения native adapters

`gameplay_continuation`: 390 утверждений, авторский pak; default-атака, точный
catalog, вертикальная граница/MISS, 1.5 после clamp, mana-граф и equipment,
64 восстановления одного мира, несколько активных врагов, устаревшие HIT,
инвентарь/оружие/corpse/HP, invalid/hardcore/alive ветви.
`death_finalization`: 62 утверждения; drop before callback, no-loot, batch,
повтор, source position snapshot, реальные авторские mesh/UNIT/spawn graph.

`player_vitals_export_comparison`: 2064 gold + 2320 mana + 2113 fee = 6497
совпадений integer-результата с неизменёнными ограниченными ASM-spans. Изолятор
сохраняет внутренние переходы и адресные смещения. Внешнее окружение синтетическое:
no-op journal, два фиксированных effect-return, host libm.ceilf, ABI-обёртка и
выход menu span. Числовой делитель подтверждён входным JSON. Не исполняются весь
CPlayer, GUI, GameClient или весь ELF. При `--original` отдельно проверяются SHA,
байты span и исходный делитель; этот режим здесь не запускался.

В среде внешнего автора полный desktop не собирался/не запускался: не было Wayland/EGL/GLES development-зависимостей,
apt DNS недоступен. Проверка gameplay syntax — лишь компиляция игровой части
с декларациями оконных типов. Входные 52/52 — исторический результат интегратора,
не результат его запуска нового кода на ресурсах. GCC 14.2.0 был проверен, GCC 16 там не установлен.

## 8. Почему ranged и мировой gold не сделаны заглушками

`performAttack @0x847280` сначала пробует weapon skill / `fireMissiles`, а отдельная
ordinary-ветка содержит rayCollision, rollAttack и ArrowTrail. Нельзя выбрать
«все ranged = missile» или «все ranged = моментальный melee».
`fireMissiles @0x87f120` использует equipment+0x400, hand tag, WEAPON_SCALE, смещение;
полет/сфера/ignore-hit-list в `missile.c` требуют согласования ресурса и collision.
Имеющиеся ranged-описания всё ещё явно unavailable, а не стреляют сквозь стены.

`CItemGold::unitInit @0x8ca940` использует два процентных ключа, четыре графа
сложности, floor context и ceil. Wide-строки отсутствуют в имеющемся текстовом
ASM; название ключа или ценность по имени предмета не угадываются.

Следующий read-only дамп:

```
python3 tools/dump_original_gameplay_inputs.py --original "$GAME_DIR/Torchlight.bin.x86_64" --output gameplay-inputs.json
```

Семь bounded wide-строк: 0xfd1e98, 0xfd1ec0, 0xfd1f48, 0xfd1f80, 0xfd1f20,
0xfd1ee8, 0xfc2078. Два f32-операнда: 0xfa86d0, 0xfc676c. Смысл названий выходных
полей привязан к use-site, не к догадке. Инструмент не запускает ELF и проверяет
точный SHA. Защита от записи поверх original проверена также для symlink/hardlink.
Синтетические тесты отрицательных входов не подменяют реальный дамп.

## Локальная интеграция после внешнего прохода

`original-code`: extractor выполнен на ELF SHA-256
`91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.
Результат находится в `research/original-gameplay-inputs.json`: `MINVALUE`,
`MAXVALUE`, четыре `GOLDDROP`-графа, строка `PROPERTIES` и operands 5.0/0.8 с
точными VA и little-endian bytes.

Полный GCC 16 desktop собран; `tools/check.sh` прошёл 59/59 с внешними ELF и
`pak.zip`. Native vitals comparison подтвердил 6497 случаев, original combat,
AI, item cycle и рендеры прошли. Ограниченный оконный запуск загрузил Main:1 и
отрисовал три кадра. Ручной death/R сценарий остаётся непроверенным.

После получения: проследить producer equipment+0x400 и projectile descriptor
`0x602dc0`; сформировать авторский снаряд с подтверждёнными полями, затем sweep по
реальной collision геометрии, HIT/retire и сквозной ranged-контроллер. Независимая
ветка — номинал CItemGold и запрет loot по точному имени layout-свойства.
