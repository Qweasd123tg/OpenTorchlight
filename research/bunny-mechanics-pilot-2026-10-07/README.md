# Пилот: убрать механическую работу из LLM-реверса

База — `ae84cf6`, свежий `main` с PR №6. Ветка —
`bunny/character-inventory-pilot`. Цель эксперимента — посмотреть реальные
действия агентов и стоимость оснастки, а не раздать модели все функции игры.
MerchantMenu/StashMenu, их createMenus-проверки, GameUI.h, SceneNodeObject.h,
SubMenu.h и `tools/decomp` не изменялись. WIP-архив не применялся.

## Игровой срез

Space Bunny восстановил 8 функций `character.cpp` и 4 обработчика вращения
`inventorymenu.cpp`. Родитель повторил objdiff на конечных исходниках:
12 сильных игровых определений имеют MATCH, неизвестных ссылок нет.
Поля Character названы внутри прежних padding-областей; размер остался 0x720.
В InventoryMenu названы только используемые байты 0x9162/0x9163, остальные
области остались padding. RTTI и проверка компилятора сохраняют вторичную базу
iInventoryListener по +0x10. Размер 0x95d0 подтверждён аргументом allocBytes
по 0xaa311d в оригинальном CGameUI::create перед вызовом конструктора по
0xaa315a. Непроверенные виртуальные возвращаемые типы нового
частичного заголовка не экспортируются как доверенные прототипы.

Это неполные TU, не самостоятельно собирающаяся игра. DIFF автоматически
сгенерированных TU-инициализаторов не принимается как восстановленный код;
гибрид такие инициализаторы не подменяет.

Полная проверка конечного среза прошла: 104 headless-теста, 0 ошибок;
906 MATCH и 2 функции по исполненному сравнению, всего 908 (59553 байта).
Все прежние принятые адреса сохранены, полные object digest всех существовавших
TU не изменились. Базовый неизменённый main также прошёл 104 headless-теста,
0 ошибок: 894 MATCH и 2 функции по исполненному
сравнению, всего 896. Первый прогон закончился таймаутом 540 секунд;
успешный повтор использовал `OTL_SELFTEST_TIMEOUT=1800`.
Проверки инструментов: 180 тестов прошли, один Java-тест первоначально
пропущен; с закреплённым JDK 21 он отдельно прошёл — проверены все 181.

## Что действительно делали агенты

Счётчики взяты из локальных журналов OpenCode, не из финальных отчётов модели.
Повторные запросы и первоначальная TLS-ошибка входят в пилот Inventory;
последующее отдельное исследование семейств в его счётчики не входит.

| Срез | Функций MATCH | Шагов модели | Tool calls | Shell calls | Shell-команд с objdiff |
|---|---:|---:|---:|---:|---:|
| Character, 4 запроса | 8 | 71 | 75 | 59 | 17 |
| Inventory, 2 запроса | 4 | 69 | 71 | 50 | 9 |

Character трижды завершался без итогового текста. Агент изучал исходники
самих objdiff/toolchain, писал собственную пробу компилятора, вручную разбирал
JSON и переключал живой заголовок на pristine-версию для сравнения объектов.
Inventory вручную считал padding; первая арифметическая ошибка дала DIFF.
Он также восстанавливал неиспользуемые поля и писал длинные свидетельства,
хотя четыре выбранные функции меняют всего два байта. Эти операции не надо
повторять в каждом новом модельном задании.

17 запусков objdiff не означают 17 backend-компиляций: действует кэш.
Provider usage содержит отдельно uncached input и cache reads; cache reads
не являются объёмом уникального текста. Сумма длительностей shell-вызовов —
wall time, не измерение CPU; параллельные вызовы могут перекрываться.
Сырые разговоры и выводы игры остаются в ignored `build-decomp`, не в git.

## Два локальных прототипа

В ignored `build-decomp` подготовлены диагностические прототипы; действующие
инструменты не изменены. Они ничего не публикуют и не заменяют приёмку.

**Краткая проверка.** Один вызов сравнивает кандидат, сохраняет полный JSON,
а агенту возвращает выбранные сильные игровые определения и ошибки ссылок.
На тех же 12 функциях обычный текстовый лог занимал 28833 байта, краткие
отчёты — 1393 + 1085. Алгоритм objdiff и полная диагностика не изменились.
Шесть отрицательных/граничных тестов проверили отсутствие цели, weak-only
MATCH, чужую цель, неизвестную ссылку и конфликтующие определения.

**Два точных шаблона для известных полей.** Из инструкций и уже имеющихся
типизированных полей получен изолированный полный кандидат Character:
HPFloat, manaFloat и три giveUnused*Points. Все пять новых определений MATCH,
прежние восемь сохранили MATCH. Это дополнительные диагностические кандидаты,
не пять новых опубликованных функций. Новые поля/типы не угадывались;
неподдерживаемые формы отвергаются. Возврат для этих форм выбран по передаче
известного float-поля либо отсутствию вычисляемого результата у прибавления.
Оригинальный исходный тип возвращаемого значения не выводится из mangled-имени.

| Реализация одного задания | Wall time | Peak RSS |
|---|---:|---:|
| JSON всех типов + pickle всех инструкций | 17,59 с | 840572 KiB (821 MiB) |
| Пакет нужных полей + целевой ASM | 8,44 с | 192216 KiB (188 MiB) |

У обоих кандидатов одинаковый полный object digest:
`d230d3e089aa6cc580b7356ec9f6e9fa9b5e262bdb82dab95787ca71b1bffc62`.
Исходный types.json занимает 35875236 байт, пакет пяти полей — 971 байт.
Его подготовка выполнялась отдельно и не входит во время второго задания.
Это один последовательный замер на рабочей машине, с возможным влиянием
прогрева кэшей и других процессов. Общее ускорение decomp и производительность
десятков агентов не измерялись.

## Следующий полезный шаг

1. Давать агенту краткий пакет выбранных функций: ASM, нужные объявления,
   поля, вызывающие и явные неизвестные ABI, а не весь пакет большого класса.
2. Выполнять расчёт padding, compile-time/DWARF-проверки и разбор результатов
   одним инструментом. Не переключать общие живые заголовки: использовать
   уже существующий publication.Stage.
3. Собирать неизменяемые входы один раз для снимка. Ограничить число местных
   compiler/checker workers независимо от количества модельных сессий.
   Ghidra и полный headless-прогон не должны запускаться каждым агентом.
4. Использовать существующие генераторы и кэши. Не вводить новый процесс
   контрактов, не возвращаться к p-code и не писать универсальный синтезатор
   по двум удачным формам. Неоднозначный ABI остаётся задачей исследования.

Перед переносом прототипов в общие инструменты нужен отдельный проверенный
коммит игрового пилота и сверка с исполнителем на другом ПК.
