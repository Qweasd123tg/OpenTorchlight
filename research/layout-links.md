# Вложенные layout и узлы переходов

## Зачем их нужно раскрывать

Объект `Layout Link` хранит `LAYOUT FILE` со ссылкой на другой
скомпилированный `.LAYOUT.adm`. Комнаты используют этот механизм для
фонарей, руды, частиц, точек входа и выхода, а также вложенных
логических графов. Без раскрытия внешняя комната загружается, но
переход на следующий этаж в runtime отсутствует.

`expand_layout_links` добавляет вложенные объекты в общий manifest. Каждая
копия получает свои ID; ссылки родителей и ID объектов в графах
переназначаются. Корневые объекты наследуют трансформацию самой
ссылки. Вложенные ссылки раскрываются до глубины 16, чтобы повреждённый
цикл не мог бесконечно раздувать уровень.

## Семантика Warper

В Linux x86-64 конструктор `CWarper` по адресу `0x9b1050` задаёт
`levelDelta=1`, `levelDepth=0`, `enabled=true`, `waypoint=false`. `CWarper::activate`
по адресу `0x9b8e60` передаёт эти поля в `CGameClient::warpLevels`.
Поэтому отсутствующий `LEVEL DELTA` у стандартного `EXIT_NODE` означает
переход на следующий этаж, а не нулевое смещение. `ENTRANCE_NODE`
явно хранит `LEVEL DELTA=-1`.

## Проверка

Первый этаж шахт с seed 42 состоит из 3 009 внешних объектов. После
раскрытия 85 ссылок manifest содержит 3 541 объект, включая два
`Warper`. Тест проверяет расширение manifest, конечные мировые координаты,
загрузку `LogicRuntime` и направления `-1/+1` для входа и выхода.
