# Проверка новых стыков инструментов, 7 октября 2026

Вход — `OpenTorchlight_revision_review.zip`, SHA-256
`5b8a967bcc04618f9363260b25ae24712f2ebd8dbe2d6f5565dd43f26b9272e7`.
Все 114 записей манифеста проверены. [Карта импорта](ARCHIVE_IMPORT.json)
сохраняет происхождение; исходные отчёты и воспроизведения — в `external/`.
Результаты автора относятся к его среде. Временные Stage/cache деревья
сохранены во внешнем ZIP и ignored извлечении, не добавлены как исходник проекта.

В этой ветке исправлены:

- Таблицы переходов: доказанный индекс/диапазон, все записи и цели;
  неизвестность запрещает MATCH. Исправлено ошибочное игнорирование cs/data16
  инструкций как padding. Версия нормализатора поднята до 3.
- Sret-перегрузки: полная ELF family и точный прототип по адресу, включая cv
  и отсутствующие прототипы. Raw C не хранит цель конкретного вызова;
  неоднозначные вызовы остаются целиком без ABI-преобразования.
- Сохранение определений: сравнивается полный объект; одинаковая надпись
  о непроверенной LSDA не сохраняет доказательство. Общие заголовки проверяются
  по всем TU, ранее принятая функция обязана сохранить MATCH или свежий receipt.
- Нативный receipt: обе стороны вызывают конкретную функцию через invoke;
  loader проверяет original/replacement по таблице hooks. Полные сравнения,
  различия и неполнота считаются по исходам наблюдателя. Пустые тела, чужая
  функция, original против самого себя и аварии не дают приёмку.
- Candidate принимает новый DIFF при свежем выполненном сравнении конечной
  сборки. Receipt связан с полным объектом и входами. Первый ручной адаптер —
  Warper activate; остальные старые TL_ORIGINAL остаются навигацией/регрессиями.
- Очередь считает новые попытки отдельно от cached failures и достигает D/E
  после отказов A/B/C. Ключ candidate учитывает incremental и версию правил;
  транзитные ERROR не фиксируются как постоянный отказ.
- Публикация: журнал с резервными байтами, восстановление под exclusive lock,
  общий снимок src/include/tests/runtime/config, проверка живых объектов перед
  committed. __FILE__-зависимость с иным финальным объектом даёт rollback.
- Сохранённую попытку можно resume/rebase без генерации; конфликты запрещены,
  результат повторно проверяется. Candidate делает одну ограниченную повторную
  интеграцию при изменившейся базе.
- Общий кэш компилирует полный свежий preprocessed input по стабильному пути.
  Macros, compiler/libs/specs/flags, shadow headers остаются в идентичности;
  unsupported/debug/profile/PCH/assembler effects получают консервативный fallback.

Runner поддерживает имеющиеся descriptor/properties генераторы. Для конкретного
полного кандидата любого выбранного игрового TU есть:

```sh
python3 tools/decomp/no_llm_loop.py Equipment.cpp --provider candidate --input-dir build-decomp/candidates
```

Это проверка предоставленного исходника, не генератор всей игры. По умолчанию
публикации нет. Для DIFF нужен собственный полноценный тест; отчёты автора,
декларации и проценты близости его не заменяют.

Локальные микрозамеры: две одинаковые попытки Equipment.cpp — 4,450 с miss
и 0,187 с hit; assembly обоих путей и исходного uncached маршрута побайтно
совпала. Общий темп восстановления и расходы не измерены.

Аудит оригинального ELF: 126 косвенных переходов в 106 функциях;
прежняя граница не установлена в 51 случае, найден один усечённый prefix
у CJournalMenu::updateLayout (0xe3c460). Новый консервативный анализ доказывает
47 диапазонов. Это охват сравнения, не список испорченных игровых функций.

Ограничения: все старые ручные оснастки не мигрированы автоматически;
счётчики нельзя выдавать за фактически выполненные сравнения. Неизвестные
таблицы остаются DIFF. Power-loss устойчивость отдельно не проверялась;
воспроизведена и исправлена остановка процесса во время публикации.
Самостоятельная игра и UI этим ремонтом не проверяются.

Локальная проверка после ремонта: **164 теста инструментов PASS**, полный
`python3 tools/decomp/check.py` — **103 самотеста, 0 failed** в оригинальном
процессе. 894 строгих MATCH плюс выполненное сравнение CWarper::activate:
146 completed, 0 different, 0 incomplete; всего принято 895/5247 функций,
53036 исходных байт. Новые тела в decomp/src не добавлялись.

[validation.json](local-check/validation.json) сохраняет итог и отпечаток входов.
В `local-check/` также сохранены результаты таблиц before/after, EH и candidate,
контроль общего заголовка и замер кэша. [review.py](local-check/review.py)
повторяет дополнительные candidate/EH проверки в ignored каталоге. EH и sret
компилировались GCC 4.4.7 и исполнялись с системным linker/runtime; проверки
маршрутизации candidate явно моделируют compiler/Stage IO и не заменяют игровой
прогон. Полные штатные отрицательные проверки остаются в tools/decomp/test_*.py.
