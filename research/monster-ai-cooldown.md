# Отдельный AI cooldown обычной атаки монстра

> **Current combat-action patch:** ordinary player/enemy attacks now share
> description/clip/HIT execution; the old enemy `100 / ATTACKSPEED` gate is gone.
> Signed AI cooldown remains independent. See `ordinary-attack-action.md` and
> `../COMBAT_ACTION_RESULT_RU.md` for current code, test results and limitations.
> Earlier descriptions/test counts below are historical unless explicitly updated.


## Граница патча

Восстановлен **один ограничитель допуска следующей обычной атаки**: загрузка
`AI_ATTACKCOOLDOWN` из UNIT монстра и выбранного оружия, независимое хранение,
уменьшение и повторное взведение таймера AI. Это не восстановление всей
`CMonster::attackAI`, вражеских HIT, выбора двух рук, навыков или порядка фаз
`CGameClient::updateIngame`.

Изменения внесены поверх `OpenTorchlight-gpt-pro-6(1).zip`. Игровые ресурсы и
оригинальный ELF в пакет и репозиторий не входят; локальная проверка читает их
как внешние входы. Синтетические определения теста не являются
`resource-derived` и не используются как значения по умолчанию игры.

## Происхождение инструкций

Исследуемая версия: Linux x86-64 `Torchlight.bin.x86_64`, заявленный SHA-256:

`91b41ae9dfea30aab6bc14dbbfcceaee096d600f39635b8507f5a88b5d41724b`.

Точечные экспорты добавлены из **ранее предоставленного**
`OpenTorchlight-gpt-pro(2).zip`, файла
`original-analysis/full-intel-disassembly.asm`. Вычисленный SHA-256 этого
текстового дампа совпал с его `PACKAGE_FILE_SHA256SUMS.txt`:

`59d876125b21e8e1a3e6b0f2f242632966b705218907de1ed5172baebc30d196`.

Полный дамп и сам ELF в этот патч не включены. Хеш внешнего ELF пересчитан локально перед
чтением адресных bytes и совпал с зафиксированным SHA-256. Псевдокод соответствующих методов уже есть в текущем
`decompiled-core/monster.c`, символы — в `original-symbols.txt`.

## Прослеженная цепочка

| Шаг | Функция / адрес | Установленное действие |
|---|---|---|
| Значение монстра | `CMonster::unitInit @0x008e2ae0`; `0x8e2b06–0x8e2b21` | Float-геттер с нулевым default; результат в `monster+0x7ec`. |
| Значение оружия | `CEquipment::calculateCombatStats @0x00880950`; `0x880b62–0x880b91` | Такой же float-геттер с default 0; результат в `equipment+0x408`. |
| Выбор оружия | `CCharacter::selectAttack @0x00811bc0` | `inferred` — роль `character+0x498` как выбранного предмета прослежена по `decompiled-core/character.c:3043–3131`; сам load указателя в `0x8e00e6` подтверждён ASM. Полное правило выбора не переносилось. |
| Допуск | `CMonster::attackAI @0x008dfd80`; `0x8dfd9a–0x8dfda5` | Положительный `monster+0x7e8` исключает начало новой обычной атаки. Отдельно вызывается `performingAttack`, например в `0x8e0084`. |
| Взведение | `0x8e00dd–0x8e013d` | Только после успешного `CCharacter::attack`; сначала вклад выбранного предмета, затем UNIT. |
| Уменьшение | `CMonster::updateAI @0x008e3a40`; `0x8e3a5b–0x8e3a67` | Из signed timer вычитается входной `dt` до проверок think-time и ранних выходов. |

Геттеры, offsets, проверка допуска, порядок взведения и уменьшение имеют статус
`original-code` для сохранённых инструкций.

Оба геттера используют **один адрес строки `0x00fcf8a0`**, которую текущая
декомпиляция `CMonster::unitInit` восстанавливает как `AI_ATTACKCOOLDOWN`.
Это не `SPEED`: чтение `SPEED` у предмета начинается следующей отдельной веткой
в `0x880bbe`, с другой строкой (`0x00fae9d0`), целочисленным геттером и default
100. Проверка с внешним ELF дополнительно сверяет UTF-32 строку по `0xfcf8a0`.
Строка по адресу `0xfcf8a0` прочитана из SHA-проверенного ELF и совпала с `AI_ATTACKCOOLDOWN`.

Точные новые экспорты находятся в `disassembly/8dfd80-ai-cooldown.asm`,
`8e2ae0-ai-cooldown-init.asm`, `8e3a40-ai-cooldown-tick.asm` и
`880b62-equipment-ai-cooldown.asm`.

### Формула для конечных float32

```text
На каждом вызове updateAI:
    remaining = remaining - dt

После успешного начала обычной атаки:
    если есть выбранное оружие:
        remaining = max(0, remaining) + weapon.AI_ATTACKCOOLDOWN
    remaining = max(0, remaining) + monster.AI_ATTACKCOOLDOWN
```

Проверка допуска — `remaining > 0`, без epsilon. Отрицательный остаток времени
сохраняется при обновлении, но не сокращает свежий cooldown. **Два max нельзя
свернуть в один `max(0, remaining + weapon + unit)`**: например, оружие `-3` и
UNIT `0.5` должны дать `0.5`. Финальное отрицательное значение UNIT не зажимается.

Задержка AI начинается вместе с успешной атакой, а не после её анимации.
`performingAttack` — отдельное условие. Эффект type `0x16` этим кодом не
обнуляется, не заменяется на `ATTACKSPEED` и вообще не изменяется.

## Конкретное расхождение исходного пакета

В исходном `src/entity_world.cpp:253–260` читался `ATTACKSPEED`, но не
`AI_ATTACKCOOLDOWN`; `equip_monster_attack:295–307` сохранял только дальность и
имя оружия. В `src/enemy_ai.cpp:104,130–148` существовал один `State::cooldown`,
который после урона получал `max(0.1, 100 / ATTACKSPEED)`.

Синтетический тест на исходной библиотеке, `dt=1/16`, диапазон времени
**[0, 1.5] секунды**, первая атака в `t=0`:

| UNIT | Вклад UNIT | Вклад оружия | Атак до патча | Атак после |
|---|---:|---:|---:|---:|
| FAST | 0 | нет | 2 | 2 |
| SLOW | 2 | нет | 2 | 1 |
| ARMED | 1.5 | 0.5 | 2 | 1 |

Это измерение порта на собственных входных данных, не запуск оригинальной игры
и не утверждение о реальном числе её атак в данном интервале.

## Что изменено

`RuntimeEntity` хранит `ai_attack_cooldown` монстра и отдельный optional
`equipped_ai_attack_cooldown`. Оба загружаются через существующий
`UnitDefinitionLoader`, поэтому применяется BASEFILE. Действующий путь выбора
оружия обеспечивает одинаковую загрузку для прямого RIGHTHAND/LEFTHAND и
SPAWNRIGHTHAND/SPAWNLEFTHAND. Без оружия optional отсутствует, у оружия без
параметра — присутствующее значение 0.

`MonsterAiCooldown` выделяет две чистые операции для числового сравнения.
`EnemyController` уменьшает его до ветвей обнаружения/потери цели и вооружает
после принятой атаки. Ожидание, невозможность атаковать и смена позиции цели
не запускают задержку заново. Состояние индивидуально для каждого entity ID.

**Сохранённое ограничение — prototype:** вражеский `attack_action_remaining`
по-прежнему вычисляется старым `max(0.1, 100 / ATTACKSPEED)`, а урон по-прежнему
происходит при старте логической атаки. Этот временный ограничитель теперь
явно отделён от восстановленного AI timer; они уменьшаются параллельно. Это
не перенос player clip timer в AI и не подтверждение правильной длительности
вражеского действия. Код игрока `CombatController` не изменён.

Текущий outer controller всё ещё ограничивает входной шаг 0.1 секунды.
Распределение подшагов, KAIThinkTime, очистка цели оригинальным AI, состояние
при Disable/Enable, враждебность, движения и выбор атак этим патчем не
восстанавливаются. Scalar timer сам не обрезает `dt`; ему передаётся уже
выбранная контроллером дельта.

Неконечные ресурсные значения отклоняются при создании сущности. Это
**валидация порта**, не утверждение об исходной реакции игры на NaN/Inf.
Конечные отрицательные значения сохранены, поскольку исходный порядок
арифметики явно обрабатывает их.

## Автоматические проверки

`tests/enemy_ai_cooldown_test.cpp` — независимый тест с **912 утверждениями**.
Он использует 21 собственное UNIT-определение, созданное
`make_ai_cooldown_fixture.py`, и настоящий путь `PakArchive -> ADM ->
UnitDefinitionLoader -> RuntimeEntityWorld -> EnemyController`.

Проверяются default, BASEFILE и override; предметы в обеих руках и spawn-класс;
одинаковая загрузка размещённого и созданного монстра; неконечные значения;
длинная и короткая AI-задержка относительно действия; параллельность двух
таймеров; граница нуля; отрицательные вклады; отсутствие цели, отказ атаки,
ожидание, некорректный dt, выключенная сущность и независимость двух монстров.

`compare_ai_cooldown.py` сравнивает **42 739 float32-результатов побитово** с двумя
неизменёнными машинными срезами:

- `0x8e00e6–0x8e013d` (87 байт, конец не включён): повторное взведение;
- `0x8e3a5b–0x8e3a6f` (20 байт): уменьшение.

Внутренний относительный переход первого среза не изменён. Синтетическая ABI-
обёртка только сохраняет RBX, передаёт адрес объекта и возвращает управление.
Объекты monster/equipment синтетические; внешних вызовов и RIP-констант в этих
срезах нет. Bytes каждого среза закреплены SHA-256. Исследуемые действия
`attack()`, `performingAttack()`, загрузчики, полный updateAI и игра **не
исполняются этим числовым тестом**.

По умолчанию байты декодируются из адресных текстовых экспортов. Режим
`--original` независимо проверяет полный SHA-256 внешнего ELF, ключ свойства и
читает соответствующие bytes из его file-backed сегментов. Он автоматически
регистрируется при `TORCHLIGHT_ORIGINAL`. Локальный запус на закреплённом ELF прошёл:
**42 739 побитовых float32-совпадений**. На платформе, отличной от Linux
x86-64, машинное сравнение явно пропускается (код 77), а C++ регрессия остаётся.

```sh
bash tools/check.sh --portable

# Отдельный режим с установленным оригиналом (файл только читается):
python3 tests/compare_ai_cooldown.py \
  --original /path/to/Torchlight.bin.x86_64 \
  --probe build/ai_cooldown_probe
```

В старом `enemy_ai_test` фиксированное ожидание смерти за четыре секунды
заменено ограниченным окном, рассчитанным из фактической задержки и HP. Такой
интеграционный тест не должен требовать прежнюю ошибочную частоту атак.
Тест с оригинальным `pak.zip` успешно прошёл в составе полного набора.

После слияния штатный `tools/check.sh` собрал desktop и провёл 42/42 теста,
включая GLES smoke и рендер исходной сцены.

## Следующий проверяемый участок

Заменить **только временный вражеский action gate** исполнением выбранного
клипа, его скоростью и HIT; `MonsterAiCooldown` при этом сохранить отдельным.
До этого выбрать одно подтверждённое обычное описание атаки и проверить
`selectAttack -> attack -> animation -> updateAttack`, не предполагая, что
первый найденный `Attack*` или клип с HIT соответствует текущему оружию.
Альтернатива отдельным патчем — численно восстановить порядок подшагов и
анимационной фазы `CGameClient::updateIngame @0x0058e5f0`. Ни одна из этих
задач не считается закрытой текущей scalar-проверкой.
