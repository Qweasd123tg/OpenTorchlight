## Сохранённое поведение

Парсер командной строки сохраняет native TokenizeString: при отсутствии
разделителя список токенов пуст. Флаги, повторные ключи, запятые, equals,
Unicode и длинные deque проверяются на настоящих строках и контейнерах.

SharedStash использует настоящие временные FILE, сериализацию ItemSaveState,
сокеты, inventory, equipment и native RTTI. Фабрика предметов и pickup
наблюдаются на контролируемой границе. Пользовательские сохранения не читаются
и не изменяются.

CLevelState сначала читает minimap старых dimensions, затем имя и новые размеры;
порядок, добавление к непустым спискам и версии 14/16/21/23 сохранены. Старый map
оригинал не освобождает; fixture отдельно убирает потерянное владение после
сравнения, исходник это поведение не исправляет. Logic binary loader использует
реальные UTF16 scratch objects оригинального ELF размером 256 байт каждый.

PropertyNode проверяет настоящие Level/Character/Player контейнеры, bounds,
NaN/infinity/FENV. Layout проверяет все пять операций над particle, technique,
timeline, sound и camera shake. Новый weak camera shake добавляется во второй
native список `+0x70`; ошибочное добавление в первый список обнаружил fixture.

Editor сохраняет повторное чтение game client, перевод Unicode, ограничение
static buffer, рекурсивную конверсию room pieces и перенос предыдущего core
между siblings при GUID=-1. В пяти Skill getters оригинальный Linux-код
копирует `count*2`байт при 4-байтовом wchar_t; эта особенность сохранена и
проверяется снимком всего 4000-байтового буфера. Изменяемые тестовые строки
подаются через общие ELF objects; UTFString-конверсия остаётся настоящей.

AnimationPlayer проверяет реальные weak references, освобождение старых целей,
character/equipment RTTI, callbacks, продолжительность и float/FENV.
Оба play overloads сравниваются отдельно и в композиции друг с другом.
SkipCutscene возвращает void: прежнее float-объявление не подтверждается ASM.
Он выбирает descendants по GUID родителя, обрабатывает ESC на следующем
обновлении, перечитывает player для каждого callback и восстанавливает
logic messages после очистки камер.

## Границы и проверка

Все сравнения требуют завершения обеих сторон, корректного отчёта и успешного
завершения дочернего процесса. Совпадающие аварии не принимаются. У каждого
теста есть отрицательный контроль. Владельцы, конструкторы, деструкторы,
weak references, native контейнеры и SDK объекты проверяются на настоящем
runtime. Headless границы создания UI и menu close не подтверждают отрисовку;
игровое окно не запускалось.

Совместная адресная проверка 19 функций: 29 тестов PASS, 13629 завершённых
сравнительных пар, 0 different, 0 incomplete, все адреса привязаны.
Полный `python3 tools/decomp/check.py`: 2367 тестов, 2364 PASS и три
незавершённых теста по общему 60-секундному лимиту isolated worker:
`level_character_view`, `missile_fire_native`, `complete_level_screen`.
Это FAIL, полный PASS не получен. Последний успел сравнить первые 1024 + 1024
пары, затем worker был прерван; эти строки не подменяют завершение теста.
Исходный журнал сохранён с SHA-256
`35ecd2338c5cd4c6e9e74d0009e5343640d1ca875602355a036dde29b61ae3d0`.
Счётчик MISSING по определениям после интеграции: 88; каноническая приёмка
требует ещё полного PASS.

Унаследованное повторение registered label `mass_linux_int_line` переименовано
в `preserve_linux_int_line` в fixture сохранения регистра. Тело теста не меняется;
полный прогон снова может проверять точный inventory и использовать измеренные
стоимости планировщика.

## Исправления, найденные общим прогоном

Первый полный прогон предыдущих 31 адресов не прошёл: пять старых fixtures
падали либо не укладывались в срок. Адресные повторы сохранили исходные
294/22/3156/640/252 случая и отклонили совпадающие аварии.

EquipmentStats удалял fake CAffix, сделанные из адресов стековых CSetAffix,
а затем удалял сами стековые записи через владеющий список CSet. Теперь это
настоящие native Equipment, Affix, AttackDescription, Inventory, переводчик
и наборы; заимствованные ссылки снимаются перед native-деструкторами.

SDL-вызовы при создании CGame и library callbacks frameEnded используют
существующие near trampolines: прямой пятибайтовый переход из shared library
к низкому адресу blob может выходить за signed rel32. Общий SystemsNativeGame
исправлен и проверен конструкторами/деструкторами. Точный старый RIP frameEnded
в первом логе не сохранён; адресный PASS подтверждает исправленный fixture.
Renderable сохраняет все 3156 пар; его изолированному worker дано 180 секунд
вместо 60, поскольку под общей нагрузкой прежний лимит прерывал сравнение.

В PathController обнаружено настоящее расхождение восстановления: native
setEnabled выделяет TSafePointer через Ogre NedAllocImpl (0x59c4c4 и 0x59c684),
а деструктор освобождает через тот же allocator (0x59d7ee). Восстановленный
код использовал plain new/delete. Оба места исправлены на OGRE_NEW_T и
OGRE_DELETE_T. Prefill lifecycle/enabled fixtures использует то же владение.
Ни одного прежнего strong MATCH в PathController TU не потеряно.

PathNumber наследовал g_pGameUI от предшествующего character_get_item_runtime:
нативный UI-конструктор сохраняет прежний ненулевой singleton. Fixture теперь
временно привязывает собственный настоящий UI и восстанавливает прежний
указатель. Строгие проверки receiver в text callbacks сохранены. Последовательный
прогон с обоими character predecessors подтвердил наследуемый singleton и
прошёл: Enabled 640, Number 252, lifecycle 128 ctor + 128 dtor, predecessors
по 768 пар. Отрицательные контроли обеих Path-функций и lifecycle завершаются
нормально и обнаруживают изменение кандидата.

Совместный адресный прогон Renderable/EquipmentStats/frameEnded/CGame C1/D1:
пять тестов PASS, 3156 + 294 + 22 + 12 + 24 пары. В отдельных проверках
графический shutdown и живой игровой цикл не проверяются. Для общей приёмки
всех 50 новых адресов всё ещё требуется свежий полный check.py.

Короткий исторический повтор старого PathController и прежнего prefill с
предшественником CharacterTownRuntime на снимке из 50 адресов не воспроизвёл
старый seed 114. Это диагностический результат, а не доказательство точной
причины прежнего abort. Исправление allocator отдельно подтверждается ASM.
